# Правила ревью: TypeScript и React

Шаблон `.review/rules.md` для фронтенда на React и TypeScript. Скопируйте файл в
`.review/rules.md` своего репозитория и поправьте паттерны под свою раскладку каталогов.
Абзацы вроде этого сервис модели не передаёт: правилом считается только раздел `##` с
`pattern:` и нумерованными проверками. Как писать свои правила — `docs/RULES_GUIDE.md`.

Правила с одинаковой областью собраны в одно: каждое правило несёт в контекст список всех
своих файлов, и на большом PR второе правило на те же `*.ts` и `*.tsx` удваивало бы этот список.

## TypeScript and React

- pattern: `*.ts`
- pattern: `*.tsx`
- exclude: `*.d.ts`
- exclude: `*.test.ts`
- exclude: `*.test.tsx`
- exclude: `*.spec.ts`
- exclude: `*.spec.tsx`
- exclude: `*.stories.tsx`

1. Нет `any`: неизвестные данные имеют тип `unknown` и сужаются проверкой
2. Ответ API проверяется схемой (например, zod) на границе, а не приводится через `as`
3. Нет `!` (non-null assertion) на значениях, которые могут отсутствовать
4. `@ts-ignore` и `@ts-expect-error` сопровождаются комментарием с причиной
5. Компонент не вызывает `fetch` напрямую: данные приходят через хук запроса (например, TanStack Query)
6. Элементы списка получают устойчивый `key` из данных, а не индекс массива
7. `useEffect` с подпиской, таймером или слушателем возвращает функцию очистки
8. Массивы зависимостей `useEffect`, `useMemo` и `useCallback` полные; отключённое правило `exhaustive-deps` объяснено комментарием
9. Состояние, которое вычисляется из пропсов или другого состояния, не хранится в `useState`
10. Кликабельный элемент — `button` или `a`, а не `div` или `span` с `onClick`
11. У изображения есть `alt`, у кнопки-иконки без текста — `aria-label`
12. Поле формы связано с подписью через `label` или `aria-labelledby`
13. `dangerouslySetInnerHTML` получает только очищенный HTML (например, через DOMPurify)
14. Токены доступа не хранятся в `localStorage` и `sessionStorage`
15. В переменных окружения сборки (`VITE_*`, `NEXT_PUBLIC_*`) нет секретов: они попадают в бандл
16. URL из пользовательского ввода не попадает в `href` или `window.location` без проверки схемы (`javascript:`)

## Frontend Tests

- pattern: `*.test.ts`
- pattern: `*.test.tsx`
- pattern: `*.spec.ts`
- pattern: `*.spec.tsx`

1. Элементы ищутся по роли или тексту (`getByRole`, `getByText`), а не по классам CSS
2. Сетевые запросы подменены (например, MSW), тест не ходит в настоящий API
3. Тест не ждёт фиксированную задержку: используется `findBy*` или `waitFor`

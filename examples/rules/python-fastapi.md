# Правила ревью: Python и FastAPI

Шаблон `.review/rules.md` для сервиса на FastAPI, SQLAlchemy и Alembic. Скопируйте файл в
`.review/rules.md` своего репозитория и поправьте паттерны под свою раскладку каталогов.
Абзацы вроде этого сервис модели не передаёт: правилом считается только раздел `##` с
`pattern:` и нумерованными проверками. Как писать свои правила — `docs/RULES_GUIDE.md`.

Правила с одинаковой областью собраны в одно: каждое правило несёт в контекст список всех
своих файлов, и на большом PR три правила на `*.py` стоили бы втрое дороже одного.

## API Handlers

- pattern: `app/api/`
- pattern: `routers/`
- exclude: `tests/`

1. Обработчик не обращается к сессии базы и ORM-запросам напрямую: данные читает и пишет сервис или репозиторий
2. Тело запроса и ответ описаны Pydantic-моделями, обработчик не возвращает словарь без схемы
3. Ожидаемый отказ (не найдено, нет прав, конфликт) отдаётся HTTPException с конкретным кодом 4xx, а не падает в 500
4. Внутри `async def` нет блокирующих вызовов: `requests`, `time.sleep`, синхронный драйвер базы

## Python Code

- pattern: `*.py`
- exclude: `tests/`
- exclude: `test_*.py`
- exclude: `*_test.py`
- exclude: `conftest.py`
- exclude: `alembic/`
- exclude: `migrations/`

1. Нет запросов в цикле по результатам другого запроса (N+1): связанные данные загружаются одним запросом
2. Сессия базы открывается контекстным менеджером или зависимостью и закрывается на всех путях, включая ошибку
3. Сырой SQL передаётся через `text()` с параметрами, значения не подставляются в строку запроса
4. Изменение нескольких таблиц, которое должно пройти целиком, выполняется в одной транзакции
5. Настройки читаются через объект настроек (pydantic-settings), а не `os.environ` в произвольном месте кода
6. Секрет в настройках имеет тип `SecretStr` и не попадает в логи, текст ошибки и `repr`
7. Нет `except:` и `except Exception: pass`: перехват называет конкретный тип ошибки
8. Исключение, перехваченное ради другого, бросается через `raise ... from err`, причина не теряется
9. Ошибка, которую перехватили и не пробросили, записана в лог с контекстом (`logger.exception`)

## Migrations

- pattern: `alembic/versions/*.py`
- pattern: `migrations/versions/*.py`

1. У миграции есть рабочий `downgrade()`, который возвращает схему к предыдущей ревизии
2. Новый столбец `NOT NULL` в существующей таблице добавляется со `server_default` или в несколько шагов
3. Миграция не импортирует модели приложения: схема описана в самой миграции
4. `drop_column` или `drop_table` не идёт в одном PR с правкой кода, который читал этот столбец или таблицу: сначала релиз без чтения, удаление — следующим PR

## Python Tests

- pattern: `tests/`
- pattern: `test_*.py`
- pattern: `*_test.py`
- pattern: `conftest.py`

1. Тест не ходит в сеть: внешние HTTP-вызовы подменены
2. Тест не ждёт `time.sleep`: время управляется или ожидается событие
3. Имя теста описывает проверяемое поведение, а не вызываемую функцию

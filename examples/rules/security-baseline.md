# Правила ревью: базовая безопасность

Шаблон `.review/rules.md`, не привязанный к стеку: секреты, инъекции, доступ, криптография и
зависимости. При объединении с шаблоном стека ставьте эти разделы **первыми**: правила идут в
контекст по порядку файла, и на большом PR последние могут не поместиться. Абзацы вроде этого
сервис модели не передаёт: правилом считается только раздел `##` с `pattern:` и нумерованными
проверками. Как писать свои правила — `docs/RULES_GUIDE.md`.

Паттерна `*` здесь нет: правило на `*` несёт в контекст список всех файлов PR и на большом PR
вытесняет правила стека. Секреты в коде проверяет правило кода, в конфигурации — отдельное
правило с явными паттернами конфигов.

## Security in Code

- pattern: `*.py`
- pattern: `*.ts`
- pattern: `*.tsx`
- pattern: `*.js`
- pattern: `*.go`
- pattern: `*.java`
- pattern: `*.kt`
- pattern: `*.rb`
- pattern: `*.php`
- exclude: `tests/`
- exclude: `test_*.py`
- exclude: `*_test.py`
- exclude: `*_test.go`
- exclude: `*.test.ts`
- exclude: `*.test.tsx`
- exclude: `*.test.js`
- exclude: `*.spec.ts`
- exclude: `*.spec.tsx`
- exclude: `*.spec.js`

1. В коде нет ключей, паролей и токенов: они читаются из окружения или хранилища секретов
2. Секрет не попадает в лог, текст ошибки или ответ API
3. SQL-запрос получает значения параметрами, а не конкатенацией или форматированием строки
4. Команда ОС запускается без оболочки, аргументы передаются списком; ввод пользователя не попадает в shell
5. Путь к файлу из ввода нормализуется и проверяется, что он остаётся внутри разрешённого каталога
6. Недоверенные данные не десериализуются небезопасно: нет `pickle`, `yaml.load` без `SafeLoader`, `eval`
7. Адрес исходящего запроса из ввода пользователя проверяется по списку разрешённых хостов (SSRF)
8. Новый эндпоинт проверяет аутентификацию; открытый без входа эндпоинт помечен явно
9. Доступ к объекту по идентификатору проверяет, что объект принадлежит текущему пользователю или его организации
10. Подписи, токены и хэши паролей сравниваются за постоянное время (`hmac.compare_digest`, `crypto/subtle`)
11. Пароли хэшируются bcrypt, scrypt или Argon2, а не MD5, SHA-1 или SHA-256 без соли
12. Проверка TLS не отключается (`verify=False`, `InsecureSkipVerify`, `rejectUnauthorized: false`)
13. Токены и одноразовые коды генерируются криптостойким генератором (`secrets`, `crypto/rand`, `crypto.getRandomValues`)

## Secrets in Config

- pattern: `.env`
- pattern: `.env.*`
- pattern: `*.env`
- pattern: `*.yaml`
- pattern: `*.yml`
- pattern: `*.json`
- pattern: `*.toml`
- pattern: `*.ini`
- pattern: `*.properties`
- pattern: `*.tfvars`

1. В конфигурации нет ключей, паролей и токенов: только ссылки на переменные окружения или хранилище секретов
2. В репозиторий не добавляется `.env` с настоящими значениями: только `.env.example` с заглушками

## Dependencies and Images

- pattern: `package.json`
- pattern: `pyproject.toml`
- pattern: `requirements*.txt`
- pattern: `go.mod`
- pattern: `Dockerfile`
- pattern: `*.Dockerfile`

1. Новая зависимость добавлена с ограничением версии, а не `*`, `latest` или без версии
2. Базовый образ Docker указан с конкретной версией или digest, а не `latest`
3. Процесс в контейнере запускается не от root (`USER`)

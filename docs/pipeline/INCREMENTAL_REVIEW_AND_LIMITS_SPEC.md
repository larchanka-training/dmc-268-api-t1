# Инкрементальное ревью и лимиты

> **Статус: предложение, не утверждено.** Требования — в OpenSpec-change
> [`incremental-review`](../../openspec/changes/incremental-review/) и
> [`review-limits`](../../openspec/changes/review-limits/) (применяется вторым). Второй круг
> после ревью #239: ядро урезано, всё, что не нужно одному VPS с одним воркером, вынесено.

## 1. Термины

| Термин | Что это |
|---|---|
| PR diff | `compare/{base}...{head}` — то, что показывает GitHub и к чему привязываются замечания |
| Hunk | Фрагмент PR diff; hunk нового файла длиннее предела делится на сегменты |
| Журнал | `reviewed_hunks`: `(путь, дайджест hunk'а, дайджест конфигурации) → вхождения, прогон, устарел ли` |
| Область ревью | Hunk'и PR diff после фильтрации, не покрытые действующими записями журнала |
| Покрытие | `complete` / `partial` / `none` области прогона и статус каждого файла |

Дайджест hunk'а — строки с маркерами ` `, `+`, `-` без `@@`-заголовка и номеров строк.
Дайджест конфигурации — версия промпта, правила владельца на `base_sha`, версия схемы пакета, модель.

## 2. Прогон

```text
приём synchronize
  устаревшая доставка (event.head_sha != metadata.head_sha) → 202 ignored
  дубль? (#225: последний прогон не failed/cancelled; review-limits: и покрытие complete)
  в одной транзакции: новый прогон + активные прогоны прежних head → cancelled(superseded)
  commit → enqueue

воркер
  статус cancelled? → ack, выход                                 # и перед каждым вызовом модели
  PR diff на (head, base) прогона
  отметить устаревшими записи журнала, чьих hunk'ов в диффе нет
  область = hunk'и сверх действующих вхождений журнала
  область пуста → completed без модели, gate + settle_merge_gate
  plan_scope: бюджет токенов, пределы размера, квота               # review-limits
  модель → находки
  pg_advisory_lock(PR) → статус ещё не cancelled? → publishing → POST → записи → unlock
  completed: в журнал — проверенные hunk'и без находок
  gate: покрытие не complete → failure; иначе по открытым critical тредам; settle_merge_gate
```

## 3. Как закрыты замечания первого круга

| Замечание | Решение |
|---|---|
| Знак без базы: `H == L → noop` после смены ветки (#225) | Знака и режимов нет; область — всегда PR diff на (head, base) минус журнал (D1) |
| `neutral` и `partial` проходят gate | Покрытие не `complete` — `failure` во всех трёх местах построения gate; `neutral` не используется |
| «Revert the revert», копия блока | Запись действует, пока hunk в PR diff; вхождения считаются; hunk с находками не записывается |
| `@generated` ставит автор PR | Шум — только `.gitattributes` с `base_sha` |
| Аренда с повторной постановкой | Сессионный `pg_advisory_lock` на время публикации, без повторной постановки |
| CAS только на знаке | Уже есть: `update` прогона читает строку `FOR UPDATE` и сверяет переход от статуса в базе (#225) |
| `updated_at` для устаревшей доставки | `event.head_sha != metadata.head_sha`, как у повторов #149 |
| Приоритет `src < tests < config` | CI и инфраструктура проверяются первыми |
| `partial`/квота не добираются | Неполный прогон не дубль; квоту добирает проход воркера |
| `installation_id` не хранится | Колонка у репозитория, заполняется приёмом |
| Новый файл — один hunk | Сегменты по текстовому правилу, одинаковому во всех прогонах |
| Нет модели в `config_digest` | Добавлена |
| Сводка «критичных нет» при открытых `critical` | Сводка называет охват прогона |
| Противоречия с #225 | Дельты переписаны поверх требований #225 и #230 |

## 4. Сценарии

| # | Сценарий | Ожидание |
|---|---|---|
| 1 | Первое ревью PR | Область — весь PR diff после фильтрации |
| 2 | Push с правкой одной функции | Модель получает только изменившиеся hunk'и |
| 3 | Сдвиг строк | Сдвинутые hunk'и не в области |
| 4 | Push только lock-файла | Без модели, gate по открытым тредам |
| 5 | Смена ветки на том же head | Область из PR diff против новой базы |
| 6 | `eval` → исправили → вернули | Вернувшийся hunk проверяется, находка публикуется снова |
| 7 | Копия блока в том же файле | Второе вхождение проверяется |
| 8 | Три push во время анализа | Публикует только последний, вытесненные `cancelled` |
| 9 | Запоздавшая доставка A после B | Прогона на A нет, B не вытеснен |
| 10 | Бюджет исчерпан | `partial`, `failure` со списком, остаток — следующим прогоном |
| 11 | 60 файлов при пределе 50 с правкой CI | CI проверен, `partial`, `failure` |
| 12 | Квота исчерпана → восстановилась | `none` и `failure`, затем прогон создаёт воркер |
| 13 | `// @generated` в новом файле | Файл в области |

## 5. Не входит

| Что | Почему |
|---|---|
| Водяной знак, режимы `full/incremental/rebased` | Журнал решает область сам; знак давал дыру при смене ветки |
| Состояния замечаний (`possibly_fixed`, `outdated`, …), fingerprint, L1/L2 | Дубли сдерживает `thread_coverage`; L2 против закрытых тредов подавлял бы новые проблемы |
| Лимиты частоты, backpressure, `defer` | Один воркер на стенде; отсрочка конфликтует с выметателем `queued` и merge gate |
| Бюджет повторов | Уже ограничен повтором доставок #149 и `x-delivery-limit` #230 |
| `GET …/coverage` | Покрытие отдаёт `ReviewJob` |
| Многочанковое ревью | Отдельный change: меняет пакет контекста и верификатор |

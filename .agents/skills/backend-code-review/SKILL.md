# Ревью диффа

Две оси считаются параллельно и не сливаются: код может пройти одну и провалить другую.

Адаптировано из [`mattpocock/skills`](https://github.com/mattpocock/skills) (MIT),
`skills/engineering/code-review`.

## 1. Точка отсчёта

База по умолчанию — `develop`, для пул-реквеста — его база.

```bash
git rev-parse <база>            # ссылка существует
git diff <база>...HEAD          # три точки: против merge-base
git log <база>..HEAD --oneline
```

Пустой дифф или несуществующая ссылка — останавливаемся здесь, а не внутри осей.

## 2. Что доказывают инструменты

```bash
uv run ruff check . && uv run lint-imports && uv run pytest
```

Ни одно замечание не повторяет их вывод: форматирование, импорты, длина строки, направление
зависимостей уже проверены. Нарушение, которое они ловят, — это упавшая сборка, а не тема для
комментария.

## 3. Ось Standards

Источники: [`AGENTS.md`](../../../AGENTS.md), [`rules/backend.md`](../../rules/backend.md),
[`docs/BACKEND_ARCHITECTURE.md`](../../../docs/BACKEND_ARCHITECTURE.md), контракты
`[tool.importlinter]` в `pyproject.toml`.

Проверки поверх документов:

- решение в адаптере вместо домена; чтение часов, случайность и I/O внутри чистой функции;
- новый порт без второго адаптера и без границы слоя;
- тест на удаление: модуль, при удалении которого сложность не всплывает, — проходной;
- широкий интерфейс над тонкой реализацией;
- функция домена без теста, идущего без базы; миграция без отката; вторая голова ревизии;
- дублирование того, что может разойтись: enum, таблица переходов, определение timestamp'ов.

Запахи (Фаулер) — размеченные эвристики, не нарушения: Mysterious Name, Duplicated Code,
Feature Envy, Data Clumps, Primitive Obsession, Repeated Switches, Shotgun Surgery, Divergent
Change, Speculative Generality, Message Chains, Middle Man, Refused Bequest. Документированное
правило репозитория перебивает запах.

## 4. Ось Spec

Источник — артефакты OpenSpec-change (`openspec/changes/<name>/`: `proposal.md`,
`specs/**/spec.md`, `tasks.md`) и задача:

```bash
gh pr view <n> --json body,title
gh issue view <n> --json title,body
```

Проверки: требование спецификации не реализовано или реализовано частично; в диффе есть
поведение, которого никто не просил; задача отмечена сделанной, а код её не закрывает. На каждое
замечание — цитата требования.

Спеки нет — ось пропускается, и это указывается в отчёте.

## 5. Отчёт

Два раздела, `## Standards` и `## Spec`, findings не переранжируются между осями. В конце —
число находок по каждой оси и худшая внутри каждой. Общий победитель не выбирается: ради этого
оси и разведены.

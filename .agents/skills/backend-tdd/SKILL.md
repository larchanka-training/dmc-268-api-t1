# Разработка через тесты

Примеры — [`tests.md`](tests.md) и [`mocking.md`](mocking.md). Команды и швы —
[`rules/backend.md`](../../rules/backend.md).

Адаптировано из [`mattpocock/skills`](https://github.com/mattpocock/skills) (MIT),
`skills/engineering/tdd`.

## Где живёт тест

| Что тестируем | Шов | Каталог | База |
|---|---|---|---|
| Решение домена | функция домена | `tests/domain/` | нет |
| Сценарий прикладного слоя | порт | `tests/` | нет, порт подменяется фейком |
| Адаптер | интерфейс репозитория | `tests/db/` | да, `TEST_DATABASE_URL` |
| HTTP-контракт | `TestClient` | `tests/` | нет |

Согласовать шов заранее нужно только при появлении нового порта.

## Правила витка

- Красный до зелёного: падающий тест, затем ровно столько кода, чтобы он прошёл.
- Один шов за виток. Вертикальные срезы, не «сначала все тесты».
- Рефакторинг относится к ревью, не к циклу.
- Заменяй, не наслаивай: после углубления модуля тесты поверх его внутренних частей удаляются.

## Антипаттерны

- **Прибитый к реализации** — мок своего модуля, проверка приватного, сверка через побочный
  канал (сырой SQL вместо метода репозитория). Признак: ломается на рефакторинге без изменения
  поведения.
- **Тавтологический** — ожидаемое считается тем же способом, что и в коде. Ожидаемое берётся из
  литерала, разобранного примера или спецификации.
- **Молча пропущенный** — интеграционный тест без `requires_db`. CI роняет сборку на любом
  пропуске, поэтому «локально зелено без базы» ничего не доказывает.

```bash
uv run pytest && uv run ruff check . && uv run lint-imports
```

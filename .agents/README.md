# `.agents/`

Машинный контекст: правила, скиллы, шаблоны.

| Каталог | Когда читать |
|---|---|
| [`rules/backend.md`](rules/backend.md) | пишете код в этом репозитории |
| [`rules/git-and-pr.md`](rules/git-and-pr.md) | ветки, коммиты, задачи, пул-реквесты, замечания |
| [`skills/`](skills/) | подключается по описанию скилла |
| [`templates/backend/`](templates/backend/) | новый модуль, адаптер или эндпоинт |

Критичный минимум продублирован в [`AGENTS.md`](../AGENTS.md): ссылку агент может не открыть.
Скиллы `openspec-*` пришли с OpenSpec, остальные написаны под проект.

Свой инструмент каждый подключает сам, симлинком на этот каталог и локально — сами каталоги
инструментов в репозиторий не коммитятся:

```bash
ln -s ../.agents/skills .claude/skills        # или .cursor/, .codex/, .gemini/
openspec init --tools <tool>                  # то же самое, если инструмент поддержан
```

Симлинк, а не копия: копия разойдётся с оригиналом на первой же правке.

Antigravity исключение: он читает `.agents/skills` сам, симлинк ему не нужен.

Раскладка `.agents/`, а не `docs/agents/`: каталог уже существовал, `.claude/skills` уже
указывал сюда, а `docs/` — для людей.

Промпты продукта лежат в [`prompts/review/`](../prompts/review/): это данные для сервиса, а не
контекст разработки, и в каждый запрос они попадать не должны.

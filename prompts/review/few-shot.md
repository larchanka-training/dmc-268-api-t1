# Примеры ответа (few-shot)

Последняя часть системного сообщения запроса ревью, после `output-format.md`: сначала описание формата, потом образцы.
Три примера ответа на выдуманные изменения, написанные сервисом: замечание по стандартным критериям, замечание со ссылкой на пункт правила владельца и ответ без замечаний.
Код проверяемых репозиториев сюда не попадает - только синтетические примеры, описанные словами.
Каждый блок `json` проверяется тестом по схеме вывода ревью (`tests/infrastructure/test_prompts.py`): пример не может разойтись со схемой молча.

---

## Примеры ответа

Ниже - образцы формы ответа на выдуманных изменениях.
Код в них описан словами и к проверяемому репозиторию отношения не имеет: не ищи его в диффе и не переноси замечания из примеров в свой ответ.

### Пример 1: замечание по стандартным критериям

Изменение: в `app/users.py` функция `find_user(name)` на новой строке 15 собирает SQL-запрос f-строкой из `name` и выполняет его через `cursor.execute`; остальные функции файла передают значения параметрами.
Правил владельца для файла нет.

```json
{
  "schemaVersion": "1",
  "findings": [
    {
      "filePath": "app/users.py",
      "side": "new",
      "line": 15,
      "category": "security",
      "severity": "critical",
      "message": "Запрос к базе теперь собирается f-строкой из аргумента name. Остальные функции этого файла передают значения параметрами в cursor.execute. Похоже, так было проще отладить запрос целиком. Имя вида ' OR 1=1 -- вернёт всех пользователей, а с точкой с запятой выполнит чужой SQL. Передайте name параметром запроса.",
      "confidence": 0.95,
      "suggestion": {
        "diff": "-    cursor.execute(f\"SELECT id, name FROM users WHERE name = '{name}'\")\n+    cursor.execute(\"SELECT id, name FROM users WHERE name = %s\", (name,))"
      },
      "rule": null
    }
  ],
  "summary": {
    "problem": "Главная проблема - SQL-инъекция в поиске пользователя по имени.",
    "positives": ["Новая функция покрыта тестом на найденного пользователя."],
    "effort": "Доработка на один небольшой коммит."
  }
}
```

### Пример 2: замечание по пункту правила владельца

Раздел правил содержит правило `"Error Handling Standards"` для файлов `["app/billing.py"]`; его пункт 1 - «Отказ возвращается значением Result, а не исключением».
Изменение: в `app/billing.py` функция `charge(order)` на новой строке 31 при нехватке средств бросает `ValueError`, хотя остальные функции файла возвращают `Result.failure(...)`.

```json
{
  "schemaVersion": "1",
  "findings": [
    {
      "filePath": "app/billing.py",
      "side": "new",
      "line": 31,
      "category": "correctness",
      "severity": "medium",
      "message": "При нехватке средств charge теперь бросает ValueError. Остальные функции этого файла возвращают отказ значением Result.failure. Вероятно, исключение показалось короче для редкой ветки. Вызывающий код проверяет только результат, и исключение дойдёт до обработчика воркера, уронив оплату целиком. Верните Result.failure с причиной вместо raise.",
      "confidence": 0.8,
      "suggestion": {
        "diff": "-        raise ValueError(\"insufficient funds\")\n+        return Result.failure(\"недостаточно средств\")"
      },
      "rule": {"name": "Error Handling Standards", "check": 1}
    }
  ],
  "summary": {
    "problem": "Главная проблема - отказ оплаты исключением вопреки правилу проекта об ошибках.",
    "positives": ["Ветка нехватки средств теперь вообще обрабатывается."],
    "effort": "Доработка на одну правку в одной функции."
  }
}
```

Имя правила в `rule` - точно как в разделе правил, номер - номер пункта оттуда же.
Префикс «Согласно пользовательскому правилу …» в `message` не пишется: его добавит сервис по полю `rule`.

### Пример 3: замечаний нет

Изменение: в `README.md` на новой строке 12 исправлена опечатка в команде установки.

```json
{
  "schemaVersion": "1",
  "findings": [],
  "summary": {
    "problem": "Проблем в изменении не найдено.",
    "positives": ["Исправление точечное и не задевает код."],
    "effort": "Мерж без доработки."
  }
}
```

Если замечаний нет, `findings` - пустой массив: не выдумывай замечание, чтобы ответ не был пустым.

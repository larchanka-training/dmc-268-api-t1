# Промпты ревью

Контракт этих промптов — `openspec/specs/ai-review-prompting/spec.md`. Здесь тексты, там
требования и сценарии.

## Как файлы попадают в запрос

Модели уходит часть файла после первой строки `---`; выше - пояснение для людей.
Воркер читает файлы при старте (`app/infrastructure/prompts.py`); нет файла или разделителя - воркер не стартует.
Запрос собирает чистая функция `app/domain/prompt.py`: одинаковые пакет контекста и тексты дают побайтно одинаковый запрос.

### Запрос ревью

| Сообщение | Что в нём |
|---|---|
| `system` | тела [`system.md`](system.md), [`comment-templates.md`](comment-templates.md), [`output-format.md`](output-format.md), [`few-shot.md`](few-shot.md) в этом порядке и сводка метаданных прогона (только значения, проверенные по формату: языки, номер PR, sha) |
| `user` | раздел правил владельца: статус загрузки, по каждому правилу имя, файлы и пронумерованные пункты в блоках недоверенных данных |
| `user` | раздел кода: контекст PR (заголовок, описание, сообщения коммитов - в блоках недоверенных данных), hunk'и диффа, AST-окружение, перечень не вошедшего |

Порядок частей системного сообщения - перечень `REVIEW_SYSTEM_PARTS` в `app/infrastructure/prompts.py`.
Новая часть - новый файл здесь и строка в этом перечне; сборщик запроса править не нужно.
Так добавлены few-shot примеры: каждый блок `json` в [`few-shot.md`](few-shot.md) проверяется тестом по схеме вывода ревью, поэтому пример не расходится со схемой молча.
Примеры, построенные на чужом коде, - данные, а не инструкции: им место в блоках недоверенных данных, а не в системном сообщении.

### Запрос верификации

| Сообщение | Что в нём |
|---|---|
| `system` | тело [`verifier.md`](verifier.md) |
| `user` | тот же раздел правил |
| `user` | тот же раздел кода |
| `user` | замечания первого прохода с идентификаторами `F1…Fn`; тексты - в блоках недоверенных данных |

[`custom-rules.md`](custom-rules.md) и [`repo-conventions.md`](repo-conventions.md) модели не отправляются: первый описывает формат правил для владельца, второй - промежуточный артефакт конвенций, который пока не реализован.
`AGENTS.md` проверяемого репозитория сервис пока не загружает, раздела для него в запросе нет.

## Что остаётся кодом, а не промптом

Замечания про линтинг и форматирование режутся дважды: запретом в промпте и постобработкой
после ответа модели. Второй проход обязателен — вывод модели не публикуется напрямую.

Кодом, а не промптом, делается и остальное, что можно проверить детерминированно:

- сверка каждой находки с диффом: замечание должно указывать на реально изменённую строку;
- отбрасывание дублей;
- отсев замечаний, покрытых линтером проекта;
- перевод координат в позиции комментариев провайдера.

Промпт отвечает за то, какие замечания вообще возникают; постобработка — за то, какие из них
доедут до автора.

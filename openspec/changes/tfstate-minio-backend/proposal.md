# Proposal

## Why

Деплой идёт из GitHub Actions при мерже в `develop`. Раннер эфемерный: он создаётся на один прогон и исчезает вместе с диском. Локальный `terraform.tfstate` в такой схеме не живёт между запусками, а без state следующий `apply` не знает, что контейнеры уже созданы, и упирается в занятые имена.

Бэкенда сейчас нет ни в `infra/` этого репозитория, ни у фронта — проверено, ни одного блока `backend` в конфигурации. Пока `apply` никто не запускал, это ничего не ломало; с появлением CD это первое, обо что он споткнётся.

Хранилище выбрано на своём сервере, а не во внешнем облаке: не нужен сторонний аккаунт, всё остаётся в нашем контуре. Объектное хранилище предпочтено бэкенду `pg`, потому что бакет пригодится не только под state — бэкапы базы и артефакты сборки просятся туда же, а контейнер с базой под состояние остался бы контейнером под одну задачу.

## What Changes

- MinIO поднимается **идемпотентным job'ом в Actions** по ключу CI обычным `docker run`: без Terraform и без собственного состояния, иначе вопрос «где хранить state» просто сдвинулся бы на шаг.
- MinIO слушает только `127.0.0.1`; CI ходит к нему через SSH-туннель тем же ключом. Наружу не публикуется ни порт, ни новая учётная запись.
- Бакет под state создаётся из раннера по туннелю, **с включённым версионированием** — ради него объектное хранилище и выбиралось.
- В `infra/` появляется блок `backend "s3"` с переопределением endpoint, `use_path_style` и отключением проверок региона и учётных данных, которые к MinIO неприменимы.
- Состояния api и ui лежат в одном бакете под разными ключами: стеки независимы, хранилище общее.
- Рутовые учётные данные MinIO заводятся двумя секретами в обоих репозиториях.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`, как у обоих предыдущих инфраструктурных изменений. Меняется то, где Terraform держит своё состояние; наблюдаемое поведение сервиса не затрагивается.

## Impact

- Новые файлы: `infra/backend.tf`, workflow и скрипт подъёма MinIO.
- Новые секреты `MINIO_USER_DMC268_T1` и `MINIO_PASSWORD_DMC268_T1` — в обоих репозиториях, у фронта свой стек и своё состояние.
- Существующий job `terraform` в `ci.yml` использует `tofu init -backend=false` (`.github/workflows/ci.yml:45`) и продолжит работать без изменений — именно для таких случаев этот флаг и нужен.
- На сервере появляется ещё один контейнер и именованный том, не входящие в управляемый Terraform стек.
- Разблокирует CD: после этого изменения можно писать деплой [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22).

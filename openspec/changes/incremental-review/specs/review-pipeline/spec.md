# Spec Delta

## MODIFIED Requirements

### Requirement: Сводка ревью называет риски и проверенные файлы

Под сводкой модели итоговый комментарий SHALL содержать блок «Риски» — число замечаний прогона уровня `critical` и `high` по категориям, без таких замечаний блока нет. Ниже SHALL идти список файлов диффа под `<details>` по группам: проверены, проверены раньше, частично, не проверены, отброшены фильтром; группы считает код по пакету контекста и журналу. «Проверены» — файл, у которого показан этим прогоном хотя бы один hunk, а каждый hunk показан или покрыт журналом; «проверены раньше» — файл, ни один hunk которого не показан этим прогоном, а все покрыты журналом; «частично» — файл, у которого есть hunk, ни показанный, ни покрытый журналом. Имя файла SHALL NOT менять разметку комментария; в группе — не больше 50 путей, путь — не длиннее 200 символов.

#### Scenario: Риски по категориям

- **WHEN** в прогоне два замечания `security` (`critical` и `high`) и одно `readability` уровня `low`
- **THEN** блок «Риски» называет только безопасность — по одному `critical` и `high`

#### Scenario: Lock-файл и файл сверх лимита

- **WHEN** в диффе `uv.lock` и файл, ни один hunk которого не вошёл в лимит контекста
- **THEN** под `<details>` `uv.lock` — в «отброшены фильтром», второй файл — в «не проверены»

#### Scenario: Имя файла с разметкой

- **WHEN** автор PR назвал файл с обратными кавычками, `</details>` или переводом строки
- **THEN** путь выводится в code span, перевод строки и обратная кавычка — видимой записью, и список не разрывается

#### Scenario: PR на тысячи файлов

- **WHEN** в группе больше 50 файлов
- **THEN** выведены первые 50 и строка «… и ещё N»

#### Scenario: Имена файлов из тысяч управляющих байт

- **WHEN** во всех группах по 50 файлов с именами в тысячи управляющих символов
- **THEN** каждый путь обрезан до 200 символов, и комментарий короче 65 536 символов — ревью публикуется

#### Scenario: Файл, проверенный прежним прогоном

- **WHEN** прогон показал модели hunk'и `a.py`, а все hunk'и `b.py` в PR diff покрыты журналом
- **THEN** `a.py` — в «проверены», `b.py` — в «проверены раньше», а не в «не проверены»

#### Scenario: Файл, проверенный частью сейчас, частью раньше

- **WHEN** прогон показал модели один hunk `c.py`, а остальные hunk'и `c.py` в PR diff покрыты журналом
- **THEN** `c.py` — в «проверены», а не в «частично»

## ADDED Requirements

### Requirement: Сводка не скрывает открытые блокирующие треды

Пока у PR есть незакрытые треды не ниже порога `min_severity` репозитория, сводка ревью SHALL NOT утверждать, что блокирующих проблем нет, даже если прогон новых находок не дал.

#### Scenario: Инкрементальный прогон без новых находок при открытом треде не ниже порога

- **WHEN** прогон проверил два изменённых фрагмента без находок, а в PR остаётся открытый тред `critical` при пороге `critical`
- **THEN** сводка говорит, что в новых изменениях замечаний нет, и ссылается на открытые замечания, а не пишет «критичных проблем не обнаружено»

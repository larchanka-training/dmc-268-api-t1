# Proposal

## Why

Конвейер ревью собирает запрос, отсеивает и верифицирует ответ (change `add-prompt-guard-and-reflection-pass`, #61), но до модели запрос не доходит: единственный адаптер порта `LlmGateway` - заглушка с пустым ответом.
Это задача #64: настоящие провайдеры (локальная модель и Eurorouter) с ротацией ключей и фоллбэком, структурированный ответ по Pydantic-модели, контекст PR и few-shot примеры в промпте и запрос, который гарантированно помещается в окно модели.

## What Changes

- Адаптер локальной модели (Ollama в нашей сети) и адаптер Eurorouter (OpenAI-совместимый протокол) за существующим портом `LlmGateway.complete`.
- Порядок провайдеров фиксирован: локальная модель основная; Eurorouter - только фоллбэк и только при явном включении в конфигурации.
  Модель угроз фиксирует это как политику: по умолчанию код проверяемого репозитория не покидает нашу сеть.
- Ротация ключей Eurorouter: ключ, отвергнутый провайдером или упёршийся в лимит, сменяется следующим в том же вызове.
- Структурированный ответ без новой зависимости: схема из модели ответа передаётся провайдеру, ответ проверяется той же моделью, ответ не по схеме даёт повтор с дописанным сообщением об ошибке; исходные сообщения не меняются, значения из ответа модели в сообщение об ошибке не попадают.
- Окно модели: запрос вместе с резервом под ответ, не помещающийся в настроенное окно, не отправляется никому; локальной модели окно передаётся явно, чтобы она не обрезала начало запроса молча.
  Конфигурация, в которой пакет контекста и резерв ответа не помещаются в окно, не даёт сервису стартовать.
- Порт: запрос к модели несёт предел длины ответа (резерв окна).
- Контекст PR в пакете: заголовок, описание и сообщения коммитов - в блоках недоверенных данных, в пределах своей доли бюджета; сбой их получения пакет деградирует, а не роняет прогон.
- Few-shot примеры ответа в системном промпте; каждый пример проверяется тестом по схеме вывода ревью.
- Выбор адаптера - конфигурацией: заглушка остаётся для разработки и тестов, но выбирается явно.

Вне этого change: подстройка текстов промптов и замер Precision/Recall на живой модели (#57, #62), развёртывание Ollama на стенде (DevOps), точный подсчёт токенов токенизатором модели.

## Capabilities

### New Capabilities

- `llm-gateway`: транспорт к модели - провайдеры и их порядок, политика hosted-провайдера, ротация ключей, фоллбэк, получение ответа по схеме с повторами, окно модели и предел ответа, сбои и их классы.

### Modified Capabilities

- `context-assembly`: новое требование - контекст PR (заголовок, описание, сообщения коммитов) входит в пакет блоками недоверенных данных; требование «Жёсткий лимит размера контекста» - контекст PR занимает свою долю бюджета первым в порядке заполнения.
- `ai-review-prompting`: новое требование - системный промпт содержит примеры ответа, написанные сервисом и соответствующие схеме вывода.

## Impact

- Новый код:
  - `app/infrastructure/llm/ollama.py`, `app/infrastructure/llm/openai_compatible.py` - адаптеры провайдеров;
  - `app/infrastructure/llm/structured.py` - общий цикл «запрос - проверка по модели - повтор»;
  - `app/infrastructure/llm/fallback.py` - составной адаптер с порядком провайдеров;
  - чистая функция проверки окна модели в `app/domain/prompt.py`;
  - `prompts/review/few-shot.md`.
- Изменённый код:
  - `app/application/ports/llm_gateway.py` (`LlmRequest.max_output_tokens`), `app/application/llm_review.py` (проверка окна до вызова);
  - `app/domain/llm_errors.py` (класс сбоя «запрос не помещается в окно»);
  - `app/application/ports/vcs_gateway.py` и `app/infrastructure/vcs/github.py` (описание PR, сообщения коммитов), `app/domain/entities.py` (`PRMetadata.description`);
  - `app/application/context_assembly.py`, `app/application/use_cases/build_review_context.py` (контекст PR), `app/domain/prompt.py` (раздел контекста PR в сообщении кода);
  - `app/config.py` (провайдеры, ключи, окно, предел ответа, повторы, таймаут), `app/infrastructure/container.py`, `app/infrastructure/prompts.py` (`REVIEW_SYSTEM_PARTS`).
- Документы: `docs/BACKEND_ARCHITECTURE.md` (адаптеры, модель угроз: self-hosted по умолчанию, hosted - явный фоллбэк), `docs/SYSTEM_DESIGN.md`, `README.md`, `.env.example`, `prompts/review/README.md`.
- CI: workflow `llm-live.yml` - живые тесты против EUrouter с ключом организации (`secrets.AI_DMC268_T1`, `vars.AI_DMC268_URL`) при правках кода модели и вручную; job `test` исключает их маркером.
- Развёртывание: новые переменные окружения воркера в `docker-compose.yml` и `infra/` (по `backend-delivery` описания должны совпадать); профиль `ollama` в `docker-compose.yml` для локального прогона.
- Зависимости: новых нет - транспорт на уже используемом `httpx`.
- Опирается на незаархивированный change `add-prompt-guard-and-reflection-pass` (PR #63): ветка и PR стопкой, архивировать после него.

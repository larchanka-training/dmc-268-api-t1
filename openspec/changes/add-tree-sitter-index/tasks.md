# Tasks: add-tree-sitter-index

Порядок — TDD по слоям (`.agents/rules/backend.md`): чистые функции
домена и решения тестируются без базы, брокера и сети; адаптеры — своими
адаптерными тестами. Проверки перед коммитом каждого шага: `uv run ruff
check .`, `uv run lint-imports`, `uv run pytest`.

Порты `CacheStore` и `DefinitionExtractor`, их адаптеры
(`InMemoryCacheStore`, `TreeSitterDefinitionExtractor`) и реестр грамматик уже
в `develop` — задач на их создание change не содержит; отдельного спайка
зависимостей не нужно (tree-sitter используется AST-уровнем).

## 1. Конфигурация

- [ ] 1.1 `uv sync --all-extras`; проверить: тесты ветки зелёные
      (`uv run pytest`).
- [ ] 1.2 Настройки в `app/config.py`: `index_max_files` (лимит соседей на
      прогон), `index_max_file_bytes`, `index_timeout_seconds`,
      `index_cache_ttl_seconds`, `index_cache_max_entries` (лимит отдельного
      экземпляра кэша индекса). Инвариант
      `index_timeout_seconds < stale_run_timeout_seconds` навязывается
      валидатором конфигурации: довыборка идёт внутри `BUILDING_CONTEXT`
      без отметок прогресса, и выметатель зависших прогонов не должен
      опередить лимит. Проверить: тест в `tests/test_config.py` читает
      настройки из окружения и отклоняет конфигурацию с
      `index_timeout_seconds >= stale_run_timeout_seconds`.

## 2. Домен: выбор соседей и разрешение импортов

- [ ] 2.1 Чистые функции в `app/domain/definitions_index.py`: разрешение
      импортов изменённых файлов в пути по дереву коммита (модуль →
      `path.py` или `path/__init__.py`) и выбор соседей «дифф +
      импорт-окрестность». Все файлы диффа исключаются безусловно —
      независимо от того, есть ли у файла контур на `head_sha` в пакете:
      базовая версия изменённого файла устарела. Проверить: юнит-тесты на
      литералах в `tests/domain/test_definitions_index.py` — сосед по
      импорту выбран, нерелевантный файл нет, изменённый файл исключён и при
      наличии, и при отсутствии head-контура, импорт вне дерева пропущен,
      пустое дерево даёт пустой выбор.

## 5. Прикладной слой

- [ ] 5.1 Get-or-fetch дерева коммита: ключ «репозиторий, base_sha» →
      попадание: дерево без запроса; промах: `fetch_tree` → сериализация и
      запись в кэш с ttl `index_cache_ttl_seconds`; усечённое дерево —
      валидный частичный список; проверить: юнит-тесты сценария на фейках —
      промах запрашивает и пишет, попадание не запрашивает, `truncated`
      не сбой.
- [ ] 5.2 Get-or-fetch определений соседа: ключ «репозиторий, base_sha,
      путь» → попадание: записи без работы; промах:
      `fetch_file(max_bytes=index_max_file_bytes)` +
      `DefinitionExtractor` → сериализация и запись в отдельный экземпляр
      `CacheStore` (лимит `index_cache_max_entries`) с ttl
      `index_cache_ttl_seconds`. Ошибки: `VcsFileTooLargeError` и файл без
      грамматики — штатный пропуск соседа; прочие `VcsError` и сбои
      извлечения — отсутствие результата без записи в кэш: неполный набор
      после сбоя не должен переживать повтор. Проверить: юнит-тесты
      сценария на фейках — записи после промаха, попадание не парсит,
      слишком большой файл пропущен, файл неизвестного языка пропущен,
      сбой VCS возвращает отсутствие результата и не пишет кэш, повторный
      вызов после сбоя повторяет довыборку, записи уходят в отдельный
      экземпляр кэша.
- [ ] 5.3 Потребление в сборке контекста: `build_review_context` берёт
      дерево (5.1), выбирает соседей функцией домена (2.1) и довыбирает
      записи (5.2) вторым источником уровня `ast` — отдельного значения в
      `tiers` не появляется; записи идут в бюджет после AST-блоков
      изменённых файлов, не поместившееся — в `omitted`; сбой довыборки —
      пакет без записей индекса, промах — довыборка в текущем прогоне;
      проверить: тесты сборки контекста — сосед по импорту в пакете,
      нерелевантные записи нет, изменённый файл не дублируется (включая
      случай без head-контура), вытеснение в `omitted` при нехватке
      бюджета, сбой довыборки, промах после вытеснения.

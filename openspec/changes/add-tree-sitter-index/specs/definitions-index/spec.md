# Spec Delta: definitions-index

## Purpose

Определяет построение и хранение индекса определений репозитория: по задаче из
очереди файлы основной ветки довыбираются через `VcsGateway`, tree-sitter
извлекает сигнатуры классов, функций и модулей, результат хранится best-effort
в `CacheStore` по неизменяемому ключу и служит словарём сигнатур для сборки
контекста ревью.

## ADDED Requirements

### Requirement: Построение индекса по задаче переиндексации

Система SHALL строить индекс определений репозитория при получении задачи
переиндексации: довыбирать дерево репозитория и содержимое файлов на указанном
коммите через `VcsGateway`, извлекать определения и сохранять их в `CacheStore`.
Коммит для индексации SHALL фиксироваться в задаче — файлы выбираются именно
на нём, а не на актуальном состоянии ветки на момент обработки.

#### Scenario: Успешная индексация основной ветки

- **WHEN** воркер получает задачу переиндексации репозитория на коммите `S`
- **THEN** система сохраняет в `CacheStore` определения файлов коммита `S` и
  обновляет маркер проиндексированного коммита репозитория значением `S`

#### Scenario: Повторная задача на тот же коммит не выполняет работу

- **WHEN** приходит задача переиндексации, чей коммит равен маркеру
  проиндексированного коммита репозитория
- **THEN** задача подтверждается без довыборки файлов и парсинга (коалесинг
  повторных доставок)

### Requirement: Определения извлекаются tree-sitter'ом за портом

Система SHALL извлекать определения (модуль, классы, функции: имя, сигнатура,
позиция в файле) парсером, доступ к которому изолирован портом; слой домена и
слой приложения SHALL не знать библиотеку парсинга. Язык файла SHALL
определяться по расширению; файл с расширением без поддержанной грамматики
SHALL пропускаться без сбоя индексации.

#### Scenario: Файл на поддержанном языке даёт определения

- **WHEN** индексируется файл на Python, содержащий классы и функции
- **THEN** в индекс попадают определения этих классов и функций с именами,
  сигнатурами и позициями строк

#### Scenario: Файл неизвестного языка пропускается

- **WHEN** индексируется файл с расширением, для которого нет грамматики
- **THEN** файл пропускается, индексация остальных файлов продолжается

### Requirement: Лимиты индексации

Система SHALL ограничивать индексацию числом файлов, размером файла и общим
временем индексации одного репозитория; лимиты задаются конфигурацией. Файл,
превышающий лимит размера, SHALL пропускаться; при исчерпании лимита числа
файлов или времени довыборка и парсинг SHALL прекращаться, а частично
построенный индекс SHALL считаться валидным результатом.

#### Scenario: Слишком большой файл пропускается

- **WHEN** при индексации встречается файл больше лимита размера
- **THEN** файл пропускается, остальные файлы индексируются

#### Scenario: Исчерпание лимита файлов даёт частичный индекс

- **WHEN** число довыбранных файлов достигает лимита до конца дерева
- **THEN** индекс сохраняется по уже обработанным файлам, задача завершается
  без сбоя

### Requirement: Best-effort хранение индекса

Индекс определений SHALL храниться в `CacheStore` по неизменяемым ключам
«репозиторий, коммит», а текущий проиндексированный коммит репозитория — в
отдельном ключе-маркере. Промах кэша SHALL не считаться ошибкой: при его
обнаружении потребитель работает без сигнатур, а следующий коммит в основную
ветку перестраивает индекс.

#### Scenario: Чтение индекса по неизменяемому ключу

- **WHEN** потребитель запрашивает определения репозитория на коммите `S`,
  ранее проиндексированном
- **THEN** он получает сохранённый набор определений по ключу «репозиторий,
  коммит `S`»

#### Scenario: Вытесненный индекс не ломает потребителей

- **WHEN** запись индекса вытеснена из `CacheStore` и потребитель обращается
  к ней
- **THEN** потребитель получает признак промаха и продолжает работу без
  сигнатур, а повторная индексация возможна следующей задачей переиндексации

### Requirement: Доступ к парсингу — через порт

Взаимодействие с парсингом кода SHALL идти через порт извлечения определений;
реализация с tree-sitter живёт в слое инфраструктуры и выбирается на этапе
композиции. Соблюдение закреплено автоматической проверкой импортов.

#### Scenario: Вендор парсинга не утекает во внутренние слои

- **WHEN** выполняется автоматическая проверка направленности импортов
- **THEN** модули домена и приложения не импортируют библиотеку tree-sitter

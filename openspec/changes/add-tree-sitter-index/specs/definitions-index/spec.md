# Spec Delta: definitions-index

## Purpose

Определяет построение и хранение индекса определений репозитория: при прогоне
ревью по промаху ключа «репозиторий, base_sha» дерево коммита довыбирается
через `VcsGateway`, определения извлекаются существующим портом за реестром
грамматик, результат хранится best-effort в `CacheStore`. Потребление словаря
сборкой контекста — способность `context-assembly`.

## ADDED Requirements

### Requirement: Ленивое построение индекса при прогоне ревью

Система SHALL при прогоне ревью запрашивать индекс определений по ключу
«репозиторий, base_sha», где `base_sha` — коммит основной ветки из сообщения
задачи. При попадании система SHALL возвращать сохранённый индекс без
довыборки файлов и парсинга. При промахе система SHALL строить индекс:
довыбирать дерево репозитория и содержимое файлов через `VcsGateway`,
извлекать определения и сохранять их в `CacheStore`.

#### Scenario: Первый прогон по коммиту строит индекс

- **WHEN** прогон ревью запрашивает индекс по ключу, которого нет в
  `CacheStore`
- **THEN** система довыбирает файлы коммита `base_sha`, извлекает определения
  и сохраняет их по этому ключу

#### Scenario: Повторный прогон по тому же коммиту переиспользует индекс

- **WHEN** прогон ревью запрашивает индекс по ключу, который уже есть в
  `CacheStore`
- **THEN** система возвращает сохранённые определения без довыборки файлов и
  парсинга

#### Scenario: Сбой построения индекса не ломает прогон

- **WHEN** довыборка дерева или файлов либо извлечение определений завершаются
  сбоем
- **THEN** индекс не сохраняется, прогон ревью продолжается без сигнатур, а
  следующий прогон по тому же коммиту повторяет построение

#### Scenario: Файлы выбираются на base_sha прогона

- **WHEN** между созданием прогона и построением индекса в основную ветку
  пришли новые коммиты
- **THEN** файлы довыбираются на `base_sha` прогона, а не на актуальном
  состоянии ветки на момент обработки

### Requirement: Извлечение определений — существующий порт и реестр языков

Система SHALL извлекать определения (модуль, классы, функции: имя, сигнатура,
позиция в файле) через существующий порт извлечения контуров и отбирать файлы
по общему с AST-уровнем реестру «расширение → язык»; слой домена и слой
приложения SHALL не знать библиотеку парсинга. Файл с расширением без
поддержанной грамматики SHALL пропускаться без сбоя индексации.

#### Scenario: Файл на поддержанном языке даёт определения

- **WHEN** индексируется файл на Python, содержащий классы и функции
- **THEN** в индекс попадают определения этих классов и функций с именами,
  сигнатурами и позициями строк

#### Scenario: Файл неизвестного языка пропускается

- **WHEN** индексируется файл с расширением, для которого нет грамматики
- **THEN** файл пропускается, индексация остальных файлов продолжается

### Requirement: Лимиты индексации

Система SHALL ограничивать индексацию числом файлов, размером файла и общим
временем индексации одного репозитория; лимиты задаются конфигурацией. Лимит
размера файла SHALL передаваться в довыборку содержимого и соблюдаться
транспортом: загрузка файла сверх лимита SHALL обрываться на лимите, файл —
пропускаться. При исчерпании лимита числа файлов или времени довыборка и
парсинг SHALL прекращаться, а частично построенный индекс SHALL считаться
валидным результатом.

#### Scenario: Слишком большой файл пропускается

- **WHEN** при индексации встречается файл больше лимита размера
- **THEN** загрузка обрывается на лимите, файл пропускается, остальные файлы
  индексируются

#### Scenario: Исчерпание лимита файлов даёт частичный индекс

- **WHEN** число довыбранных файлов достигает лимита до конца дерева
- **THEN** индекс сохраняется по уже обработанным файлам, построение
  завершается без сбоя

#### Scenario: Усечённое дерево даёт частичный индекс

- **WHEN** провайдер отдаёт дерево, усечённое по своему внутреннему лимиту
- **THEN** индекс строится по доступной части дерева и считается валидным

### Requirement: Best-effort хранение индекса

Индекс определений SHALL храниться в `CacheStore` по неизменяемым ключам
«репозиторий, коммит». Промах кэша SHALL не считаться ошибкой: при его
обнаружении потребитель работает без сигнатур, а следующий прогон по тому же
коммиту перестраивает индекс.

#### Scenario: Чтение индекса по неизменяемому ключу

- **WHEN** потребитель запрашивает определения репозитория на коммите `S`,
  ранее проиндексированном
- **THEN** он получает сохранённый набор определений по ключу «репозиторий,
  коммит `S`»

#### Scenario: Вытесненный индекс не ломает потребителей

- **WHEN** запись индекса вытеснена из `CacheStore` и потребитель обращается
  к ней
- **THEN** потребитель получает признак промаха и продолжает работу без
  сигнатур, а следующий прогон по тому же коммиту перестраивает индекс

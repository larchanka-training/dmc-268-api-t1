# Spec Delta: definitions-index

## Purpose

Определяет довыборку и хранение определений файлов основной ветки: при
прогоне ревью сосед по импортам довыбирается по требованию через
`VcsGateway`, определения извлекаются существующим портом за реестром
грамматик, результат хранится best-effort в `CacheStore` по ключу
«репозиторий, base_sha, путь». Потребление записей сборкой контекста —
способность `context-assembly`.

## ADDED Requirements

### Requirement: Довыборка определений по требованию

Система SHALL при прогоне ревью довыбирать определения соседнего файла по
требованию: по ключу «репозиторий, base_sha, путь», где `base_sha` — коммит
основной ветки из сообщения задачи. При попадании система SHALL возвращать
сохранённые определения без довыборки файла и парсинга. При промахе система
SHALL довыбрать содержимое файла на `base_sha` через `VcsGateway`, извлечь
определения, сохранить их по этому ключу и передать результат текущему
прогону ревью.

#### Scenario: Первый запрос соседа довыбирает и сохраняет определения

- **WHEN** прогон ревью запрашивает определения файла по ключу, которого нет
  в `CacheStore`
- **THEN** система довыбирает файл на `base_sha`, извлекает определения,
  сохраняет их по этому ключу и передаёт текущему прогону

#### Scenario: Повторный запрос берёт определения из кэша

- **WHEN** определения файла по ключу уже есть в `CacheStore`
- **THEN** система возвращает их без довыборки файла и парсинга

#### Scenario: Сбой довыборки не ломает прогон и не портит кэш

- **WHEN** довыборка файла либо извлечение определений завершаются сбоем
- **THEN** запись не сохраняется, прогон ревью продолжает работу без
  определений этого файла, а следующий запрос по тому же ключу повторяет
  довыборку

#### Scenario: Файлы довыбираются на base_sha прогона

- **WHEN** между созданием прогона и довыборкой в основную ветку пришли
  новые коммиты
- **THEN** файл довыбирается на `base_sha` прогона, а не на актуальном
  состоянии ветки на момент обработки

### Requirement: Разрешение импортов по дереву коммита

Система SHALL разрешать импорты изменённых файлов в пути репозитория по
дереву коммита `base_sha`, получаемому через `VcsGateway`, и кэшировать
дерево по ключу «репозиторий, base_sha». Импорт, чей путь не нашёлся в
дереве, SHALL пропускаться без сбоя.

#### Scenario: Дерево коммита переиспользуется

- **WHEN** дерево коммита `base_sha` уже закэшировано
- **THEN** разрешение импортов идёт по сохранённому дереву без запроса к
  `VcsGateway`

#### Scenario: Усечённое дерево ограничивает разрешение

- **WHEN** провайдер отдаёт дерево, усечённое по своему внутреннему лимиту
- **THEN** импорты, чьи пути не нашлись в доступной части, пропускаются без
  сбоя, остальные разрешаются

### Requirement: Извлечение определений — существующий порт и реестр языков

Система SHALL извлекать определения (модуль, классы, функции: имя, сигнатура,
позиция в файле) через существующий порт извлечения контуров и отбирать файлы
по общему с AST-уровнем реестру «расширение → язык»; слой домена и слой
приложения SHALL не знать библиотеку парсинга. Файл с расширением без
поддержанной грамматики SHALL пропускаться без сбоя довыборки.

#### Scenario: Файл на поддержанном языке даёт определения

- **WHEN** довыбирается файл на Python, содержащий классы и функции
- **THEN** из него извлекаются определения этих классов и функций с именами,
  сигнатурами и позициями строк

#### Scenario: Файл неизвестного языка пропускается

- **WHEN** сосед разрешается в файл с расширением, для которого нет
  грамматики
- **THEN** файл пропускается, довыборка остальных соседей продолжается

### Requirement: Лимиты довыборки

Система SHALL ограничивать довыборку числом соседних файлов за один прогон,
размером файла и общим временем довыборки; лимиты задаются конфигурацией.
Файл сверх лимита размера SHALL пропускаться без сбоя. При исчерпании лимита
соседей или времени довыборка SHALL прекращаться, а уже полученные
определения SHALL передаваться прогону.

#### Scenario: Слишком большой файл пропускается

- **WHEN** при довыборке встречается файл больше лимита размера
- **THEN** загрузка обрывается на лимите, файл пропускается, остальные
  соседи довыбираются

#### Scenario: Исчерпание лимита соседей даёт неполный набор

- **WHEN** число соседей, довыбранных за прогон, достигло лимита, а импорты
  ещё разрешаются
- **THEN** довыборка прекращается, прогон получает уже полученные
  определения, построение завершается без сбоя

### Requirement: Лимит времени не конкурирует с выметателем прогонов

Лимит времени довыборки SHALL быть меньше порога зависших прогонов:
довыборка идёт внутри шага сборки контекста без отметок прогресса, и
выметатель зависших прогонов не должен объявлять живой прогон зависшим раньше
срабатывания лимита.

#### Scenario: Конфигурация с лимитом времени выше порога отклоняется

- **WHEN** настройки задают лимит времени довыборки не меньше порога
  зависших прогонов
- **THEN** конфигурация отклоняется при старте сервиса

### Requirement: Best-effort хранение записей

Определения SHALL храниться в `CacheStore` по неизменяемым ключам
«репозиторий, коммит, путь», дерево коммита — по ключу «репозиторий,
коммит»; время жизни записей SHALL ограничиваться настройкой. Промах SHALL не
считаться ошибкой и SHALL запускать довыборку в текущем прогоне. Вытеснение
и истечение времени жизни SHALL требовать обработки: следующий запрос
довыберет записи заново и передаст их текущему прогону.

#### Scenario: Чтение определений по неизменяемому ключу

- **WHEN** потребитель запрашивает определения файла `P` на коммите `S`,
  ранее довыбранном
- **THEN** он получает сохранённый набор определений по ключу «репозиторий,
  коммит `S`, путь `P`»

#### Scenario: Вытесненная запись довыбирается текущим прогоном

- **WHEN** запись вытеснена из `CacheStore`, а прогон ревью запрашивает её
- **THEN** система довыбирает файл и передаёт определения текущему прогону,
  а не откладывает довыборку до следующего прогона

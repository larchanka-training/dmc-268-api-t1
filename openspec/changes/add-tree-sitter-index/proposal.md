# Proposal: add-tree-sitter-index

## Why

AST-уровень сборки контекста довыбирает и парсит только изменённые файлы на
`head_sha` (спека `context-assembly`): сигнатуры остального кода репозитория —
самый стабильный и переиспользуемый кусок контекста — не попадают в него
вовсе, хотя §2 `docs/SYSTEM_DESIGN.md` называет «сигнатуры из файлов, на
которые ссылаются импорты» запланированными. Словарь сигнатур основной ветки,
построенный один раз на коммит и переиспользуемый прогонами, закрывает пробел
и убирает довыборку и парсинг соседних файлов из горячего пути ревью.

Индекс потребляется сразу: прогон ревью, первым обратившийся к коммиту, строит
его, последующие берут по тому же ключу. Ленивая сборка выбрана осознанно:
in-process `CacheStore` воркера сбрасывается при каждом рестарте, а рестарт
происходит на каждом деплое — упреждающая переиндексация по push строила бы
индекс, который умирает до первого чтения.

## What Changes

- Сборка контекста запрашивает индекс по ключу «репозиторий, base_sha» (sha
  основной ветки из сообщения задачи, §4.2): промах — `fetch_tree` даёт дерево
  коммита, файлы языков из реестра грамматик довыбираются существующим
  `fetch_file` (лимит размера — через `max_bytes`), определения извлекаются
  существующим портом `DefinitionExtractor`, словарь сохраняется в
  `CacheStore`; попадание — переиспользование без довыборки и парсинга.
- Новая способность `definitions-index`: ленивое построение при прогоне
  ревью, лимиты (число файлов, размер, время), best-effort хранение по
  неизменяемым ключам; сбой построения или промах не ломают прогон — контекст
  собирается без словаря.
- Потребление: сигнатуры из индекса входят в пакет вторым источником уровня
  `ast` — отдельного значения в `tiers` не появляется. Из словаря берутся
  только определения, релевантные диффу: файлы, разрешимые из импортов
  изменённых; записи для самих изменённых файлов не дублируются (их контур на
  `head_sha` уже в пакете и побеждает). Записи идут в бюджет после AST-блоков
  изменённых файлов, не поместившееся — в `omitted`.
- `VcsGateway` расширяется единственным методом `fetch_tree` (рекурсивный
  список путей дерева коммита); порты `CacheStore` и `DefinitionExtractor`,
  их адаптеры и реестр грамматик переиспользуются без изменений.
- Изменение принципа «контекст без клона» в `docs/SYSTEM_DESIGN.md`: полный
  клон и хранение репозитория по-прежнему запрещены, но индекс определений
  основной ветки (файлы довыбираются через `VcsGateway` по sha) разрешён.

## Capabilities

### New Capabilities

- `definitions-index`: ленивое построение и best-effort хранение индекса
  определений репозитория — промах при прогоне ревью, довыборка дерева и
  файлов через `VcsGateway`, извлечение за существующим портом, лимиты.

### Modified Capabilities

- `context-assembly`: уровень `ast` получает второй источник — сигнатуры
  основной ветки из индекса; релевантность — дифф и его импорт-окрестность,
  приоритет контура на `head_sha` при дубле файла, место в бюджете токенов.

## Impact

- **Код**: `app/application/` (сценарий get-or-build индекса, встраивание в
  сборку контекста), `app/application/ports/vcs_gateway.py` (+`fetch_tree`),
  `app/domain/` (чистые функции выбора записей индекса и разрешения
  импортов), `app/infrastructure/vcs/github.py` (trees API), `app/config.py`
  (лимиты индексации). Порты `CacheStore`/`DefinitionExtractor`, их адаптеры,
  гейт вебхуков и формат очереди не меняются.
- **Зависимости**: новых нет — tree-sitter и грамматики уже в
  `pyproject.toml` (AST-уровень).
- **Документы**: `docs/SYSTEM_DESIGN.md` (принцип «контекст без клона», §4.3 —
  второй потребитель кэша, §5 — второй источник уровня `ast`),
  `docs/BACKEND_ARCHITECTURE.md` (`fetch_tree` в таблице портов).
- **База данных**: схемы не касается — миграций нет, `alembic heads` остаётся
  один.
- **Очередность**: база — `develop`; контракт потребления добавляется
  требованием в `context-assembly`, конфликтов с существующими требованиями
  спек не закладано.

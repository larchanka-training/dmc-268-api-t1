# Proposal: add-tree-sitter-index

## Why

AST-уровень сборки контекста ревью (сигнатуры определений из соседних файлов) на каждое
событие довыбирает и парсит файлы заново, а сигнатуры кода основной ветки — самый
стабильный и переиспользуемый кусок контекста: между прогонами меняются редко. Индекс
определений, который строится tree-sitter'ом один раз на коммит основной ветки и
переиспользуется прогонами, убирает повторный парсинг из горячего пути ревью и даёт
пайплайну готовый словарь сигнатур по sha основной ветки.

Индекс потребляется сразу: прогон ревью, первым обратившийся к коммиту, строит его,
последующие прогоны берут по тому же ключу. Ленивая сборка выбрана осознанно: in-process
`CacheStore` воркера сбрасывается при каждом рестарте, а рестарт происходит на каждом
деплое — упреждающая переиндексация по push строила бы индекс, который умирает до первого
чтения.

## What Changes

- Сборка контекста прогона ревью запрашивает индекс определений по ключу
  «репозиторий, base_sha» (sha основной ветки из сообщения задачи, §4.2): промах —
  довыборка дерева и содержимого файлов на `base_sha` через `VcsGateway`, извлечение
  определений (модули, классы, функции с сигнатурами и позициями) tree-sitter'ом,
  сохранение в `CacheStore`; попадание — переиспользование без довыборки и парсинга.
- Новая способность `definitions-index`: ленивое построение при прогоне ревью, лимиты,
  best-effort хранение в `CacheStore` по неизменяемым ключам; сбой построения или промах
  не ломают прогон — контекст собирается без сигнатур.
- Потребление: словарь сигнатур включается в контекст прогона (уровень `ast` в
  `tiers`) наравне с другими уровнями и под теми же жёсткими лимитами токенов.
- Язык файла определяется по расширению; первой поддержана грамматика Python,
  реестр грамматик — шов для следующих языков; файл неизвестного языка или
  превышающий лимиты пропускается, не ломая индекс.
- Изменение принципа «контекст без клона» в `docs/SYSTEM_DESIGN.md`: полный клон и
  хранение репозитория по-прежнему запрещены, но индекс определений основной ветки
  (файлы довыбираются через `VcsGateway` по sha) разрешён.
- Парсинг спрятан за портом `DefinitionExtractor`: tree-sitter остаётся деталью
  адаптера инфраструктуры, домен и приложение вендора не знают; сохранён шов
  Strangler Fig на случай выноса парсинга в отдельный сервис.

## Capabilities

### New Capabilities

- `definitions-index`: построение и хранение индекса определений репозитория —
  ленивый триггер промахом при прогоне ревью, довыборка файлов через `VcsGateway`,
  извлечение tree-sitter'ом, лимиты, best-effort хранение в `CacheStore`, потребление
  сборкой контекста.

### Modified Capabilities

Нет: webhook-приём и формат очереди не меняются — подписка на событие `push` и задачи
переиндексации не вводятся, спеки `webhook-intake` и `job-queue` дельт не получают.

## Impact

- **Код**: `app/application/` (сценарий get-or-build индекса, встраивание в сборку
  контекста прогона), `app/application/ports/` (`CacheStore`, `DefinitionExtractor`,
  расширение `VcsGateway` — `fetch_tree`, `fetch_file`), `app/infrastructure/`
  (адаптеры кэша, tree-sitter, GitHub trees/blobs), `app/config.py` (лимиты
  индексации). Гейт вебхуков, формат очереди и диспетчеризация воркера не меняются.
- **Зависимости**: `tree-sitter` и `tree-sitter-python` через `uv sync --all-extras`;
  проверить колёса для Python 3.14 — риск, задача спайка стоит первой.
- **Документы**: `docs/SYSTEM_DESIGN.md` (принцип «контекст без клона»),
  `docs/BACKEND_ARCHITECTURE.md` (порт `DefinitionExtractor`, шов парсинга).
- **База данных**: схемы не касается — миграций нет, `alembic heads` остаётся один.
- **Очередность**: база — `develop` (PR #37 смёржен); дельта одна, конфликты с
  существующими спеками не заложены.

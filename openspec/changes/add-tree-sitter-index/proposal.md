# Proposal: add-tree-sitter-index

## Why

AST-уровень сборки контекста довыбирает и парсит только изменённые файлы на
`head_sha` (спека `context-assembly`): сигнатуры остального кода репозитория —
самый стабильный и переиспользуемый кусок контекста — не попадают в него
вовсе, хотя §2 `docs/SYSTEM_DESIGN.md` называет «сигнатуры из файлов, на
которые ссылаются импорты» запланированными. Определения соседей по импортам,
закэшированные по ключу «репозиторий, base_sha, путь», закрывают пробел:
первый прогон, которому нужен сосед, довыбирает его, последующие прогоны и
другие MR того же коммита берут запись по тому же ключу.

Довыборка по требованию выбрана осознанно: in-process `CacheStore` воркера
сбрасывается при каждом рестарте, а рестарт происходит на каждом деплое —
упреждающая переиндексация по push строила бы словарь всего репозитория,
который умирает до первого чтения, тратя запросы к GitHub API на файлы,
которые никто не спросит. По требованию прогон платит один запрос дерева
коммита и довыборку только своих соседей.

## What Changes

- Сборка контекста разрешает импорты изменённых файлов по дереву коммита
  `base_sha` (sha основной ветки из сообщения задачи, §4.2): `fetch_tree`
  даёт список путей (кэш по ключу «репозиторий, base_sha»), чистая функция
  домена превращает импорты в пути соседей.
- Для каждого соседа — get-or-fetch по ключу «репозиторий, base_sha, путь»:
  промах — файл довыбирается существующим `fetch_file` (лимит размера —
  через `max_bytes`), определения извлекаются существующим портом
  `DefinitionExtractor`, словарь сохраняется в `CacheStore`; попадание —
  переиспользование без довыборки и парсинга. Результат промаха получает
  текущий прогон, а не следующий.
- Новая способность `definitions-index`: довыборка по требованию при прогоне
  ревью, лимиты (число соседей за прогон, размер файла, время), best-effort
  хранение по неизменяемым ключам с TTL; сбой довыборки или отсутствие
  записей не ломают прогон — контекст собирается без словаря, сбой не
  оставляет записи в кэше.
- Записи индекса живут в отдельном экземпляре `CacheStore` со своим лимитом
  записей: килобайтные определения не делят лимит с кэшем правил, память
  воркера ограничена сверху.
- Потребление: сигнатуры из индекса входят в пакет вторым источником уровня
  `ast` — отдельного значения в `tiers` не появляется. Из словаря берутся
  только определения, релевантные диффу: файлы, разрешимые из импортов
  изменённых; записи для самих изменённых файлов никогда не добавляются —
  независимо от наличия контура на `head_sha` (когда он есть, он побеждает
  как более свежий). Записи идут в бюджет после AST-блоков изменённых
  файлов, не поместившееся — в `omitted`.
- `VcsGateway` расширяется единственным методом `fetch_tree` (рекурсивный
  список путей дерева коммита); порты `CacheStore` и `DefinitionExtractor`,
  их адаптеры и реестр грамматик переиспользуются без изменений.
- Изменение принципа «контекст без клона» в `docs/SYSTEM_DESIGN.md`: полный
  клон и хранение репозитория по-прежнему запрещены, но индекс определений
  основной ветки (файлы довыбираются через `VcsGateway` по sha) разрешён.

## Capabilities

### New Capabilities

- `definitions-index`: довыборка по требованию и best-effort хранение
  определений файлов репозитория — запрос соседа при прогоне ревью, дерево
  коммита и содержимое через `VcsGateway`, извлечение за существующим портом,
  лимиты.

### Modified Capabilities

- `context-assembly`: уровень `ast` получает второй источник — сигнатуры
  основной ветки из индекса; релевантность — дифф и его импорт-окрестность,
  безусловное исключение изменённых файлов, место в бюджете токенов.

## Impact

- **Код**: `app/application/` (сценарии get-or-fetch дерева и определений,
  встраивание в сборку контекста), `app/application/ports/vcs_gateway.py`
  (+`fetch_tree`), `app/domain/` (чистые функции выбора соседей и разрешения
  импортов), `app/infrastructure/vcs/github.py` (trees API), `app/config.py`
  (лимиты довыборки, TTL и лимит отдельного кэша, инвариант таймаута),
  контейнер (второй экземпляр `CacheStore` для индекса). Порты
  `CacheStore`/`DefinitionExtractor` и их адаптеры не меняются; гейт вебхуков
  и формат очереди не меняются.
- **Зависимости**: новых нет — tree-sitter и грамматики уже в
  `pyproject.toml` (AST-уровень).
- **Документы**: `docs/SYSTEM_DESIGN.md` (принцип «контекст без клона», §4.3 —
  второй потребитель кэша в отдельном экземпляре, §5 — второй источник
  уровня `ast`), `docs/BACKEND_ARCHITECTURE.md` (`fetch_tree` в таблице
  портов).
- **База данных**: схемы не касается — миграций нет, `alembic heads` остаётся
  один.
- **Очередность**: база — `develop`; контракт потребления добавляется
  требованием в `context-assembly`, конфликтов с существующими требованиями
  спек не заложено.

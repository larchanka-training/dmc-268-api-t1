# Proposal: add-tree-sitter-index

## Why

AST-уровень сборки контекста ревью (сигнатуры определений из соседних файлов) на каждое
событие довыбирает и парсит файлы заново, а сигнатуры кода основной ветки — самый
стабильный и переиспользуемый кусок контекста: между прогонами меняются редко. Индекс
определений, который строится tree-sitter'ом один раз на репозиторий и обновляется при
каждом коммите в основную ветку, убирает повторный парсинг из горячего пути ревью и
даёт пайплайну готовый словарь сигнатур по sha основной ветки.

## What Changes

- Приём вебхуков расширяется событием `push`: доставки в основную ветку
  (`ref == refs/heads/<default_branch>`) ставят задачу переиндексации в очередь;
  пуши в остальные ветки, удаления ветки (нулевой `after`) и незарегистрированные
  репозитории молча игнорируются (`202 ignored`), как того требует существующий
  контракт приёма.
- Очередь, кроме задач ревью, несёт задачи переиндексации (`event_type: "push"`):
  тот же брокер, тот же порт `JobQueue`, тот же механизм dead-letter; в теле задачи
  нет `review_run_id` — переиндексация не создаёт строку в `review_runs`.
- Воркер при получении задачи переиндексации через `VcsGateway` довыбирает дерево
  репозитория и содержимое файлов на `after`-коммите и извлекает определения
  (модули, классы, функции с сигнатурами и позициями) tree-sitter'ом.
- Новая способность `definitions-index`: best-effort хранение определений в
  `CacheStore` по неизменяемым ключам `(репозиторий, sha)` плюс маркер
  «проиндексированный sha репозитория»; задача с уже проиндексированным sha
  подтверждается без работы (коалесинг повторных доставок).
- Язык файла определяется по расширению; первой поддержана грамматика Python,
  реестр грамматик — шов для следующих языков; файл неизвестного языка или
  превышающий лимиты пропускается, не ломая индекс.
- Изменение принципа «контекст без клона» в `docs/SYSTEM_DESIGN.md`: полный клон и
  хранение репозитория по-прежнему запрещены, но индекс определений основной ветки
  (файлы довыбираются через `VcsGateway` по sha) разрешён.
- Парсинг спрятан за портом `DefinitionExtractor`: tree-sitter остаётся деталью
  адаптера инфраструктуры, домен и приложение вендора не знают; сохранён шов
  Strangler Fig на случай выноса парсинга в отдельный сервис.

## Capabilities

### New Capabilities

- `definitions-index`: построение и хранение индекса определений репозитория —
  триггер задачей из очереди, довыборка файлов через `VcsGateway`, извлечение
  tree-sitter'ом, лимиты, best-effort хранение в `CacheStore`, коалесинг по sha.

### Modified Capabilities

- `webhook-intake`: новое требование — приём события `push`: фильтр по основной
  ветке, отсечение удалений ветки и незарегистрированных репозиториев, постановка
  задачи переиндексации. Существующие требования (HMAC, ответы 501 и ignored)
  не меняются.
- `job-queue`: новое требование — очередь несёт задачи переиндексации
  (`event_type: "push"`, без `review_run_id`), dead-letter и приоритеты
  применяются к ним наравне с задачами ревью.

## Impact

- **Код**: `app/api/webhooks.py` (гейт событий пропускает `push`),
  `app/domain/webhook.py` (извлечение push-события), `app/application/ports/`
  (`CacheStore`, `DefinitionExtractor`, расширение `VcsGateway` — `fetch_tree`,
  `fetch_file`), `app/application/use_cases/` (обработка push, сценарий
  переиндексации), `app/worker/` (диспетчеризация задач по `event_type`),
  `app/infrastructure/` (адаптеры кэша, tree-sitter, GitHub trees/blobs),
  `app/config.py` (лимиты индексации).
- **Зависимости**: `tree-sitter` и `tree-sitter-python` через `uv sync --all-extras`;
  проверить колёса для Python 3.14 — риск, задача спайка стоит первой.
- **Документы**: `docs/SYSTEM_DESIGN.md` (принцип «контекст без клона»),
  `docs/BACKEND_ARCHITECTURE.md` (порт `DefinitionExtractor`, шов парсинга).
- **База данных**: схемы не касается — миграций нет, `alembic heads` остаётся один.
- **Очередность**: база — ветка PR #37 (вебхуки, `VcsGateway`, очередь); вливается
  в `develop` после него. Пока #37 не влит, спеки `webhook-intake` и `job-queue`
  отсутствуют в основных спеках этой ветки, поэтому дельты добавляют новые
  требования и локально валидируются без базы.

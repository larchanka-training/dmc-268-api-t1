# Proposal

## Why

Аудит того, что построено за день, нашёл четыре мелких дефекта и один лишний файл. Ничего из этого не горит, но всё измерено и подтверждено, а стоимость исправления — один прогон деплоя.

Шаг проверки публичной доступности пишет значение в `$GITHUB_OUTPUT`, не имея `id`: прочитать его невозможно, строка просто не работает. `packages: write` выдан всему деплой-workflow, хотя нужен только job'у сборки образа. У контейнера API нет healthcheck, притом что `/health` существует именно для этого, а у postgres и rabbitmq healthcheck'и есть — то есть Docker не знает, живой ли сервис, и реагирует только на выход процесса. Контейнер миграций ждёт открытия TCP-порта базы, а PostgreSQL открывает порт раньше, чем начинает принимать запросы: окно маленькое, поэтому и не выстрелило, но это флак, который однажды уронит деплой без причины.

Отдельно `tfstate-backend.yml` после появления деплоя потерял собственное содержание. Проба условной записи свою задачу выполнила — ответ получен и зафиксирован. `tofu init` дублируется: `ci.yml` проверяет конфигурацию на каждом пул-реквесте, деплой делает настоящий `init`. Подъём и починка хранилища живут в composite action, который деплой вызывает первым job'ом.

## What Changes

- Шаг проверки публичной доступности перестаёт писать в никуда.
- `packages: write` переезжает с уровня workflow на job сборки образа.
- У контейнера API появляется healthcheck по `/health`.
- Контейнер миграций перестаёт угадывать готовность базы по открытому порту и вместо этого повторяет саму команду миграции.
- `tfstate-backend.yml` удаляется; composite action остаётся.

**Не входит:** выходы `postgres_url` и `rabbitmq_url`. Изначально попали в аудит как неиспользуемые, но в них зашит `urlencode` пароля — та деталь, которую собирают руками и ошибаются. Остаются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`: требования `backend-delivery` не меняются. Healthcheck и ретрай миграций делают уже описанное поведение надёжнее, а не другим.

## Impact

- `.github/workflows/deploy.yml`, `infra/main.tf`.
- Удаляется `.github/workflows/tfstate-backend.yml`.
- Теряется возможность проверить хранилище состояния, не применяя конфигурацию. Сценарий редкий; когда понадобится, это двадцать строк поверх composite action. Фиксируется в [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22), чтобы не выяснять заново, почему файла нет.

# Proposal

> **Статус: предложение, не утверждено.** Кода, миграций и правок `openspec/specs/` нет.
> Применяется после change `incremental-review`: неполное покрытие опирается на его журнал.

## Why

Расход модели ничем не ограничен: `context_max_tokens` молча отбрасывает не поместившееся в
`omitted`, а прогон всё равно `completed` и gate получает `success`. Квоты расхода нет.
Нужны покрытие и квота, при которых непроверенный код никогда не проходит merge gate.

## What Changes

- **Покрытие прогона** — причина неполноты и перечень непроверенных файлов; пустой перечень —
  покрытие полное. Непроверенное не попадает в журнал и проверяется следующим прогоном.
- **Неполное покрытие — `failure` на head** со списком непроверенных файлов. Везде, где строится
  gate: публикация, пересчёт по треду, `settle_merge_gate`. `neutral` не используется:
  GitHub считает его пройденной обязательной проверкой.
- **`omitted` — неполное покрытие.** Hunk, отложенный сборкой контекста по `context_max_tokens`,
  даёт причину `context_budget` и `failure` на head. Правило включается вместе с журналом
  (`INCREMENTAL_REVIEW_ENABLED`): без него остаток не добрать. Hunk больше предела называется в
  check run отдельно — его добор не проверит.
- **Новые hunk'и раньше перепроверяемых** — с находками прошлого прогона: в этом порядке сборка
  контекста набирает пакет.
- **Суточная квота токенов репозитория.** Исчерпана — прогон без модели с причиной `quota` и
  `failure`; остаток проверяет следующий push или повтор доставки. Токены отменённых прогонов
  в расход входят.
- **Неполный прогон не дубль**: повтор доставки на коммит, чей последний прогон с неполным
  покрытием, создаёт новый прогон.

Квота выключена по умолчанию и включается настройками стенда.

Бюджет токенов прогона, предел числа файлов и строк с приоритетом CI и шум по `.gitattributes`
из этого change вынесены — proposal `incremental-review`, «Не входит».

## Capabilities

### New Capabilities

- `review-limits`: покрытие, отложенное сборкой контекста, gate при неполном покрытии, квота
  репозитория.

### Modified Capabilities

- `webhook-intake`: MODIFIED «Повторная доставка на проверенный коммит отвечает существующим
  прогоном» — неполный прогон не дубль.
- `review-data-model`: ADDED покрытие прогона.

## Impact

- Код: `context_assembly.py` — порядок hunk'ов и перечни непроверенного; `build_merge_gate_check`
  (#225) учитывает покрытие; `_duplicate_of` (#225); `review_pipeline.py` — `tokens_used` при
  отмене; `app/config.py` — квота.
- БД: `review_runs.coverage_reason`, `unreviewed_paths`, `oversized_paths` — миграцией на этапе
  реализации.
- API: `coverage_reason`, `unreviewed_paths` в `ReviewJob` — аддитивно.

# Proposal

> **Статус: предложение, не утверждено.** Кода, миграций и правок `openspec/specs/` нет.
> Применяется после change `incremental-review`: неполное покрытие опирается на его журнал.
> Сводный документ — [`docs/pipeline/INCREMENTAL_REVIEW_AND_LIMITS_SPEC.md`](../../../docs/pipeline/INCREMENTAL_REVIEW_AND_LIMITS_SPEC.md).

## Why

Расход модели ничем не ограничен: `context_max_tokens` молча отбрасывает не поместившееся в
`omitted`, а прогон всё равно `completed` и gate получает `success`. Квоты расхода нет.
Нужны бюджет и квота, при которых непроверенный код никогда не проходит merge gate.

## What Changes

- **Покрытие прогона** — `complete`, `partial` или `none` по файлам области. Непроверенное не
  попадает в журнал и проверяется следующим прогоном.
- **Неполное покрытие — `failure` на head** со списком непроверенных файлов. Везде, где строится
  gate: публикация, пересчёт по треду, `settle_merge_gate`. `neutral` не используется:
  GitHub считает его пройденной обязательной проверкой.
- **Бюджет токенов прогона** на ревью, верификатор и повторы; не поместившееся — `partial`.
- **Размер области** — пределы файлов и изменённых строк; приоритет — CI и инфраструктура
  первыми (`.github/`, `Dockerfile*`, `infra/`, `*.tf`, скрипты деплоя), затем код, тесты, документация.
  Новые hunk'и идут раньше перепроверяемых — с находками прошлого прогона.
- **Суточная квота токенов репозитория.** Исчерпана — прогон без модели с покрытием `none` и
  `failure`; остаток проверяет следующий push или повтор доставки.
- **Шум по `.gitattributes` только с `base_sha`.** Маркер `@generated` и `.gitattributes` из
  самого PR файл из области не исключают: их ставит автор PR.
- **Неполный прогон не дубль**: повтор доставки на коммит, чей последний прогон с неполным
  покрытием, создаёт новый прогон.

- **`omitted` — всегда неполное покрытие.** Hunk, отложенный сборкой контекста по
  `context_max_tokens`, даёт `partial` с причиной `context_budget` и `failure` на head — без
  флага, даже при выключенных лимитах.

Лимиты выключены по умолчанию и включаются настройками стенда; правило про `omitted` от них не
зависит.

## Capabilities

### New Capabilities

- `review-limits`: покрытие, gate при неполном покрытии, бюджет токенов, размер области,
  квота репозитория, фильтрация по `.gitattributes`.

### Modified Capabilities

- `webhook-intake`: MODIFIED «Повторная доставка на проверенный коммит отвечает существующим
  прогоном» — неполный прогон не дубль.
- `review-data-model`: ADDED покрытие прогона по файлам.

## Impact

- Код: чистые `plan_scope` и `fits_budget` в `app/domain`; `build_merge_gate_check`
  (#225) учитывает покрытие; `_duplicate_of` (#225); `filter_diff_files`; `app/config.py` —
  лимиты.
- БД: `review_runs.coverage`, `coverage_reason`, таблица `review_run_files` — миграциями на
  этапе реализации.
- API: `coverage`, `coverage_reason` в `ReviewJob` — аддитивно.

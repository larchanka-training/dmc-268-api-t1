## ADDED Requirements

### Requirement: Приложение работает с базой под ролью без прав на схему

API и воркер SHALL входить в базу данных ролью без суперпользователя и без права менять схему: только чтение и запись данных таблиц, в том числе таблиц, которые создадут будущие миграции. Схему SHALL менять только миграции под ролью владельца. Пароль роли приложения SHALL приходить из своего секрета и меняться обычным развёртыванием; пустой, короче 16 символов или с пробелом пароль SHALL отклоняться до изменений на сервере.

#### Scenario: Приложение работает с данными

- **WHEN** API или воркер записывает и читает прогоны, блокирует плательщика и слушает уведомления о прогонах
- **THEN** запросы проходят под ролью приложения

#### Scenario: Приложение пытается изменить схему

- **WHEN** под ролью приложения выполняется создание, изменение или удаление таблицы, её очистка или запись ревизии схемы
- **THEN** база отвечает отказом в правах, схема не меняется

#### Scenario: База восстановлена из копии

- **WHEN** база восстановлена из копии с пересозданием таблиц и после этого прошло развёртывание
- **THEN** запись ревизии схемы под ролью приложения снова отклоняется

#### Scenario: Миграция добавила таблицу

- **WHEN** миграция под ролью владельца создаёт новую таблицу
- **THEN** приложение читает и пишет её без отдельной выдачи прав

#### Scenario: Новый пароль роли приложения

- **WHEN** в развёртывание приходит новый пароль роли приложения
- **THEN** после миграций роль принимает новый пароль и отклоняет старый, новые API и воркер входят новым

#### Scenario: Пароль роли приложения не задан

- **WHEN** секрет пароля роли приложения пуст или короче 16 символов
- **THEN** планирование завершается ошибкой проверки переменной, контейнеры стенда не пересоздаются

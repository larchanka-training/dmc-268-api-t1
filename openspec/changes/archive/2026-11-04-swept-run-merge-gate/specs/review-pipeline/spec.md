## MODIFIED Requirements

### Requirement: Упавший прогон после ревью head блокирует merge gate

Прогон, упавший в воркере или выметенный очисткой последним на своём head-коммите, SHALL выставить check run `failure`, если до него на этот head-коммит уже был прогон `completed` или `cancelled` по вебхуку: прежний мог оставить `success` по старому диффу. Без прежнего прогона на head check run SHALL NOT выставляться. На паузе ревью действует требование «Прогон при паузе ревью не блокирует merge gate». Сбой GitHub SHALL попадать в лог и SHALL NOT подменять ошибку прогона и прерывать очистку.

#### Scenario: Ревью после смены ветки упало, поправка не дошла

- **WHEN** на head `success` прежнего прогона по старой ветке, а прогон нового диффа упал
- **THEN** на head выставляется `failure` «Ревью не удалось»

#### Scenario: Первое ревью коммита упало

- **WHEN** ревью не на паузе, прогон упал, а других прогонов на этот head-коммит нет
- **THEN** check run не выставляется, на PR ничего не появляется

#### Scenario: За head отвечает более поздний прогон

- **WHEN** прогон упал, а на этот head-коммит уже создан более поздний прогон
- **THEN** упавший прогон check run не выставляет

#### Scenario: Очистка вымела прогон

- **WHEN** воркер умер посреди прогона на коммите, где уже было ревью, и очистка перевела прогон в `failed`
- **THEN** очистка узнаёт у GitHub номер установки по репозиторию прогона и ставит на head `failure` «Ревью не удалось»

#### Scenario: Очистка вымела прогон живого воркера

- **WHEN** вызов модели длиннее порога, очистка перевела прогон в `failed`, и на этот head-коммит уже было ревью
- **THEN** следующая запись воркера падает, ревью не публикуется, на head ставится `failure` «Ревью не удалось»

#### Scenario: GitHub недоступен во время очистки

- **WHEN** очистка вымела два прогона, а номер установки или check run GitHub не отдал
- **THEN** сбой пишется в лог, оба прогона остаются `failed`, и счётчик выметенных равен двум

#### Scenario: Временный сбой GitHub в проходе очистки

- **WHEN** на первом выметенном прогоне GitHub отвечает временным сбоем (сеть, лимит)
- **THEN** до конца прохода очистка в GitHub не ходит: остальные прогоны выметаются без gate

## REMOVED Requirements

### Requirement: Очистка не меняет merge gate

**Reason**: выметенный прогон оставлял на head устаревший check run (#331); теперь очистка выставляет gate по требованию «Упавший прогон после ревью head блокирует merge gate».

**Migration**: сценарии перенесены в это требование; поведение пайплайна не меняется.

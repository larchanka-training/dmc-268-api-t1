# Proposal

## Why

На сервере наружу слушает порт 5355 — LLMNR, протокол разрешения имён для локальной сети, который поднимает `systemd-resolved`. Проверено: сокеты висят на `0.0.0.0` и по TCP, и по UDP, `resolvectl status` показывает `+LLMNR`, а в `/etc/systemd/resolved.conf` строка закомментирована — то есть работает значение по умолчанию из образа Ubuntu.

На одиночном сервере LLMNR не разрешает ничего полезного: он нужен машинам в одном сетевом сегменте, чтобы спрашивать имена друг у друга. Поверхность атаки он добавляет небольшую — по замыслу протокол link-local и через маршрутизатор не ходит, — но в любом сканировании порт виден как открытый, и объяснять его придётся каждый раз.

Это наследство образа, а не чьё-то решение.

## What Changes

- LLMNR отключается в конфигурации `systemd-resolved`, порт 5355 перестаёт слушать.
- Изменение выполняется workflow по ключу CI, как и всё остальное на сервере, а не руками.
- Workflow удаляется после применения: он одноразовый, как и подготовка сервера до него.

**Не входит:** порт 22. SSH — канал доставки: через него идут `tofu apply`, туннель к хранилищу состояния и отладка. Закрыть его значит отрезать деплой.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`: настройка операционной системы на стенде не меняет наблюдаемого поведения сервиса. Требование «наружу доступен только API через `/api/`» уже записано и после этого изменения продолжает выполняться — просто рядом становится на один посторонний порт меньше.

## Impact

- Новый временный workflow, удаляемый после применения.
- На сервере меняется `/etc/systemd/resolved.conf`, перезапускается `systemd-resolved`. Обычное разрешение имён через DNS не затрагивается.
- **Вскрывает пробел:** настройкам уровня операционной системы негде жить. Docker ставился удалённым bootstrap-workflow, который мы удалили; Terraform управляет только контейнерами. При пересоздании сервера и установка Docker, и эта настройка будут потеряны. Записывается в [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22) как известный пробел, а не решается здесь.

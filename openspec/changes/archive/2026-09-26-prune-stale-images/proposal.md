# Proposal

## Why

Каждый деплой публикует образ с тегом по commit sha и забирает его на сервер. У `docker_image.api` стоит `keep_locally = true`, то есть Terraform старые образы не удаляет никогда. После двух деплоев на хосте уже лежат два образа API по 320 МБ.

Масштаб измерен, а не прикинут, и он оказался заметно меньше ожидаемого. `docker images` показывает у каждого образа API 320 МБ, но это размер со всеми общими слоями. Удаление двух старых образов API и разового `alpine` освободило **99 КБ**: базовый слой и зависимости у всех тегов общие, различается только слой с кодом приложения.

Значит линейного роста «по 320 МБ за мерж» нет. Реальный рост наступает, когда меняются зависимости (`pyproject.toml`, `uv.lock`) — тогда на диск ложится новый набор слоёв целиком. За долгий проект это накапливается, но счёт идёт на изменения зависимостей, а не на деплои.

Попутно на хосте лежит `alpine:latest`, притащенный разовой диагностикой содержимого тома.

## What Changes

- После успешного `apply` деплой удаляет неиспользуемые образы старше заданного возраста.
- Возраст не нулевой: недавние теги остаются, чтобы откат на предыдущий коммит не требовал повторной загрузки.
- Шаг не роняет деплой: неудачная уборка — это мусор на диске, а не сломанный выкат.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`: уборка диска на стенде не меняет наблюдаемого поведения сервиса.

## Impact

- `.github/workflows/deploy.yml` — один шаг после `apply`.
- На сервере удаляются образы, на которых не работает ни один контейнер и которые старше порога. Работающие образы Docker не трогает по определению.
- Разово уйдёт `alpine:latest`.

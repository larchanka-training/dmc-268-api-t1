# Proposal: правки по ревью LLM Gateway

## Why

Ревью PR #65 нашло, где транспорт к модели и его конфигурация расходятся с обещаниями `add-llm-gateway`.
Описание PR при настройках по умолчанию почти никогда не доходит до модели, обрезанный ответ гоняется по кругу, токены сбойных попыток теряются, а стек без выбора адаптера молча берёт заглушку.

## What Changes

- Ответ, который модель оборвала по пределу длины (`done_reason` у Ollama, `finish_reason` у OpenAI-совместимого API - `length`), сразу завершает вызов провайдера сбоем «ответ обрезан» без повторной попытки: повтор с тем же пределом оборвался бы снова.
- Токены, которые израсходовал сбойный вызов, учитываются: адаптер передаёт их в сбое (`LlmError.tokens_used` из #63), составной фоллбэк суммирует токены всех провайдеров, к которым обращался, и в ответе, и в сбое.
- Подключение к провайдеру ограничено отдельным таймаутом в 10 секунд: выключенный хост локальной модели больше не держит вызов полный таймаут ответа.
- Воркер не стартует, если худший случай одного вызова модели (таймаут × попытки × провайдеры) не короче порога зависшего прогона.
- Стек не выбирает заглушку за пользователя: у `llm_backend` в `infra/variables.tf` нет значения по умолчанию, деплой стенда задаёт `stub` явно, `docker-compose.yml` передаёт пустое значение, и воркер без выбора не стартует.
- Описание PR, не помещающееся в долю контекста PR, обрезается до доли с пометкой, а не выпадает целиком.
- Сообщения коммитов подписываются номером по месту в PR: метка «самый новый» не переезжает на более старый коммит, когда новый не поместился.
- Без изменения требований:
  - `uv run pytest` по умолчанию не собирает живые тесты (`addopts = -m "not live"`), локальный прогон без пропусков;
  - `.github/workflows/llm-live.yml` срабатывает и на правки `app/infrastructure/prompts.py`, `app/worker/factory.py`, `app/domain/context_budget.py`, `uv.lock`;
  - `ollama.py`: сбой транспорта не цепляет исходное исключение `httpx` (`from None`), как в `openai_compatible.py`;
  - на PR длиннее 250 коммитов GitHub отдаёт первые 250, новые в пакет не попадают: записано в порте и адаптере.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `llm-gateway`: явный выбор заглушки в описаниях стека, обрезанный ответ, токены сбойных вызовов, таймаут подключения, проверка худшего случая вызова при старте.
- `context-assembly`: обрезка описания PR по доле.
- `review-prompt-assembly`: подпись сообщений коммитов по месту в PR.

## Impact

- Код: `app/infrastructure/llm/structured.py`, `ollama.py`, `openai_compatible.py`, `fallback.py`, `app/infrastructure/container.py`, `app/infrastructure/vcs/github.py`, `app/application/ports/vcs_gateway.py`, `app/application/context_assembly.py`, `app/domain/prompt.py`, `app/config.py`, `app/worker/factory.py`.
- Стек: `docker-compose.yml`, `.env.example`, `infra/variables.tf`, `infra/README.md`, `.github/workflows/deploy.yml`, `.github/workflows/llm-live.yml`, `.github/workflows/ci.yml`, `pyproject.toml`.
- Пакет контекста: у сообщения коммита поле `index`, у обрезанного описания - `truncated`; пакеты без них читаются как раньше.
- Схема базы данных и API не меняются.

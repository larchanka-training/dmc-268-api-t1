## Context

Расход вызова модели сейчас переносят четыре слоя. `complete_structured` складывает попытки и
прибавляет их к сбою, `FallbackLlmGateway` прибавляет расход сбойных провайдеров к ответу или
сбою и сдвигает счёт слушателя повтора, `LlmError.tokens_used` несёт число через исключение,
пайплайн держит «незаписанные токены» на случай сбоя. Число одно — `tokens_used`. Разбивка по
видам и деньги умножили бы эту проводку на пять.

## Goals / Non-Goals

**Goals:** одна точка учёта на каждый HTTP-ответ провайдера; разбивка токенов и стоимость на
прогоне; `tokens_used` прогона и шагов — те же числа, что раньше.

**Non-Goals:** метрики `gen_ai.*`, баланс `/credits`, связь с трейсом, бюджет в EUR (#119);
списания, квота, наценка (#286); новые колонки у шагов.

## Decisions

**D1. `LlmUsage` — значение домена.** Неизменяемый dataclass: `input_tokens`, `output_tokens`,
`cached_tokens`, `reasoning_tokens`, `total_tokens`, `cost_eur: Decimal`, сложение и нулевое
значение. `total_tokens` — отдельное поле, а не сумма видов: прежнее `tokens_used` бралось из
`usage.total_tokens` провайдера, и оно не обязано совпадать с суммой. Без него адаптер берёт
входные плюс выходные, у Ollama — `prompt_eval_count + eval_count`, как раньше. Кэшированные
входят во входные, reasoning — в выходные. Поле токенов без значения (нет, `null`) — 0; не целое
от 0 (строка, `true`, дробь) — «неожиданное тело», `LlmError`.

**D2. Стоимость — точный `Decimal`, 10 знаков.** Eurorouter отдаёт стоимость с 10 знаками
(`/generation` — `"0.0000913000"`, `/credits` — `"13.0960038381"`), а суммы прогонов должны сходиться
с балансом `/credits` и с SQL до знака. Поэтому ни float, ни целые микроевро (0,0000913 € — 91,3
мкЕвро, доля терялась бы на каждом вызове). Тело ответа разбирается `response.json(parse_float=Decimal)`:
число из JSON сразу точное, float не появляется. Других дробных полей адаптер из тела не читает.
Значение квантуется до 10 знаков банковским округлением (`ROUND_HALF_EVEN`). Колонка —
`NUMERIC(20, 10)`. Плохое значение стоимости (не число, `true`, NaN, отрицательное, ≥ 10¹⁰ €) —
предупреждение в лог и 0: ответ модели уже оплачен, отвергать его из-за поля учёта значит
заплатить второй раз.

**D3. Счётчик на запросе.** `LlmMeter` в модуле порта — изменяемый сумматор с полем `total`.
Запрос несёт его рядом с `on_retry`, в сравнении не участвует. Пишет только
`complete_structured`, сразу после ответа `send`: так повтор по схеме, ротация ключей (ключ без
ответа модели ничего не приносит) и фоллбэк (у каждого провайдера свой `complete_structured`)
учитываются без кода в этих местах. Ответ, который адаптер получил, но не принял (Ollama насчитала
больше окна), — `RawReply.rejected`: расход записывается, затем цикл бросает сбой. Исключения
расход больше не несут.

**D4. Один счётчик на прогон.** Пайплайн создаёт счётчик на прогон и отдаёт его обоим вызовам.
`StepRecorder` получает тот же счётчик: доля шага — разность итога с уже записанным, как раньше
с нарастающим итогом от адаптера. Шаг без вызова модели — `tokens_used = null`; это решает
пайплайн явным признаком, как сейчас. Прогон пишет `total` счётчика при записи замечаний, а при
сбое — `_mark_failed` ставит итог счётчика, если тот не нулевой: запись идемпотентна, двойного
счёта после уже записанных затрат нет. Отменённый прогон (`cancelled` после смены целевой ветки)
`update` не пишет — терминальная строка; итог счётчика ему дописывает отдельный метод порта
`ReviewRunRepo.record_cancelled_spend`, который меняет только расход и только у `cancelled`.

**D5. API.** `GET /reviews/{id}` — поле `usage` (объект или `null`), `cost_eur` — точная
десятичная строка без экспоненты и хвостовых нулей колонки (`"0.0000913"`, ноль — `"0"`). Строкой,
а не числом JSON: клиент прочёл бы число во float. Кэшированные и reasoning-токены хранятся для
внутренней аналитики (настройка промптов, отдача кэша, цена reasoning) и в API кабинета не
отдаются; наружу их может вывести метриками #119. Остальные поля прогона не меняются.

## Risks / Trade-offs

- [Открытый PR #316 опирается на `answer.tokens_used`, `exc.tokens_used` и `spent_tokens`] →
  после мерджа одного из двух второй переводит симуляцию на счётчик.
- [Провайдер без `usage.total_tokens`] → итог — сумма видов; без `usage` вовсе — «неожиданное
  тело», как раньше.

## Migration Plan

Ревизия `0018`: четыре nullable-колонки `BigInteger` и `cost_eur NUMERIC(20, 10)` на
`review_runs`, откат удаляет их. Старый код новые колонки не читает, поэтому expand без второго шага.

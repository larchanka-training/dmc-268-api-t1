## Why

Ревью PR #30 нашло два места, которые стоит поправить до мёржа:

- Проверка живости воркера в `deploy.yml` сравнивает два среза с интервалом
  10 секунд. Процесс, проживший дольше 10 секунд, Docker после падения
  поднимает сразу, без задержки, поэтому воркер с периодом падений 15–30
  секунд почти наверняка попадает хотя бы в одно «чистое» окно из шести и
  проходит проверку. Требование «не перезапускается» выполнено только для
  падений на старте.
- Окружение приложения описано в `infra/main.tf` трижды — у `migrate`, `api`
  и `worker`. После вливания `develop` копии уже разошлись: у API добавились
  реквизиты GitHub App. Именно такое расхождение двух описаний одного стека
  дважды ломало стенд.

## What Changes

- Воркер считается работающим, если он 30 секунд подряд запущен и ни разу не
  перезапустился; состояние опрашивается каждые 5 секунд, на проверку — до
  90 секунд. Рестарт сбрасывает окно, поэтому ранние падения, пока брокер не
  готов, деплой не роняют.
- Общее окружение контейнеров приложения выносится в `local.app_env`; API
  добавляет к нему реквизиты GitHub App. Значения не меняются, Terraform
  контейнеры не пересоздаёт.

## Impact

- `.github/workflows/deploy.yml` — шаг «Проверить, что воркер работает»;
  `infra/README.md` — описание проверки;
  деплой становится длиннее минимум на 20 секунд.
- `infra/main.tf` — `locals`, `env` трёх контейнеров.
- Код приложения, схема БД и внешний контракт не меняются.

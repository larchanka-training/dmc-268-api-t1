## Why

Финальное ревью PR #70 (контракт API из кода, ошибки по RFC 9457) нашло расхождения поведения со спекой и дыры в строгости ответов:

- `POST /api/v1/reviews` с битым JSON без `Origin` получал `422`, а не `403`: FastAPI разбирает тело раньше зависимостей, а `Origin` проверяла зависимость.
- Имя лишнего поля тела (ключ от клиента) возвращалось в `errors[].where`.
- `offset` больше bigint доходил до PostgreSQL и давал `500`.
- Время в ответах было в двух формах: `+00:00` у вебхука и `Z` у остальных; nullable-поля `ReviewJob` вебхук не отдавал вовсе.
- Тело ручного запуска принимало snake_case, приводило `"5"` к числу и не ограничивало длину.

## What Changes

- `Origin` изменяющих запросов под `/api/v1/` (кроме вебхуков) проверяет ASGI-middleware — раньше разбора тела, сессии и базы. Зависимость `require_origin` удалена.
- `errors[].where` у лишнего поля указывает на объект, без имени поля; причина — «лишнее поле». Русские причины для длины строки, границ и слишком больших чисел.
- `offset` ограничен максимумом bigint: больше — `422`.
- Время во всех ответах и в событиях SSE — тип `UtcDatetime`: UTC с `Z`, в схеме `format: date-time` с `pattern`.
- Вебхук отдаёт модели `ReviewJob` / `WebhookIgnored` / `WebhookAcknowledged`, все поля `ReviewJob` обязательны (`T | null`).
- Тело `CreateReviewRequest` — только camelCase, без приведения типов, с границами колонок.
- Типы ответов строже: `failedStage` — три этапа сбоя, `id` — UUID, `number` — положительное.
- Статусы HTTP в `app/api` — `HTTPStatus`; описания полей и операций в схеме.

## Capabilities

### Modified Capabilities

- `user-auth`: `Origin` проверяется раньше разбора тела, для всех изменяющих запросов под `/api/v1/` кроме вебхуков.
- `review-rest-api`: формат времени в ответах, `422` на `offset` вне bigint, строгое тело без эха имён полей.
- `webhook-intake`: тело `202` — модель из схемы со всеми полями.

## Impact

- `app/api/*`, `app/domain/run_events.py` (запись SSE переехала в `app/api/review_events.py`), `docs/openapi/openapi.json`.
- Фронтенд: изменились сгенерированные TS-типы (обязательные nullable-поля `ReviewJob`, `failedStage`, `pattern` у времени).

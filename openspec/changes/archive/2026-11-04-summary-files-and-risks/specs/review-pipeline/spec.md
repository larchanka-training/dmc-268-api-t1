## ADDED Requirements

### Requirement: Сводка ревью называет риски и проверенные файлы

Под сводкой модели итоговый комментарий SHALL содержать блок «Риски» — число замечаний прогона уровня `critical` и `high` по категориям, без таких замечаний блока нет. Ниже SHALL идти список файлов диффа под `<details>` по группам: проверены, частично, не проверены, отброшены фильтром; группы считает код по пакету контекста. Имя файла SHALL NOT менять разметку комментария; в группе — не больше 50 путей, путь — не длиннее 200 символов.

#### Scenario: Риски по категориям

- **WHEN** в прогоне два замечания `security` (`critical` и `high`) и одно `readability` уровня `low`
- **THEN** блок «Риски» называет только безопасность — по одному `critical` и `high`

#### Scenario: Lock-файл и файл сверх лимита

- **WHEN** в диффе `uv.lock` и файл, ни один hunk которого не вошёл в лимит контекста
- **THEN** под `<details>` `uv.lock` — в «отброшены фильтром», второй файл — в «не проверены»

#### Scenario: Имя файла с разметкой

- **WHEN** автор PR назвал файл с обратными кавычками, `</details>` или переводом строки
- **THEN** путь выводится в code span, перевод строки — видимой записью, и список не разрывается

#### Scenario: PR на тысячи файлов

- **WHEN** в группе больше 50 файлов
- **THEN** выведены первые 50 и строка «… и ещё N»

#### Scenario: Имена файлов из тысяч управляющих байт

- **WHEN** во всех группах по 50 файлов с именами в тысячи управляющих символов
- **THEN** каждый путь обрезан до 200 символов, и комментарий короче 65 536 символов — ревью публикуется

## MODIFIED Requirements

### Requirement: Один прогон на коммит, если не запрошено повторное ревью

Модель хранения SHALL не допускать, чтобы у запроса на изменение накапливалось больше одного нетерминального прогона ревью для одного и того же head-коммита. Прогон, достигший терминального состояния, SHALL NOT блокировать в хранилище последующий прогон для того же коммита, чтобы явно запрошенное повторное ревью и прогон после `failed` оставались возможными. Повторная доставка вебхука после завершённого не-`failed` прогона нового прогона не создаёт — это решает приём (спека `webhook-intake`).

#### Scenario: Второй активный прогон для того же коммита отклоняется

- **WHEN** создаётся прогон ревью для запроса на изменение и head-коммита, у которых уже есть прогон в нетерминальном состоянии
- **THEN** запись отклоняется, и существует только исходный прогон

#### Scenario: Повторное ревью после завершения разрешено

- **WHEN** в хранилище создаётся прогон ревью для head-коммита, предыдущий прогон для которого достиг терминального состояния, — явное повторное ревью или прогон после `failed`
- **THEN** новый прогон сохраняется, а предыдущий остаётся доступным для чтения; повторная доставка вебхука после `completed` до хранилища не доходит

#### Scenario: История сохраняется при повторных ревью

- **WHEN** запрос на изменение проверяется повторно после нового коммита
- **THEN** создаётся новая запись прогона ревью, а предыдущие прогони остаются доступными для чтения

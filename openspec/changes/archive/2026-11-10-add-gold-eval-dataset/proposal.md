# Proposal

## Why

Задача #32 (подзадача #57): золотой датасет и Eval Harness для качества AI-ревью. Сегодня в
репозитории есть только корпус eval правил владельца (`tests/eval/rules/`, 8 кейсов), и он
гоняется на живой модели вручную (`eval.yml`). Общего датасета по четырём категориям
`FindingCategory` с негативными и враждебными кейсами нет, а обязательный CI не проверяет ни
формат ответа модели на нём, ни Precision/Recall: регрессию метрик или сломанный раннер видно
только после платного прогона.

## What Changes

- **Золотой датасет** `tests/eval/dataset/` — 20–30 синтетических кейсов по
  `docs/testing/LLM_EVAL.md` §4: на кейс `mr.json`, `diff.patch`, `expected.json`, `notes.md` и
  зафиксированные ответы модели `responses/run-<n>.json`. Враждебные — в `dataset/adversarial/`.
  Негативные и враждебные вместе — не меньше четверти набора.
- **Раннер** `tests/eval/runner.py`: загрузка кейсов, проверка каждого ответа схемой
  `ReviewOutput`, сопоставление находок по правилу §2 (тот же файл и сторона, категория, окно
  ±3 строки, один к одному), Precision, Recall, F1, Valid-output rate, Duplicate rate, срез по
  категориям, injection-сьют; отчёт JSON и Markdown; ненулевой код выхода при ошибке схемы
  датасета или пороге ниже §6.
- **Шаг CI** — раннер на зафиксированных ответах без обращения к внешней модели, отчёт —
  артефактом.
- Поведение сервиса не меняется: код в `app/` не трогается.

## Impact

- `tests/eval/` (датасет, загрузчик, раннер, тесты), `.github/workflows/ci.yml`, `Makefile`,
  `docs/testing/LLM_EVAL.md`.
- Спека `backend-base-setup`: новое требование к CI.

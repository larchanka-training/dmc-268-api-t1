## Context

Вердикты верификатора живут только в памяти воркера: `apply_verdicts` отдаёт `JudgedFinding(finding, verdict)` по каждому оставленному замечанию, а в базу пишется лишь итог прогона и число отброшенных.
Контекст модели сохраняется пакетами контекста прогона (секреты заменены меткой), а `file_contexts(body)` уже читает пакет по файлам - им же пользуется результат симуляции.

## Decisions

### D1. Вердикт - столбцы замечания, а не отдельная таблица

`findings` получает `verifier_verdict` (enum `verifier_verdict`: `keep`, `drop`) и `verifier_reason` (text), оба пустые вместе: проверяет CHECK.
Вердикт - свойство одного замечания, связь один к одному; отдельная таблица добавила бы соединение без выгоды.
Оба столбца допускают `NULL` без значения по умолчанию, поэтому `ADD COLUMN` не перезаписывает таблицу, а миграция укладывается в `lock_timeout = 5s`.
Прежние замечания остаются без вердикта: восстановить его нечем.

### D2. Вердикт пишется там же, где замечание

Воркер строит `Finding` из `JudgedFinding` и пишет замечание с вердиктом одной записью; второй проход, не давший вердиктов (`not_required`, `unavailable`), оставляет оба столбца пустыми.
Домен: `Finding.verdict: Verdict | None` - тот же `Verdict`, что у замечания симуляции, второго типа не заводим.

### D3. Контекст файла выбирает чистая функция

`file_context_of(payloads, file_path)` в `app/domain/file_context.py`: из пакетов прогона по порядку частей берёт первый с телом и контекстом этого файла; `None`, если пакетов нет, тело стёрто или файла в пакете нет.
Адаптера не нужно: `uow.context_payloads.list_for_run` уже есть.
Ручка не вызывает GitHub: ответ не зависит от доступности провайдера, кроме проверки видимости прогона, которая у ручек прогона уже есть.

### D4. Схема ответа не меняется

`FindingInspectionResponse` уже описана заглушкой, фронтенд генерирует по ней типы; реализация только наполняет поля. `verdict` - `null` при `verification` не `verified` и у замечаний до этого change, `context` - `null`, если пакета нет или тело стёрто.

## Risks

- Прогоны до миграции остаются без вердиктов навсегда: ответ честно отдаёт `verdict = null`, как и описано в схеме.
- Тело пакета может быть записано старой версией сборщика контекста; чтение через `file_contexts` совпадает с тем, что делает результат симуляции для своих пакетов.

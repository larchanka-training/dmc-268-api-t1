# Proposal

## Why

После слияния `develop` в PR #111 (задача #107) общий поток `GET /api/v1/events` (#115) считает видимые репозитории при подключении той же зависимостью, что и `GET /api/v1/repositories/available`. Эта зависимость теперь ходит в GitHub токеном пользователя, поэтому подключение к потоку получило исходы токена: обмен refresh token, закрытие сессии с `401` и `502` при сбое обмена. В спеке эти исходы описаны только для ручек репозиториев.

## What Changes

- Требования о токене пользователя распространяются на подключение к `GET /api/v1/events`: истёкший токен обменивается до начала потока, непригодный — `401 UNAUTHENTICATED` с закрытием сессии и удалением cookie, сбой GitHub при обмене — `502 SCM_UNAVAILABLE`; во всех отказах поток не открывается.
- Проверка сессии в открытом потоке (каждые 5 секунд) токен не трогает и к GitHub не ходит.

## Capabilities

### Modified Capabilities

- `review-rest-api`: «Истёкший токен пользователя обновляется», «Непригодный токен пользователя закрывает сессию».

## Impact

`app/api/repositories.py` (зависимость `available_repositories`), `app/api/events.py` (описание), `app/api/errors.py` (`ERRORS_502_SCM_EVENTS`), `tests/test_events_api.py`, `docs/openapi/openapi.json`. Схема ответов не меняется: `401` и `502` у потока уже были.

# Design

Повторяет change `ci-build-summary` фронтенда (ui#85): одинаковые ключи и раскладка summary в
обоих стеках. Отличия — нет раздела бандла (в образе бэкенда нет JS) и язык скрипта.

## База для сравнения с develop

Метрики последней успешной сборки образа на develop — в кэше Actions. Успешный job `image` на
develop сохраняет `build-base/metrics.json` с ключом `build-metrics-<sha>`; любой прогон
восстанавливает самый свежий по `restore-keys: build-metrics-` (основной ключ
`build-metrics-restore` не сохраняется никогда, точного совпадения нет). Пул-реквест видит
кэш своей базовой ветки. Токену ничего не нужно: кэш ходит по `ACTIONS_RUNTIME_TOKEN`, `permissions`
остаётся `contents: read`. Ключ по sha: запись кэша неизменяема, а «последняя» выбирается по
времени создания. Сохранение — шаг с `success()`, то есть только после успеха job'а `image`:
красные тесты в другом job'е базу не останавливают.

Отвергнуто: артефакт прошлого прогона (`download-artifact` с `run-id` требует `actions: read` и
поиска прогона через API) и пересборка develop в том же job'е (удваивает время ради одного
числа).

Ограничение: кэш вытесняется через 7 дней без обращений и при превышении лимита репозитория.
Тогда summary пишет «Базы для сравнения нет» и показывает абсолютные значения — это не ошибка.
Summary — подсказка, а не бюджет: за рост образа CI не краснеет.

Предположение, проверенное во фронтенде, но не здесь: пул-реквест видит кэш develop. В этом
репозитории подтвердится на первом пул-реквесте после мерджа.

## Размер образа

Несжатый — `docker image inspect --format '{{.Size}}'`. Сжатый — байты `docker save | gzip`:
порядок размера слоёв при отдаче в реестр, но не точное значение (реестр жмёт каждый слой
отдельно).

## Сканеры

Gate остаётся прежним (hadolint с порогом по умолчанию, trivy HIGH и CRITICAL с
`ignore-unfixed`). Второй запуск каждого — `format: json` в файл и без падения (`no-fail: true`,
`exit-code: "0"`): так видно то, что gate пропускает. Шаги summary — с `!cancelled()`, чтобы
summary был и после красного gate.

## Скрипт

Python, только стандартная библиотека: скрипты бэкенда — на Python, их проверяют `ruff` и
`pytest`, а job `image` вызывает его системным `python3` без `uv sync`. `render` не падает на
отсутствующих файлах: нет или битый отчёт сканера — раздел со строкой «Отчёта нет: шаг сканера
упал»; нет базы — значения без разницы; нет метрик — одна строка о том, что они не собраны.
Списки находок не обрезаются: лимит summary в 1 МиБ заполнится лишь на тысячах находок.

## Имена

По семантическим соглашениям OpenTelemetry — `container.image.name`, `container.image.id`.
Своё — `dmc268.build.image.{size,size.compressed}`,
`dmc268.build.scan.{severity,vulnerabilities}`, `dmc268.build.lint.{level,findings}`.

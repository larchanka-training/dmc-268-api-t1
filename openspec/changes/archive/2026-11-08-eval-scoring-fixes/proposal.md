# Proposal

## Why

PR #74 (E2E правил, eval Precision/Recall, нагрузка) смёржен с открытыми тредами ревью. Часть
замечаний искажает главный вывод `docs/testing/RULES_E2E_REPORT.md` — Recall по правилам
0.38 → 0.95, — часть делает полный прогон `Load` нестабильным или вводящим в заблуждение (#166).

## What Changes

- Сопоставление замечаний с разметкой — максимальное паросочетание один к одному с
  лексикографическим весом (число пар, затем совпадение смысла, затем расстояние до строки)
  вместо жадного перебора: жадный занижал TP и одновременно завышал FP и FN.
- F1 считается как `2·TP / (2·TP + FP + FN)`: при TP = 0 он равен 0, а не выпадает из среднего.
  Ячейка отчёта показывает, у скольких повторов значение есть: «1.00 (2/3)».
- Нарушение проектного правила засчитывается, только если замечание сослалось на тот же пункт
  или его категория — среди допустимых для этого нарушения. Допустимые категории размечены в
  корпусе (`categories`). `docs/testing/LLM_EVAL.md` §2 обновлён.
- Сбой одного прогона eval не губит весь платный прогон: он пишется в отчёт как прогон, не
  дошедший до публикации, очереди очищаются, eval идёт дальше; тест падает после записи отчёта.
- Нагрузка: исходный прогон PR — самый ранний по `created_at`, а не созданный первой доставкой:
  повтор может уйти раньше неё. Воркеры нагрузочного сценария — отдельные процессы, поэтому
  латентность приёма не меряется под общим GIL.
- Отчёт `RULES_E2E_REPORT.md` §3–§4 приведён к новым правилам подсчёта.

**Не входит:** перенос корпуса eval из YAML в TOML — `pyyaml` всё равно нужен тестам workflow и
песочнице.

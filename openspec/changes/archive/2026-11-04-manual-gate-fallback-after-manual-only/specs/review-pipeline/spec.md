## MODIFIED Requirements

### Requirement: Прогон при паузе ревью не блокирует merge gate

Если при выставлении check run ревью репозитория на паузе (репозиторий выключен или `auto_review_enabled = false`), система SHALL ставить check run паузы вместо итога прогона, в том числе упавшего.
Исключение: пауза `auto_review_enabled = false` SHALL NOT перекрывать итог ручного прогона на head, который не упал и не отменён, а если последний прогон на head — упавший или отменённый ручной, — итог последнего завершённого ручного прогона на head; выключенный репозиторий перекрывает любой прогон.

#### Scenario: Прогон завершился после включения паузы

- **WHEN** прогон по вебхуку начался до паузы, у него есть незакрытый тред не ниже порога, и он завершается, когда у репозитория уже `auto_review_enabled = false`
- **THEN** ревью публикуется, на head ставится check run `success` «Авторевью выключено в настройках»

#### Scenario: Прогон упал после выключения репозитория

- **WHEN** на head уже было ревью, репозиторий выключен `DELETE /api/v1/repositories/{repository_id}`, и начатый до этого прогон падает
- **THEN** на head ставится check run `success` «Ревью выключено в сервисе», а не `failure`

#### Scenario: Первый прогон упал на паузе

- **WHEN** других прогонов на head нет, у репозитория уже `auto_review_enabled = false`, и начатый до этого прогон по вебхуку падает
- **THEN** на head ставится check run `success` «Авторевью выключено в настройках»: обязательная проверка не держит PR

#### Scenario: Ручной прогон при выключенном авторевью выставляет свой gate

- **WHEN** у репозитория `auto_review_enabled = false`, ручной прогон на head завершается с незакрытым тредом уровня `critical`, а порог — `critical`
- **THEN** на head ставится check run `failure` «Есть незакрытые замечания уровня critical и выше», а не check run паузы

#### Scenario: Закрытие треда после ручного прогона пересчитывает gate

- **WHEN** у репозитория `auto_review_enabled = false`, последний прогон на head — завершённый ручной, и человек закрывает его последний тред не ниже порога
- **THEN** на head ставится check run `success` «Ревью пройдено», а не «Авторевью выключено в настройках»

#### Scenario: Упавший ручной прогон на паузе не блокирует

- **WHEN** у репозитория `auto_review_enabled = false`, ручной прогон на head падает, и раньше на этом head не было завершённого ручного прогона
- **THEN** на head ставится check run `success` «Авторевью выключено в настройках», а не `failure`

#### Scenario: Упавший повторный ручной прогон на паузе возвращает gate прежнего

- **WHEN** у репозитория `auto_review_enabled = false`, ручной прогон на head завершился с незакрытым тредом уровня `critical` при пороге `critical`, а повторный ручной прогон на тот же head падает
- **THEN** на head остаётся check run `failure` «Есть незакрытые замечания уровня critical и выше» завершённого прогона, а не check run паузы; закрытие этого треда ставит `success` «Ревью пройдено»

#### Scenario: Выключенный репозиторий важнее ручного прогона

- **WHEN** ручной прогон на head начат до выключения репозитория `DELETE /api/v1/repositories/{repository_id}` и завершается с незакрытым тредом не ниже порога
- **THEN** на head ставится check run `success` «Ревью выключено в сервисе»

#### Scenario: Повторное событие PR на head ручного прогона не запускает авторевью

- **WHEN** у репозитория `auto_review_enabled = false`, последний прогон на head — ручной, и приходит событие PR на тот же head (переотправка `synchronize` или `edited`)
- **THEN** приём отвечает `202` `ignored`: прогона и задачи нет, check run на head не ставится

#### Scenario: Вебхуковый прогон после ручного на паузе

- **WHEN** у репозитория `auto_review_enabled = false`, на head есть завершённый ручной прогон, а после него вебхуковый прогон на том же head завершается с незакрытым тредом не ниже порога
- **THEN** на head ставится check run `success` «Авторевью выключено в настройках», а не gate ручного прогона

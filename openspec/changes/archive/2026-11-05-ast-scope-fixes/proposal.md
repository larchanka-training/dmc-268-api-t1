# Proposal

## Why

Проверка tree-sitter по документации 2026-11-04 нашла две ошибки AST-окружения (#348):

- метод класса тянет в пакет чужой тип с тем же именем: метод вложенного `class Local` — модульный
  `class Local`, метод TS `class Money` — `interface Money`. Поиск по имени нужен только для Go,
  где метод объявлен вне структуры;
- в JS/TS не распознаются функции в свойствах объектных литералов
  (`export const routes = { list: async () => {…} }`), перегрузки и `declare function`, хотя штатный
  `tags.scm` грамматик считает их определениями. Правка внутри такой функции даёт пустое
  AST-окружение.

## What Changes

- `select_scopes`: тип по имени родителя не ищется, если сам метод лежит внутри выбранного типа
  с этим именем. Для Go ничего не меняется: тип ресивера метод не охватывает.
- Адаптер tree-sitter: узел `pair` объектного литерала держит функцию, как поле класса или
  переменная, имя — из поля `key`; `function_signature` — функция без тела, у сигнатуры срезается
  хвостовой `;`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `context-assembly`: тип по имени родителя не дублирует выбранный по диапазону; функции объектных
  литералов и сигнатуры TS — определения.

## Impact

- `app/domain/code_context.py`, `app/infrastructure/parsing/tree_sitter_extractor.py` и их тесты.
- Пакет контекста на JS/TS станет чуть больше на правках внутри объектных литералов, а на методах
  одноимённых типов — меньше.
- Закрывает #348.

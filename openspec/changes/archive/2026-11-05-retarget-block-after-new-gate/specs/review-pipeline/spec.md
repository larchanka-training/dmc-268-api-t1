## MODIFIED Requirements

### Requirement: Отменённый прогон не выставляет merge gate

Прогон, отменённый (`cancelled`) сменой целевой ветки, SHALL NOT публиковать ни ревью, ни check run, а его сообщение SHALL NOT попадать в DLQ. Check run прогон SHALL собирать по последнему прогону на head: свой итог, если за head отвечает он, иначе итог того, кто отвечает; на паузе ревью — check run паузы. После выставления прогон SHALL перечитать состояние и, если итог изменился, поправить check run. Check run, который GitHub не принял, SHALL повторять до трёх раз.

#### Scenario: Ветку сменили во время публикации

- **WHEN** прогон дошёл до POST ревью, а в базе он уже `cancelled`
- **THEN** ни ревью, ни check run этим прогоном не публикуются, а шаг `publishing` закрывается как брошенный (`REVIEW_RUN_STALE`), а не `completed`

#### Scenario: Ветку сменили во время ревью

- **WHEN** прогон отменили, пока он работал, и его следующий переход отвергнут как переход из терминального состояния
- **THEN** воркер пишет в лог info, закрывает открытый шаг и прочие незакрытые шаги как брошенные (`REVIEW_RUN_STALE`) и подтверждает сообщение, в DLQ оно не уходит

#### Scenario: Ветку сменили между проверкой статуса и check run

- **WHEN** прогон выставил `success`, а приём к этому моменту уже закоммитил отмену и новый прогон
- **THEN** прогон выставляет блокировку смены ветки, а если новый прогон уже `completed` или записал своё ревью, то его итог

#### Scenario: Блокировка дошла после gate нового прогона

- **WHEN** прогон отправил блокировку смены ветки, пока новый прогон был `publishing`, а новый тем временем записал ревью, и его gate дошёл до GitHub раньше блокировки
- **THEN** перечитав состояние, прогон выставляет итог нового прогона, а не оставляет блокировку

#### Scenario: Ревью нового диффа уже упало

- **WHEN** прогон выставил `success`, а новый прогон после смены ветки уже `failed`
- **THEN** поправка — `failure` «Ревью не удалось», а не «идёт повторное ревью»

#### Scenario: GitHub не принял поправку

- **WHEN** прогон выставил `success`, увидел, что за head отвечает новый прогон, а POST поправки GitHub отверг
- **THEN** поправка отправляется снова, до трёх попыток, и каждый раз собирается по прогону, который отвечает за head в момент попытки

## Context

Статус прогона пишет воркер, API и воркер разделяют только базу. NOTIFY из транзакции записи — следующий шаг задачи #103; пока источник — опрос, как у потока одного прогона.

## Decisions

### D1. Курсор `(updated_at, id)` и окно перепроверки

`updated_at` ставится раньше коммита: время транзакции в базе (`now()` у UPDATE) или часы процесса (вставка прогона). Запись, закоммиченная позже соседней, может прийти с меньшим `updated_at`, чем уже увиденный курсор, и строгий курсор её потерял бы навсегда: прогон остался бы в старом статусе до переподключения. Поэтому опрос читает две части одним запросом: до `limit` строк новее курсора и до `limit` строк окна `RECHECK` (5 секунд) под курсором; уже отправленные версии отсеиваются по `recent`. У каждой части свой `LIMIT`: полное окно уже виденных строк не останавливает курсор.

### D2. История не отдаётся

Первый опрос идёт до ответа и учитывает строки окна под моментом подключения как виденные, без событий: их последние версии клиент получит снимком REST после `open`. Всё, что закоммичено после первого опроса, придёт событием.

### D3. Тип события

Итоговый статус — всегда `run.finished`, даже у прогона, впервые увиденного уже завершённым: контракт обещает при переходе в итоговый статус только `run.finished`. `run.created` — у прогона с `created_at` позже подключения при первом его событии в соединении. Остальное — `run.status_changed`, в том числе новая версия без смены статуса (прогресс): клиент делает upsert по id.

### D4. Видимость — тот же расчёт, что у `/repositories/available`

Список доступных пользователю репозиториев — FastAPI-зависимость `available_repositories`, общая для `GET /repositories/available` и потока: правило одно, при его смене (вход токеном пользователя, PR #111) поток следует сам. Поток сопоставляет список с зарегистрированными репозиториями по провайдеру и id у провайдера одним запросом.

### D5. Трасса

Опрос раз в секунду через `UntracedUnitOfWork` (подавление инструментирования OTel на время единицы работы): трейс запроса не растёт на спан в секунду. На `http.disconnect` Starlette отменяет генератор и оставляет ответ незавершённым — телеметрия FastAPI отмечает такой запрос ERROR. Поток после отмены закрывает ответ пустым телом: уход клиента — штатный конец, исключение генератора остаётся сбоем.

## Risks

- Окно перепроверки покрывает запись, закоммиченную не позже чем через 5 секунд после своего `updated_at`. Длиннее транзакций записи прогона в коде нет.
- Нагрузка: один запрос в секунду и одна проверка сессии в 5 секунд на соединение; запрос идёт по индексу `(updated_at, id)`.

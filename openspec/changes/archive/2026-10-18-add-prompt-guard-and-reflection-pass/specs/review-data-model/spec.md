# Spec Delta

## ADDED Requirements

### Requirement: Замечание хранит ссылку на правило владельца

Замечание, выпущенное по пользовательскому правилу, SHALL хранить ссылку на него: имя правила, номер пункта и текст пункта на момент прогона.
Ссылка SHALL быть либо заполнена целиком, либо пуста целиком; номер пункта SHALL быть не меньше единицы.
Ограничение SHALL обеспечиваться базой данных, а не только кодом записи.

#### Scenario: Замечание по правилу сохраняет ссылку

- **WHEN** сохраняется замечание по пункту 2 правила `Error Handling Standards`
- **THEN** запись замечания содержит имя правила, номер 2 и текст пункта

#### Scenario: Частичная ссылка отклоняется базой

- **WHEN** в базу пишется замечание с именем правила, но без номера пункта
- **THEN** запись отклоняется ограничением базы данных

#### Scenario: Замечание по стандартным критериям

- **WHEN** сохраняется замечание без ссылки на правило
- **THEN** все поля ссылки пусты

### Requirement: Прогон хранит итог верификации замечаний

Прогон SHALL хранить итог второго прохода модели - одно из значений `verified`, `not_required` или `unavailable` - и число замечаний, отброшенных верификатором.
До завершения анализа итог SHALL быть пуст, а число - равно нулю; у прогонов, созданных до появления верификации, итог пуст.

#### Scenario: Завершённый прогон с верификацией

- **WHEN** прогон завершился, а верификатор отбросил два замечания
- **THEN** итог верификации прогона - `verified`, число отброшенных верификатором - 2

#### Scenario: Прогон, упавший до анализа

- **WHEN** прогон перешёл в `failed` на этапе сборки контекста
- **THEN** итог верификации пуст, число отброшенных верификатором равно нулю

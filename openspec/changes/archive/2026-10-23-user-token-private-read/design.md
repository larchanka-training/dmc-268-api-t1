# Design: роль read на приватном репозитории

## Context

Change `user-token-explicit-access` (D2) приравнял роль read к «не виден», потому что по одному `pull` чужой публичный репозиторий не отличить от репозитория, где у пользователя роль read. Признак `private` из ответа GitHub это различает: приватный `GET /repositories/{id}` отдаёт только тому, у кого на нём есть роль.

## Decisions

### D1. Приватный — виден, публичный — только с явным правом

`visible_for_connect` (чистая функция домена): `private` или `has_explicit_access`. Приватный с ролью read проходит дальше: установка, затем права — `403 REPOSITORY_MANAGE_REQUIRED`. Пользователь — участник репозитория, установку приложения на нём он может увидеть и в самом GitHub, оракула для постороннего нет.

Публичный с одним `pull` — как раньше: `404` до запроса установки (D1 change `user-token-explicit-access`).

### D2. `private` по умолчанию `false`

Поле `InstallationRepository.private` имеет значение по умолчанию `false`: если источник его не задал, срабатывает прежнее, более закрытое поведение (`404`). Адаптер GitHub заполняет его всегда — поле `private` обязательно в ответе «Get a repository».

## MODIFIED Requirements

### Requirement: Лимит размера диффа в воркере

Воркер SHALL получать дифф с лимитом размера `DIFF_MAX_BYTES` (по умолчанию 5 МиБ): тело ответа читается потоком и SHALL NOT дочитываться дальше лимита. Дифф прогона больше лимита SHALL переводить прогон в `failed` с причиной «дифф больше лимита», а шаг `fetching_diff` — в `failed` с кодом `DIFF_TOO_LARGE`; модель SHALL NOT вызываться, частичное ревью SHALL NOT публиковаться, повторная доставка задачи SHALL NOT перезапускать прогон.

#### Scenario: Дифф больше лимита — прогон failed без ревью

- **WHEN** воркер получает дифф прогона больше `DIFF_MAX_BYTES`
- **THEN** прогон — `failed` с причиной «дифф больше лимита», шаг `fetching_diff` — `failed` с кодом `DIFF_TOO_LARGE`, модель не вызывается и на PR ничего не публикуется

#### Scenario: Тело диффа не дочитывается дальше лимита

- **WHEN** VCS отдаёт дифф больше лимита — с объявленной длиной или потоком без неё
- **THEN** загрузка обрывается не позже лимита, остаток тела не читается

#### Scenario: GitHub отказался строить дифф

- **WHEN** GitHub отвечает `422` на сравнение коммитов прогона (дифф слишком велик для GitHub)
- **THEN** прогон — `failed` с причиной «дифф больше лимита», шаг `fetching_diff` — `failed` с кодом `DIFF_TOO_LARGE`, модель не вызывается и на PR ничего не публикуется

# Proposal

## Why

Интерфейс развёрнут и проксирует `/api/` на бэкенд по внутренней сети сервера. Значит публичный порт API стал второй дверью в те же ручки: `62.169.24.237/api/health` и `62.169.24.237:8000/health` отвечают одно и то же, но второй путь минует интерфейс.

Лишний открытый порт не нужен ни для чего: интерфейс обращается к API внутри docker-сети, а не через публикацию на хосте. Проверка живости из деплоя ходит через SSH-туннель к петле сервера и от публикации наружу тоже не зависит.

При этом требование спеки `backend-delivery` сформулировано как «наружу доступен только HTTP-порт API» — оно описывает состояние до появления интерфейса и после закрытия порта станет прямо неверным. Менять конфигурацию, оставив требование, значит получить спеку, противоречащую стенду.

## What Changes

- API перестаёт публиковаться за пределы сервера: порт остаётся на петле, чтобы туннельная проверка и отладка работали.
- Требование спеки переформулируется: наружу смотрит ровно один вход, и это интерфейс.
- Шаг деплоя, проверявший публичную доступность API, удаляется: проверять доступность того, что намеренно не публикуется, бессмысленно. Публичный путь `/api/` проверяет деплой интерфейса — он это уже делает.

**Не входит:** пути документации `/docs` и `/openapi.json`. Они останутся доступны через `/api/`, и это отдельное отложенное решение — закрывать их надо в приложении одним переключателем, а не запретами на входах.

## Capabilities

### Modified Capabilities

- `backend-delivery`: требование о доступности API снаружи меняется — он доступен через `/api/` на публичном входе интерфейса, а не через собственный порт.

## Impact

- `.github/workflows/deploy.yml`: `bind_ip` для API становится петлёй, удаляется шаг проверки публичной доступности.
- Спека `backend-delivery`.
- Снаружи перестаёт отвечать `62.169.24.237:8000`. Путь `62.169.24.237/api/...` продолжает работать: интерфейс ходит к API по внутренней сети.
- **Следствие для QA:** дёргать API напрямую, минуя интерфейс, снаружи больше нельзя — только через `/api/`. Внутри сервера и через туннель доступ сохраняется.

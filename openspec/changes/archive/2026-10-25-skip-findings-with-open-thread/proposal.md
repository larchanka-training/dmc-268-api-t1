## Why

`publish_review` публикует все находки прогона, не сверяясь с тредами бота. Каждый push повторяет те же замечания новыми inline-комментариями рядом со старыми тредами, а замечание, тред которого закрыл человек, возвращается на следующем прогоне. Задача #148; решение команды — #169, пункт 3а: замечание, тред которого закрыл человек, повторно не публикуем; критичное, ставшее серьёзнее, публикуется в любом случае.

## What Changes

- Перед публикацией находки сверяются с тредами бота на этом PR по пути, стороне, категории и текущей строке треда на GitHub. Строку и закрытие отдаёт тот же GraphQL-запрос `reviewThreads`, которым уже шла сверка тредов (добавлены поля `isOutdated` и `line`), — один запрос с пагинацией на прогон. Устаревший тред (`line: null`) ни с чем не совпадает.
- Открытый тред совпал и серьёзность находки не выше серьёзности его замечания — inline не публикуется, находка ссылается на находку треда (`findings.covered_by_finding_id`). Серьёзность выросла — находка публикуется.
- Тред, закрытый не ботом, считается закрытым человеком: находка повторно не публикуется, кроме `critical` при замечании треда ниже `critical`. Тред, который бот закрыл сам, ничего не покрывает: проблема вернулась и публикуется снова. Своё закрытие бот отмечает в `published_comments.thread_resolved_by_bot`.
- Одна проблема — один комментарий: в тред, вместо которого опубликован новый inline, ответ модели не уходит; тред, который покрывает находку этого прогона, бот в этом прогоне не закрывает, даже если модель ответила «исправлено», — merge gate продолжает блокировать по открытому критичному треду.
- Сверка тредов перенесена до публикации и больше не повторяется после неё: свои закрытия бот записывает сам, gate считается по базе. При сбое сверки находки публикуются без сверки (лучше повтор, чем потерянное замечание), gate — по базе.
- `GET /api/v1/reviews/{id}`: у находки поле `covered_by_finding_id`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `review-pipeline`: ADDED «Повторный прогон не дублирует открытый тред», «Тред, закрытый человеком, не повторяется», «Одна проблема — один комментарий»; MODIFIED «Диалог в тредах на повторном прогоне» (исключения для ответов и закрытия) и «Merge gate по критичным открытым тредам» (сверка до публикации, одним запросом; сценарий сбоя GraphQL — на повторном прогоне).
- `review-data-model`: ADDED «Находка ссылается на тред, который её уже покрывает»; MODIFIED «Опубликованные комментарии отслеживаются» (`thread_resolved_by_bot`).

## Why

Стек свежее, чем память моделей, на которых работают агенты команды: Python 3.14, OpenTofu 1.13, PostgreSQL 18, RabbitMQ 4.4, Pydantic 2.14. Агент пишет API библиотеки по памяти, и ошибка всплывает только на ревью или на стенде: `OTEL_EXPORTER_OTLP_TIMEOUT` Python SDK читает в секундах, а не в миллисекундах; `TestClient` поверх `httpx` уже помечен устаревшим. Сверка с документацией нужной версии ловит такое до коммита.

Документации тоже мало: она описывает задуманное поведение, а не поведение нашей связки версий. На аудите 2026-10-24 запуск опроверг три вывода, сделанных по документации и чтению кода: вынос миграций из графа OpenTofu сам по себе не убирает простой API, RabbitMQ в контейнере не видит лимит памяти cgroup, ранний отказ `RequestBodyLimitMiddleware` уходит `text/plain`.

## What Changes

- В `.agents/rules/backend.md` — раздел «Документация библиотек и проверка на практике»: API библиотек и платформ сверять с документацией версии из `uv.lock` и `infra/.terraform.lock.hcl` (context7, если подключён, иначе официальная документация); решение, которое держится на поведении брокера, базы, провайдера или фреймворка, проверять запуском до кода; непроверенное предположение называть таким в задаче и пул-реквесте. Код проекта в запросы к внешнему сервису не вставлять.
- В `README.md`, раздел «Правила разработки и агенты», — как подключить context7 у себя. Подключение личное, как и остальные инструменты: конфиг MCP в репозиторий не коммитится.

## Impact

- `README.md`, `.agents/rules/backend.md`. Код, контракт API и поведение сервиса не меняются.

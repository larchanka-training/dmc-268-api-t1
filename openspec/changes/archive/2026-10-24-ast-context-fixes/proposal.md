## Why

Извлечение определений в трёх местах даёт модели неверный AST-контекст (задача #153):

- у метода TypeScript декораторы лежат соседями в теле класса, у `@Component(…) export class` — в `export_statement`, поэтому правка декоратора не попадает в диапазон определения и метод или класс выпадают из контекста;
- `select_scopes` добавляет тип по имени `parent` для любого определения, хотя у вложенной функции или класса `parent` — охватывающее определение, а не тип: при слиянии объявлений TS (`interface Money` и `function Money`) правка внутренней функции тянет чужой интерфейс;
- заголовок типа Go режется по первой `{`, и ограничение `[T interface{ ~int }]` обрывает параметры типа: `type Set[T interface`.

Правка входит раньше задач 5.x change'а `add-tree-sitter-index`: индекс определений переиспользует тот же адаптер.

## What Changes

- Первая строка определения — первый декоратор: дети узла, соседи в `decorated_definition`, теле класса и `export_statement`; комментарии между декораторами не прерывают их. Сигнатура — без декораторов (как в Python).
- Тип по имени родителя добавляется только для метода.
- Заголовок типа Go — до узла типа, с параметрами типа целиком. Сигнатура generic-функции Go параметры типа уже содержала — закреплено тестом.

- `context-assembly`: ADDED «Декораторы и параметры типа входят в определение» и «Тип по имени родителя — только для метода».

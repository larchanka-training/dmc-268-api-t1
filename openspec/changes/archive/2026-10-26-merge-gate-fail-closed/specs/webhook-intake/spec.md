## ADDED Requirements

### Requirement: Смена целевой ветки блокирует merge gate до нового ревью

При смене целевой ветки, когда на head-коммит уже есть прогон с другой базой, приём SHALL до записи нового прогона выставить на head-коммит check run merge gate с `conclusion=failure`: прежний `success` описывает чужой дифф. Сбой GitHub на этом шаге SHALL давать HTTP 502 без записей и задачи.

#### Scenario: Окно между сменой ветки и новым ревью закрыто

- **WHEN** на head-коммите check run `success` по старой базе, и приходит `edited` со сменой целевой ветки
- **THEN** до постановки нового прогона на head-коммит выставлен check run `failure`; если новое ревью упадёт, он остаётся

#### Scenario: GitHub недоступен на блокировке

- **WHEN** выставить блокирующий check run не удалось
- **THEN** ответ — HTTP 502, прогон не создаётся, задача не ставится

## MODIFIED Requirements

### Requirement: Повторная доставка отвечает существующим прогоном

Вебхук для запроса на изменение и head-коммита, у которых уже есть прогон в нетерминальном состоянии или завершённый не-`failed` прогон с источником `webhook` на ту же базу (из свежих метаданных PR), SHALL NOT создавать новый прогон и ставить задачу. Ответ SHALL быть HTTP 202 с проекцией найденного прогона. Прогон `failed` дублем не делает. Дубль SHALL NOT переписывать записи: он проверяется до обновления merge_request.

#### Scenario: Повторная доставка безвредна

- **WHEN** приходит вебхук для head-коммита, у которого уже есть прогон в нетерминальном состоянии на ту же базу
- **THEN** второй активный прогон не создаётся, и ответ — не 5xx

#### Scenario: Повторная доставка отвечает 202 с проекцией существующего прогона

- **WHEN** приходит вебхук для head-коммита, у которого уже есть активный прогон на ту же базу
- **THEN** ответ — HTTP 202 с проекцией `ReviewJob` существующего прогона, новых записей нет и очередь не трогается

#### Scenario: Повтор после завершения прогона — один прогон и одно ревью

- **WHEN** приходит вебхук для head-коммита, прогон по вебхуку для которого на ту же базу уже завершился в `completed`, в том числе с тем же `X-GitHub-Delivery`
- **THEN** ответ — HTTP 202 с проекцией завершённого прогона, новый прогон не создаётся, задача не ставится, и второе ревью не публикуется

#### Scenario: Прогон без записанной базы

- **WHEN** приходит `opened` или `synchronize` для head-коммита, завершённый прогон которого не хранит базу
- **THEN** он считается прогоном на любую базу: ответ — дубль, новый прогон не создаётся

#### Scenario: Смена целевой ветки и прогон без базы

- **WHEN** приходит `edited` со сменой целевой ветки для head-коммита, завершённый прогон которого не хранит базу
- **THEN** дублем он не считается: создаётся новый прогон — база заведомо менялась

#### Scenario: Повтор после failed создаёт новый прогон

- **WHEN** приходит вебхук для head-коммита, единственный прогон которого завершился в `failed`
- **THEN** создаётся новый прогон в `queued` и задача ставится в очередь

#### Scenario: Новый коммит после активного прогона запускает новый прогон

- **WHEN** приходит вебхук с новым head-коммитом для запроса на изменение, у которого есть активный прогон на предыдущем коммите
- **THEN** создаётся новый прогон ревью для нового коммита, а предыдущий прогон по-прежнему указывает свой коммит

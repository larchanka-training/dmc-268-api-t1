# Proposal: review-pipeline приведён к webhook-intake после мерджа #36

## Why

Ветки #37 (приём) и #36 (обработка) независимо описали один шаг — приём
вебхука. После вливания обеих в `develop` в дереве спек остались два
противоречия между `review-pipeline` и `webhook-intake` (треды ревью #37):

- `review-pipeline` требует «зарегистрировать репозиторий» по вебхуку
  (создав при первом упоминании), а `webhook-intake` прямо запрещает
  регистрацию на лету: «регистрацию выполняет отдельная операция с
  авторизацией». Ручки регистрации в системе ещё нет — если бы требование
  `review-pipeline` выполнялось, вебхуки незарегистрированных репозиториев
  всё равно уходили бы в `ignored`, а сама формулировка блокирует
  консервативное поведение, согласованное в `webhook-intake`.
- Сценарий `review-pipeline` «Закрытие запроса на изменение отражается в
  хранилище» требует по вебхуку `closed` обновлять состояние запроса, а
  `webhook-intake` относит `closed` к игнорируемым: записей не создаётся,
  очередь не трогается. Приём (#37) реализован по `webhook-intake`: запускают
  ревью только `opened` и `synchronize`, пользователь переназначает бота
  ревьюером сам.

Код противоречий не содержит — противоречат друг другу две спеки. Change
снимает требования из `review-pipeline`, делая её согласованной с
`webhook-intake`.

## What Changes

- Требование «Приём вебхука создаёт прогон и ставит задачу в очередь»
  больше не требует регистрировать репозиторий по вебхуку: репозиторий к
  моменту вебхука уже существует, регистрация — отдельная операция с
  авторизацией (будущая ручка, тикет следует).
- Сценарий «Закрытие запроса на изменение отражается в хранилище» удалён:
  `closed` и `merged` остаются игнорируемыми по `webhook-intake`.
- README получает раздел о ручной регистрации репозитория до появления
  ручки.

Схема базы данных, REST-контракт (`openapi.yaml`) и код не меняются.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `review-pipeline`: требование «Приём вебхука создаёт прогон и ставит
  задачу в очередь» — без регистрации репозитория по вебхуку и без сценария
  об обновлении состояния при закрытии запроса.

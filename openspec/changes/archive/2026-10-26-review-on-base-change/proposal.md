## Why

Security-аудит #222 нашёл обход merge gate. Автор PR открывает его в свою ветку, где бэкдор уже лежит: в диффе только безобидная правка, бот ставит check run `success` на `head_sha`. Потом автор меняет целевую ветку на `develop`. GitHub шлёт `pull_request` `edited` с `changes.base`, приём его игнорировал, а check run на том же `head_sha` оставался `success`: обязательная проверка пройдена без ревью нового диффа.

Три круга ревью #225 нашли в исправлении гонки и ложные срабатывания: блокировку перекрывал `success` старого прогона, смена ветки определялась по сдвигу вершины, пересчёт по треду ставил `success` непроверенному head, отменённый прогон публиковал ревью и уходил в DLQ, упавшее ревью нового диффа оставляло старый `success`.

## What Changes

- `edited`, у которого ветка в свежих метаданных отличается от записанной у PR, запускает ревью. `edited` без смены ветки по-прежнему игнорируется.
- Приём отменяет активный прогон на старой ветке, коммитит новый прогон, ставит на head `failure` «идёт повторное ревью» и только потом ставит задачу. Отказ GitHub — 502, новый прогон в `failed`, у PR прежняя ветка, повтор доставки (#149) снова блокирует.
- Дубль — только если последний прогон на коммит не `failed` и не `cancelled`.
- Кто бы ни ставил gate (публикация, пересчёт по треду), он собирает check по последнему прогону на head, после POST перечитывает его и поправляет, если тот сменился; отказ GitHub повторяется до трёх раз.
- Пересчёт по закрытию треда — только если последний прогон на head `completed`.
- Отменённый прогон не публикует ни ревью, ни gate, его сообщение подтверждается, открытый шаг закрывается как брошенный.
- Упавший прогон, последний на head, ставит `failure`, если до него этот head уже ревьюили.

## Capabilities

### Modified Capabilities

- `webhook-intake`: ADDED «Смена целевой ветки запускает ревью», «Смена целевой ветки блокирует merge gate до нового ревью», «Повторная доставка на проверенный коммит отвечает существующим прогоном»; MODIFIED «Прочие действия pull request игнорируются», «Упавшие доставки повторяются»; REMOVED «Повторная доставка отвечает существующим прогоном».
- `review-pipeline`: ADDED «Пересчёт merge gate только по завершённому ревью head», «Отменённый прогон не выставляет merge gate», «Упавший прогон после ревью head блокирует merge gate».

## ADDED Requirements

### Requirement: Пересчёт merge gate только по завершённому ревью head

Пересчёт merge gate по вебхуку закрытия треда SHALL выставлять check run, только если последний прогон на head-коммите PR - `completed`. Если прогона на head нет, или последний идёт, упал или отменён, check run по тредам SHALL NOT выставляться: `success` непроверенному коммиту не даётся, gate выставит прогон, который его проверит. Если после этого последний прогон на head сменился, пересчёт SHALL поправить check run, как прогон.

#### Scenario: Тред закрыт, пока ревью нового head идёт

- **WHEN** после push ревью нового head-коммита ещё идёт, и приходит вебхук закрытия треда
- **THEN** check run на новый head не выставляется

#### Scenario: Ревью после смены целевой ветки упало

- **WHEN** последний прогон на head - `failed` (ревью нового диффа), а прежний `completed` был на старой базе, и закрыт тред
- **THEN** check run не выставляется: блокировка смены ветки остаётся

#### Scenario: Ветку сменили во время пересчёта

- **WHEN** пересчёт выставил check run по `completed` прогону, а приём к этому моменту закоммитил смену ветки и новый прогон
- **THEN** пересчёт выставляет блокировку смены ветки, а если новый прогон уже `completed`, то его итог

### Requirement: Отменённый прогон не выставляет merge gate

Прогон, отменённый (`cancelled`) сменой целевой ветки, SHALL NOT публиковать ни ревью, ни check run, а его сообщение SHALL NOT попадать в DLQ. Check run прогон SHALL собирать по последнему прогону на head: свой итог, если за head отвечает он, иначе итог того, кто отвечает. После выставления прогон SHALL перечитать последний прогон и, если тот сменился, поправить check run. Check run, который GitHub не принял, SHALL повторять до трёх раз.

#### Scenario: Ветку сменили во время публикации

- **WHEN** прогон дошёл до POST ревью, а в базе он уже `cancelled`
- **THEN** ни ревью, ни check run этим прогоном не публикуются, а шаг `publishing` закрывается как брошенный (`REVIEW_RUN_STALE`), а не `completed`

#### Scenario: Ветку сменили во время ревью

- **WHEN** прогон отменили, пока он работал, и его следующий переход отвергнут как переход из терминального состояния
- **THEN** воркер пишет в лог info, закрывает открытый шаг и прочие незакрытые шаги как брошенные (`REVIEW_RUN_STALE`) и подтверждает сообщение, в DLQ оно не уходит

#### Scenario: Ветку сменили между проверкой статуса и check run

- **WHEN** прогон выставил `success`, а приём к этому моменту уже закоммитил отмену и новый прогон
- **THEN** прогон выставляет блокировку смены ветки, а если новый прогон уже `completed`, то его итог

#### Scenario: Ревью нового диффа уже упало

- **WHEN** прогон выставил `success`, а новый прогон после смены ветки уже `failed`
- **THEN** поправка — `failure` «Ревью не удалось», а не «идёт повторное ревью»

#### Scenario: GitHub не принял поправку

- **WHEN** прогон выставил `success`, увидел, что за head отвечает новый прогон, а POST поправки GitHub отверг
- **THEN** поправка отправляется снова, до трёх попыток, и каждый раз собирается по прогону, который отвечает за head в момент попытки

### Requirement: Упавший прогон после ревью head блокирует merge gate

Прогон, упавший последним на своём head-коммите, SHALL выставить check run `failure`, если до него на этот head-коммит уже был прогон `completed` или `cancelled` по вебхуку: прежний прогон мог оставить `success` по старому диффу. Без прежнего прогона на head упавший прогон SHALL NOT выставлять check run. Сбой GitHub SHALL попадать в лог и SHALL NOT подменять ошибку прогона.

#### Scenario: Ревью после смены ветки упало, поправка не дошла

- **WHEN** на head `success` прежнего прогона по старой ветке, а прогон нового диффа упал
- **THEN** на head выставляется `failure` «Ревью не удалось»

#### Scenario: Первое ревью коммита упало

- **WHEN** прогон упал, а других прогонов на этот head-коммит нет
- **THEN** check run не выставляется, на PR ничего не появляется

#### Scenario: За head отвечает более поздний прогон

- **WHEN** прогон упал, а на этот head-коммит уже создан более поздний прогон
- **THEN** упавший прогон check run не выставляет

## Context

С #382 тело пакета контекста (`context_payloads.body`) через `CONTEXT_PAYLOAD_RETENTION_DAYS`
стирается: `body` → NULL, `body_expired_at` — время стирания; строка и метаданные остаются. У
прогона может быть несколько пакетов. Ручка диффа берёт дифф не из пакета, а у GitHub по паре
`base_sha...head_sha`, с кэшем в памяти API на час.

## Goals / Non-Goals

**Goals:** API говорит, что дифф прогона удалён по сроку хранения, и когда; после срока ручка
диффа его не отдаёт; «удалён» отличим от «изменений нет».

**Non-Goals:** новые колонки и миграции; срок хранения других данных; расширения в теле
Problem Details.

## Decisions

### D1. «Дифф удалён» — все тела пакетов прогона стёрты; решает чистая функция

`diff_expired_at` = `max(body_expired_at)` по пакетам прогона, если пакеты есть и `body` у всех
NULL; иначе `null`. Частично стёртый прогон считается живым: срок хранения у пакетов одного
прогона почти совпадает, и до стирания последнего пакета дифф ещё законно показывать. Берётся
максимум — момент, когда стёрт последний пакет.

Правило живёт не в адаптере. Адаптер одним запросом, не читая тела (до 128 КБ каждое), отдаёт
агрегат `BodyExpiryStats`: число пакетов, число стёртых тел и `max(body_expired_at)` —
метод `ContextPayloadRepo.body_expiry_stats_for_run` в существующем порте, новый порт не нужен.
Решение принимает чистая функция `diff_expired_at(stats) -> datetime | None` в `app/domain`
(`app/domain/payload_retention.py`, рядом с сущностью-агрегатом): данные на входе, данные на
выходе, без I/O. Фейк репозитория считает только агрегат, поэтому правило проверяется
юнит-тестами функции, а не дублируется в фейке.

### D2. Отказ — в use case `load_run_diff`, ручка переводит его в `410 DIFF_EXPIRED`

`load_run_diff` (`app/application/use_cases/run_diff.py`) получает `diff_expired_at` аргументом,
и первая его проверка — раньше `base_sha`, кэша и запросов установки и диффа к GitHub —
бросает `RunDiffExpired`. Ручка ловит его, как остальные отказы use case, и отвечает
`410 DIFF_EXPIRED`. Так порядок «от дешёвого к дорогому» остаётся в одном месте, и тест
«ни кэша, ни `fetch_diff`» пишется на уровне use case без HTTP. Удалённый по сроку хранения код
не возвращается ни из кэша, ни от провайдера. Раньше `base_sha`: прогон без `base_sha` со
стёртыми телами — это «удалён», а не «пары коммитов нет»; интерфейсу важнее первое.

`410 Gone` — тот же статус, что у `COMMIT_NOT_FOUND`: ресурс был и больше не будет доступен;
коды различают причину.

Альтернатива: `200` с `files: []` и флагом. Отклонена: пустой список уже значит «изменений нет»,
интерфейс не смог бы их различить без второго поля.

### D3. Время — в поле прогона, `ApiError` не расширяется

Машиночитаемое время удаления отдаёт `diff_expired_at` прогона; в `410` оно только в `detail`.
Расширять `ApiError` и модель ошибки полем ради одного кода — абстракция без второго вызова.
Интерфейс и так грузит прогон до диффа.

## Risks / Trade-offs

- **Предположение: прогон без пакетов — `null`.** Прогон, упавший до сборки контекста, пакетов
  не имеет: стирать было нечего, и дифф по-прежнему отдаётся из GitHub, даже если прогон старше
  срока хранения. Так правило остаётся одним — «стёрто то, что хранили», — без второго правила
  по возрасту прогона. Предположение не проверено с владельцем продукта; оно записано и в
  описании пул-реквеста.
- Лишний SQL-запрос в `GET /reviews/{id}` и `/diff`: агрегат по индексу `review_run_id` без
  чтения тел, цена мала.

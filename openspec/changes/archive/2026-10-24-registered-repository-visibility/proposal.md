## Why

#127 закрыл прогоны: `GET /reviews/{review_run_id}`, `/steps` и `/diff` отдают прогон только тому, кто видит его репозиторий на GitHub. Рядом остались ручки, которые проверяли только сессию. `GET /repositories` отдавал любому вошедшему все зарегистрированные репозитории, в том числе `full_name` приватных. `GET /repositories/{id}` отдавал любой репозиторий по id, а `GET /repositories/{id}/pull-requests` — заголовки, описания, авторов и ветки его PR. Угадывать id не нужно: он есть в списке. Задача #129.

## What Changes

- `GET /repositories` — только репозитории, которые пользователь видит на GitHub, по тому же правилу, что список прогонов, поток и прогон. Порядок и пагинация прежние.
- `GET /repositories/{id}` и `/repositories/{id}/pull-requests` — невидимый репозиторий отвечает тем же `404 REPOSITORY_NOT_FOUND`, что несуществующий.
- Репозиторий не с GitHub не виден никому.
- GitHub спрашиваем при любом id, до чтения базы: сбой GitHub — `502 SCM_UNAVAILABLE`, отозванный токен — `401` и закрытая сессия, одинаково для существующего и несуществующего id. При `422` параметров запроса к GitHub нет.
- Правило видимости — одна функция `is_visible` в `app/api/repositories.py`, её же использует прогон.

## Capabilities

### Modified Capabilities

- `review-rest-api`: ручки зарегистрированных репозиториев проверяют видимость.

## Impact

- Код: `app/api/repositories.py`, `app/api/pull_requests.py`, `app/api/reviews.py` (общее правило), `app/api/errors.py` (`ERRORS_502_SCM_REVIEWS` → `ERRORS_502_SCM_VISIBILITY`).
- Контракт: у трёх ручек в ответах `502 ScmUnavailableProblem`, в описаниях — видимость. Схемы ответов не меняются.
- Фронтенд: вкладка «Репозитории» показывает только видимые; экран настроек репозитория (ui#29) на чужой id получит `404`.
- Нагрузка: каждый запрос трёх ручек — обход установок пользователя у GitHub; кэш — #126.

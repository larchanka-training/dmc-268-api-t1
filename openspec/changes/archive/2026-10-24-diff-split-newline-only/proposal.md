## Why

`parse_diff` и `parse_rules_markdown` делят текст на строки через `str.splitlines()`, а она режет не только по `\n`, но и по `\x0b`, `\x0c`, `\x1c`–`\x1e`, `\x85`, ` `, ` ` и одиночному `\r`. Git и GitHub делят строки только по `\n`. Такой символ внутри строки кода превращает её хвост в отдельную строку: хвост `diff --git …` даёт фальшивый файл, `@@ … @@` — фальшивый hunk, номера строк после него уезжают. Комментарии встают не на те строки, а GitHub отвечает 422 на весь `POST /reviews`. В `.review/rules.md` так же подкладывается заголовок правила или поле `pattern:`. Задача #142.

## What Changes

- `parse_diff` и `parse_rules_markdown` делят текст только по `\n`; один `\r` в конце строки отбрасывается, как и раньше отбрасывала `splitlines()`, поэтому CRLF разбирается по-прежнему.
- Остальные разделители `splitlines()` остаются частью строки.

## Capabilities

### Modified Capabilities

- `webhook-intake`: строки диффа делятся только по `\n`, посторонний разделитель внутри строки не сдвигает номера и не создаёт заголовок файла или hunk'а.
- `repo-rules`: строки `rules.md` делятся только по `\n`, посторонний разделитель внутри строки не создаёт раздел или поле правила.

## Impact

- Код: `app/domain/diff_parser.py`, `app/domain/repo_rules.py`.
- Контракт API, схема базы и формат очереди не меняются.

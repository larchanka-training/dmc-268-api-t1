# Proposal: постановка в очередь отказывает за секунды, когда брокер блокирует издателей

## Why

При алярме памяти или диска RabbitMQ блокирует издателей: перестаёт читать сокет
соединения, которое публикует. `RabbitMQJobQueue.enqueue` в этом случае ждёт
подтверждения публикации без таймаута и держит общий lock адаптера. Следующие
вебхуки встают за lock'ом, потоки threadpool, общего со всеми sync-ручками,
кончаются — встаёт весь API (#143). Проверено на `rabbitmq:4.4-alpine`: три
параллельных `enqueue` под алярмом висят больше 20 с без ошибки. Одного
`blocked_connection_timeout` мало: повтор после обрыва ловит и
`ConnectionBlockedTimeout` (наследник `AMQPConnectionError`), каждый вызов ждёт
два таймаута, а вызовы идут по очереди через lock — 8, 16, 24 с при таймауте 4 с,
больше 10-секундного лимита доставки GitHub.

## What Changes

- Соединение издателя открывается с `blocked_connection_timeout`: заблокированное
  брокером дольше таймаута соединение pika рвёт и отдаёт `ConnectionBlockedTimeout`.
- `ConnectionBlockedTimeout` не повторяется: публикация сразу отказывает ошибкой
  «брокер блокирует издателей», соединение сбрасывается, следующий `enqueue`
  открывает новое.
- Lock адаптера берётся с таймаутом: не дождались — отказ той же ошибкой, без
  обращения к соединению.
- Повтор после настоящего обрыва соединения или канала остаётся прежним.
- Отказ уходит в существующую компенсацию приёма: прогон → `failed`, вебхук
  отвечает 5xx. GitHub упавшую доставку сам не повторяет: до #149 ревью этого
  коммита теряется, но API не встаёт.

Порт `JobQueue` не меняется. Схема базы и HTTP-контракт не меняются.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `job-queue`: новое требование «Постановка в очередь не ждёт заблокированного
  брокера».

## Impact

- `app/infrastructure/queue/rabbitmq.py` (`RabbitMQJobQueue`).
- Тесты: `tests/queue/test_channel_liveness.py` (lock без брокера),
  `tests/queue/test_broker_blocked.py` (живой алярм брокера).
- CI (`.github/workflows/ci.yml`): тесту нужен идентификатор контейнера
  RabbitMQ — `TEST_RABBITMQ_CONTAINER`, чтобы включать алярм через `rabbitmqctl`.

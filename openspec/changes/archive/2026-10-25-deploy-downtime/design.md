## Context

Стенд — OpenTofu 1.13.2 с провайдером `kreuzwerker/docker` 4.6.0, демон Docker на сервере через `ssh://stand`. Выкат: `apply -target` базы и брокера → `migrate.sh` (`docker pull` образа и `alembic upgrade head`) → полный `apply`, который заменяет `api` и `worker`.

## Goals / Non-Goals

**Goals:** простой API при выкате меньше 10 с (DoD #159); контейнеры приложения не пересоздаются, если образ тот же.

**Non-Goals:** выкат без простоя (второй экземпляр API за балансировщиком); digest образов PostgreSQL и RabbitMQ (#150, #102).

## Decisions

- **Контейнер ссылается на образ строкой, без `docker_image`.** Провайдер (`resourceDockerContainerCreate` → `findImage`) сначала ищет образ локально (`ImageInspect` по ссылке) и тянет его, только если не нашёл. При чтении он пишет в состояние `Config.Image` контейнера — строку, с которой контейнер создан, — если значение в конфигурации не начинается с `sha256:`. Поэтому сравнивается строка, и вечного diff нет: проверено на Docker 29.9.2 с классическим хранилищем образов (как на сервере) и с containerd — повторный `plan` даёт `No changes`.
- **Ссылка без тега.** С тегом строка менялась бы на каждом коммите, и `image` с `ForceNew` пересоздавал бы контейнеры при том же digest. Тег срезается регуляркой в `local.api_image_ref`; двоеточие порта реестра тегом не считается (тег — после последнего `/`, грамматика `[\w][\w.-]{0,127}`).
- **`removed` с `destroy = false`.** У ресурсов образа был `keep_locally = true`, уничтожение и так не снимало образ; `removed` убирает их из состояния без вызова провайдера. Старые образы убирает шаг чистки деплоя.
- **Без `registry_auth`.** Образ API тянет `migrate.sh` через docker CLI раннера; образы PostgreSQL и RabbitMQ публичные. Учётные данные у провайдера понадобились бы, только если образа API на сервере нет к моменту apply — в деплое такого не бывает, а при ручном запуске README требует `docker pull`. `GITHUB_TOKEN` больше не попадает в окружение `tofu`.
- **ControlMaster, туннели — мимо него.** Через master `ssh -f -N -L` отдаёт проброс самому master: на занятом порте ssh возвращает 0 (`ExitOnForwardFailure` относится к master), а проброс живёт, пока жив master, — ControlPersist закрывает его через 10 минут без сессий, и туннель к хранилищу состояния пропал бы посреди долгого apply. Поэтому туннели — `-o ControlPath=none`, своим соединением; проверено: на занятом порте код 255, как раньше. Сессии сверх `MaxSessions` сервера ssh открывает своим соединением («Session open refused by peer» → прямое подключение), вызов не падает; на полном apply одновременно было до 6 сессий.
- **`start_interval = "1s"`.** Провайдер опрашивает состояние контейнера раз в секунду; проверка раз в 2 с добавляла до 2 с к ожиданию `healthy`. Правка healthcheck пересоздаёт API (`replace_triggered_by`) — один раз, на том же первом деплое, где пересоздание и так идёт.

## Замеры

Отдельный демон `docker:29-dind` (Docker 29.9.2, overlay2), sshd в нём, клиент — Ubuntu 24.04 (OpenSSH 9.6) с задержкой 80 мс на ssh, реестр — отдельный контейнер с задержкой 50 мс. Тестовое приложение стартует ~2,2 с, воркер дренирует 15 с. Последовательность шагов — как в `deploy.yml`.

| | до (develop) | после |
| --- | --- | --- |
| 10 × `docker -H ssh://stand version` | 12,4–12,6 с | 3,9 с (4,6 с с подъёмом master) |
| `kill` старого API → `start` нового (события Docker) | 2,45 / 1,59 с | 1,25 / 1,31 / 1,24 / 1,08 с |
| простой по опросу `/health` раз в 0,2 с | 4,8 / 3,8 с | 3,3 / 3,5 / 3,3 с (4,4 — медленный старт приложения) |
| `api: Destroying` → `api: Creation complete` в логе apply | 6,3 / 8,8 с | 5,2–5,8 с |

Без ControlMaster, но без `docker_image`: `kill` → `start` 1,73 с. Переход со старого состояния: `2 to add, 1 to change, 2 to destroy, 2 to forget`, простой 3,4 с, затем `No changes`; новый тег при том же digest — `No changes`, ID контейнеров прежние.

## Risks / Trade-offs

- В лаборатории реестр рядом, и pull образа, который уже на сервере, стоит 0,35–1,4 с; от ghcr в деплое #202 — 6 с. Итоговый простой на стенде подтверждается деплоем после мёржа (DoD #203).
- `docker ps` показывает репозиторий без тега: commit sha выката — в summary деплоя.
- Первый деплой после мёржа пересоздаёт `api` и `worker` даже при том же digest.

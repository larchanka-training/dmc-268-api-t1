## MODIFIED Requirements

### Requirement: Текущий пользователь

`GET /api/v1/auth/me` SHALL возвращать профиль пользователя текущей сессии: id пользователя сервиса, провайдер, логин, имя, аватар и признак `is_demo`. Для пользователя с действительной сессией `is_demo` SHALL быть `false`. Без действительной сессии ответ SHALL быть `401`; в демо-режиме (`demo-mode`) — `200` с профилем демо-пользователя и `is_demo = true`.

#### Scenario: Вошедший пользователь

- **WHEN** запрос с действительной cookie сессии
- **THEN** ответ — `200` с логином и аватаром пользователя и `is_demo = false`

#### Scenario: Id для оплаты

- **WHEN** вошедший пользователь открывает кабинет
- **THEN** ответ `GET /api/v1/auth/me` содержит `id` — тот же, что ссылка оплаты Stripe (Payment Link) передаёт в параметре `client_reference_id`

#### Scenario: Без входа в демо-режиме

- **WHEN** демо-режим включён и запрос пришёл без cookie
- **THEN** ответ — `200` с профилем демо-пользователя и `is_demo = true`

### Requirement: Ответ без сессии удаляет cookie

Ручка, требующая сессию, SHALL отвечать `401` с `code = UNAUTHENTICATED` в теле Problem Details, если действительной сессии нет. Исключение — читающий запрос (`GET`) в демо-режиме (`demo-mode`): он обслуживается как запрос демо-пользователя. Если запрос пришёл с cookie `session`, которая недействительна, ответ SHALL её удалять, в том числе в демо-режиме.

#### Scenario: Недействительная cookie

- **WHEN** запрос пришёл с cookie `session`, которой нет в базе
- **THEN** ответ — `401` с `UNAUTHENTICATED` и `Set-Cookie`, удаляющим `session`

#### Scenario: Недействительная cookie в демо-режиме

- **WHEN** демо-режим включён и `GET`-запрос пришёл с cookie `session`, которой нет в базе
- **THEN** ответ — `200` с демо-данными и `Set-Cookie`, удаляющим `session`

### Requirement: Выход

`POST /api/v1/auth/logout` SHALL быть идемпотентным: он SHALL удалять сессию текущей cookie вместе с токеном провайдера, если она существует, SHALL после ответа пытаться отозвать токен у провайдера, SHALL всегда удалять cookie в ответе и SHALL отвечать `204`, в том числе без cookie и с cookie неизвестной сессии. После выхода запрос с этой cookie SHALL получать `401` из любой вкладки, кроме `GET` в демо-режиме (`demo-mode`).

#### Scenario: Выход в одной вкладке

- **WHEN** пользователь вышел в одной вкладке, а в другой открыт кабинет
- **THEN** следующий запрос из другой вкладки получает `401`

#### Scenario: Выход в демо-режиме

- **WHEN** демо-режим включён, и пользователь вышел
- **THEN** `GET /api/v1/auth/me` с той же cookie получает `200` с `is_demo = true` и `Set-Cookie`, удаляющим `session`
- **AND** изменяющий запрос с той же cookie получает `401 UNAUTHENTICATED`

#### Scenario: Выход удаляет токен провайдера

- **WHEN** пользователь вышел
- **THEN** токена его сессии в базе нет

#### Scenario: Отзыв токена у провайдера

- **WHEN** пользователь вышел, и у сессии был токен GitHub
- **THEN** после ответа токен отзывается у GitHub; сбой отзыва не меняет ответ `204` и не пишет токен в лог

#### Scenario: Выход без сессии

- **WHEN** `POST /api/v1/auth/logout` пришёл с верным `Origin` без cookie сессии или с cookie, которой нет в базе
- **THEN** ответ — `204`, cookie `session` удаляется

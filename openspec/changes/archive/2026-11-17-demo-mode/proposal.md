## Why

#386 (Sprint 5, DevOps): внешний разработчик поднимает проект с чистого клона командой `docker compose up`, но реквизитов GitHub App у него нет. Все ручки данных кабинета (`/reviews`, `/repositories`, аналитика, поток событий) требуют сессию GitHub OAuth и отвечают `401`, поэтому кабинет остаётся пустым и показать продукт без настройки App нельзя. В задаче отдельно просили скрипт начальных данных (seed).

## What Changes

- Настройка `DEMO_MODE` (по умолчанию выключена). В `.env.example` для compose она включена, на стенде выключена всегда.
- Скрипт начальных данных `python -m app.worker.seed_demo`: идемпотентно пишет демо-данные — демо-пользователя, два репозитория, запросы на изменение и прогоны в разных статусах с шагами и находками. В compose это одноразовый сервис `seed` после `migrate`.
- В демо-режиме читающий запрос (`GET`) без действительной сессии обслуживается как запрос демо-пользователя. Видимые репозитории берутся из базы (демо-репозитории), GitHub не вызывается.
- Запрос с действительной сессией ведёт себя как сейчас: видимость репозиториев идёт через GitHub, демо-данные такому пользователю не видны.
- Изменяющий запрос без сессии по-прежнему получает `401`: демо — только чтение.
- `GET /api/v1/auth/me` получает поле `is_demo` — по нему кабинет показывает плашку «Демо-данные» и кнопку входа. Схема ответа меняется аддитивно.

## Capabilities

### New Capabilities
- `demo-mode`: демо-режим без входа — включение, демо-данные, правило видимости, только чтение.

### Modified Capabilities
- `user-auth`: «Текущий пользователь» — поле `is_demo` и ответ без сессии в демо-режиме; «Ответ без сессии удаляет cookie» — исключение для читающих запросов в демо-режиме.
- `backend-delivery`: стенд не запускается в демо-режиме.

## Impact

- Код: `app/config.py` (`demo_mode`), `app/domain/demo.py`, `app/application/demo.py`, `app/api/session.py` (запасной демо-вход в `current_session`), use case `list_user_repositories` (ветка демо), `app/api/repositories.py` (правила и `install_url` демо), `app/api/events.py`, `app/api/auth.py` (`is_demo`), новые `app/application/use_cases/seed_demo.py` и `app/worker/seed_demo.py`.
- Контракт API: поле `is_demo` в ответе `/auth/me`, перегенерация `docs/openapi/openapi.json`.
- `docker-compose.yml` (сервис `seed`), `.env.example`, `README.md`, job `compose-smoke` в CI.
- Деплой: `deploy.yml` отклоняет `DEMO_MODE=true`.
- Фронтенд (отдельная подзадача в `dmc-268-ui-t1`): плашка демо-режима по `is_demo`, кнопки изменений скрыты.

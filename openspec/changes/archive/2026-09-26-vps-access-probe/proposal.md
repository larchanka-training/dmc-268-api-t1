# Proposal

## Why

CD из GitHub Actions упирается в два неизвестных, которые нельзя выяснить чтением репозитория. Первое: чем аутентифицируется `VPS_DMC268_P` — паролем или приватным ключом. Второе: проходит ли SSH с эфемерного раннера до `VPS_DMC268_IP_T1` и виден ли там Docker.

Значения секретов GitHub обратно не отдаёт никому, поэтому узнать это можно только изнутри прогона. Ответ определяет форму всего деплоя: docker-провайдер для `ssh://` вызывает системный `ssh`, а тот пароль из переменной окружения не принимает. Если `_P` окажется паролем, деплою понадобится отдельный bootstrap-шаг, который один раз положит на сервер ключ CI, — и этот шаг придётся спроектировать до того, как писать сам деплой, а не после.

Проверка вынесена отдельным шагом, потому что она не зависит ни от одной из открытых развилок спринта (хранилище Terraform state, разведение окружений develop/main на единственном сервере) и может пройти раньше них.

## What Changes

- Добавляется диагностический workflow, запускаемый вручную и по изменению самого себя.
- Workflow определяет форму значения `VPS_DMC268_P` (приватный ключ против пароля) по префиксу `-----BEGIN`, не печатая значение.
- Workflow выполняет **ровно одну** попытку SSH-подключения выбранным способом и сообщает, удалась ли она.
- При удачном подключении проверяется, что на сервере доступен Docker и пользователь имеет право с ним работать.
- Результат пишется в summary прогона в виде трёх фактов: тип секрета, доступность SSH, доступность Docker.
- Ничего не деплоит, не меняет состояние сервера, не трогает `app/`, `infra/` и существующий `ci.yml`.

Workflow временный: после того как ответ получен и зафиксирован в [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22), он удаляется вместе с задачей, которая его породила.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

Изменение помечено `skip_specs: true`. Это одноразовая диагностика инфраструктуры: она не добавляет и не меняет ни одного наблюдаемого требования к сервису. Требования к деплою появятся в следующем изменении — том, которое будет опираться на полученный здесь ответ.

## Impact

- Новый файл в `.github/workflows/`. Существующий `ci.yml` не затрагивается.
- Новых секретов не требуется: `VPS_DMC268_U`, `VPS_DMC268_P` и переменная `VPS_DMC268_IP_T1` уже заведены на уровне организации и доступны этому репозиторию.
- Разблокирует: выбор схемы аутентификации в CD, а значит и задачу [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22).
- Риск: неудачная попытка входа по паролю — это то, за что fail2ban банит адрес, а адреса раннеров общие. Отсюда ограничение в одну попытку за прогон.

# Design: явное право на репозиторий при подключении

## Context

Change `user-token-listing-edges` (D3) перевёл подключение на два прямых запроса: `GET /repositories/{id}` токеном пользователя, затем установка приложения. Первый запрос GitHub выполняет для любого публичного репозитория, даже если у пользователя нет на нём роли: `permissions` тогда — только `pull: true`.

## Decisions

### D1. Только `pull` — не виден

Явное право — хотя бы одно из push, triage, maintain, admin (`has_explicit_access`, чистая функция домена). Без него репозиторий для подключения не виден: тот же `404 REPOSITORY_NOT_IN_INSTALLATION`, что у отсутствующего, установка не запрашивается — ответ не зависит от того, стоит ли там приложение. Так подключение совпадает со списком: `/user/installations…` отдаёт только репозитории с явным доступом.

Решение в use case над данными порта, адаптер только переводит `push` и `triage` из ответа. `pull` в домен не переносится: решение его не читает.

### D2. Роль read без записи — `404`, а не `403`

По одному `pull` чужой публичный репозиторий не отличить от репозитория, где у пользователя роль read. Такой репозиторий есть в списке (GitHub отдаёт его по явному доступу), а подключение отвечает `404` вместо прежнего `403`. Подключить его нельзя в обоих случаях, разница только в коде отказа; признак `private` ради этого не вводится.

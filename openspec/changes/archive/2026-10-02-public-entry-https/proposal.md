# Proposal

## Why

Публичный вход стенда — `nginx` интерфейса (`dmc-268-ui-t1`) — поменялся в двух местах, а спека `backend-delivery` и `infra/README.md` описывают его прежним:

- `nginx` больше не срезает префикс `/api`: по контракту API (#25) префикс `/api/v1` ставит само приложение, и запрос доходит до него с исходным путём. `infra/README.md` по-прежнему утверждает обратное и требует монтировать роутеры без `/api` — ровно то, что дало бы 404 на каждой ручке.
- `/health` через публичный вход больше не публикуется: это проверка живости для Docker и деплоя бэкенда, она ходит мимо `nginx`. Сценарий спеки «`GET /api/health` отвечает по внешнему адресу» стал неверным.
- Стенд отдаётся по HTTPS с сертификатом Let's Encrypt на IP, HTTP перенаправляется на HTTPS.

## What Changes

- Требование «Наружу доступен только API» уточняется: запрос под `/api/` доходит до API с исходным путём; внешний вход — HTTPS; проверка живости `/health` снаружи не публикуется, доступность API снаружи подтверждается запросом под `/api/v1/`.
- `infra/README.md` описывает адресацию без срезания префикса и адрес стенда `https://`.

## Capabilities

### Modified Capabilities

- `backend-delivery`: требование о внешнем доступе к API.

## Impact

- `openspec/specs/backend-delivery/spec.md` — после синхронизации.
- `infra/README.md`. Код и конфигурация бэкенда не меняются: роутеры уже смонтированы на `/api/v1` (#36, #37), `/health` — в корне.

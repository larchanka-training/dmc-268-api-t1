## Why

Заказчик сказал прямо, что код читать не будет: его интересует продукт, безопасность и
архитектура. Значит, качество кода держится не на ревью человеком, а на правилах, по которым
пишут агенты, и на автоматических проверках. Сейчас в репозитории лежат только шесть скиллов
OpenSpec — правил разработки под наш стек нет, и каждый участник команды объясняет агенту
заново, чем ставить зависимости, чем гонять тесты и где проходит граница слоёв.

Вторая половина — сам продукт. Системные промпты ревью-агента до сих пор нигде не
зафиксированы, хотя разобран реальный прогон похожего сервиса и известно, из чего складывается
его поведение: порядок анализа, фильтрация бесполезных замечаний, формат пользовательских
правил, атрибуция сработавшего правила и формат вывода. Без этого контракта каждая будущая
реализация LLM-шлюза придумает промпт заново.

Задача команды: #11 «AI dev tools» (роль 7 «Инженер 4 (DevTools / Agentic Engineer)») на доске
https://github.com/orgs/larchanka-training/projects/7 (`dmc-268-t1`), разбита на две подзадачи
по стекам. Это изменение закрывает бэкендовую — #10; фронтовая, larchanka-training/dmc-268-ui-t1#7,
едет отдельным пул-реквестом в своём репозитории.

Требования к промптам ревью опираются на разбор реального прогона ревью-агента, показанный
заказчиком: оттуда взяты порядок анализа, формат пользовательских правил, мета-инструкции,
промежуточный артефакт с конвенциями репозитория и форма комментария.

## What Changes

- Набор скиллов в `.agents/skills/` под бэкендовый стек: цикл разработки через тесты,
  ревью диффа в этом репозитории, оформление пул-реквеста, рецепт миграции Alembic.
  Скиллы видны всем агентам через существующий симлинк `.claude/skills`.
- Правила разработки в `.agents/rules/`: бэкендовый стек с реальными командами
  (`uv sync --all-extras`, `uv run ruff check .`, `uv run lint-imports`, `uv run pytest`,
  `uv run alembic …`) и общие правила Git — именование веток `fix/…`, `feat/…`,
  `deps-update-YYYY-MM-DD`, требования к заголовку и описанию пул-реквеста.
- Шаблоны кода и тестов в `.agents/templates/`: чистая функция с юнит-тестом без базы,
  адаптер с интеграционным тестом, эндпоинт, миграция.
- Системные промпты AI-ревью в `prompts/review/` — ядро задачи и единственная часть,
  описывающая поведение продукта: главный системный промпт, промежуточный шаг «выписать
  конвенции репозитория», формат пользовательских правил со стартовым набором и шаблоны
  комментария и сводки.
- Фиксация раскладки каталогов: `.agents/` как источник, симлинки под конкретные инструменты.
  Вариант `docs/agents/` из пака заказчика отклоняется — в репозитории уже живёт `.agents/`.
- `AGENTS.md` этой задачей не создаётся и не переписывается. Строки, которые предлагается
  внести в него роли 1, перечислены в `design.md` и уходят ей отдельным уведомлением.

## Capabilities

### New Capabilities
- `ai-review-prompting`: контракт промптинга ревью-агента — порядок анализа, отсев замечаний
  про линтинг и форматирование, формат пользовательских правил и атрибуция сработавшего
  правила, чтение `AGENTS.md` проверяемого репозитория, промежуточный артефакт с конвенциями
  проекта, формат комментария и сводки, требование краткости и осторожности в утверждениях.

### Modified Capabilities

Нет. Правила, скиллы и шаблоны — инструментарий разработки, а не поведение сервиса, и
требований не меняют.

## Impact

- Новые каталоги: `.agents/rules/`, `.agents/templates/`, `prompts/review/`; пополняется
  `.agents/skills/`.
- Кода приложения (`app/`), миграций, зависимостей и CI изменение не трогает. Промпты лежат
  как данные: вызывающего кода у них пока нет, LLM-шлюз ещё не реализован.
- Потребитель — вся команда и будущая реализация оркестратора. Фронтовая половина тикета
  едет отдельным пул-реквестом в ui-репозиторий и переиспользует правила Git и формат
  промптов без изменений.

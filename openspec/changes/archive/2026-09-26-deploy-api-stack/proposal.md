# Proposal

## Why

Предусловия сняты: на сервере стоит Docker, вход по ключу работает, состояние Terraform живёт в S3-хранилище и переживает прогон раннера. Осталось то, ради чего всё это делалось, — чтобы мерж в `develop` сам выкатывал бэкенд.

Сейчас `infra/` собирает образ локально из исходников (`docker_image "api"` с тегом по хешу файлов). Это работает у того, кто запускает `tofu apply` руками на машине с кодом, и не работает из CI против удалённого демона: сборка пошла бы на сервере, без контекста и без кеша.

Отдельно в `infra/main.tf` лежит дефект, который выстрелит на первом же автодеплое: `docker_container.api` не переопределяет команду образа, то есть стартует как `uvicorn ...`. В `docker-compose.yml` та же роль запускается как `alembic upgrade head && uvicorn ...`. Пока стенд никто не поднимал, расхождение ничего не стоило; автодеплой поднимет API против непромигрированной базы.

## What Changes

- Образ API собирается в CI и публикуется в `ghcr.io/larchanka-training/dmc-268-api` с тегом по commit sha.
- `infra/` переходит с локальной сборки на pull готового тега; тег приходит переменной.
- Аутентификация в ghcr — через `registry_auth` docker-провайдера с `GITHUB_TOKEN`, поэтому пакет может остаться приватным и на сервере не нужно хранить долгоживущий токен.
- Миграции применяются **до** старта API: отдельным одноразовым контейнером в Terraform, от которого API зависит.
- Пароли PostgreSQL и RabbitMQ перестают быть плейсхолдерами: заводятся секретами и приходят через `TF_VAR_*`.
- API публикуется на внешний интерфейс (`bind_ip = 0.0.0.0`), иначе стенд недоступен снаружи и DoD не закрывается.
- Деплой-workflow на мерж в `develop`: сборка и публикация образа → job хранилища состояния → туннель → `tofu apply` по ключу CI → smoke-проверка `/health`.

**Не входит:** воркер — его кода ещё нет; выбор Redis против RabbitMQ — решение команды, в `infra/` остаётся RabbitMQ; TLS и домен — у нас только IP, а DoD принимает «доменное имя **или** IP».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`, как у `2026-09-26-vps-bootstrap` и `tfstate-s3-backend`. Меняется способ доставки сервиса, а не его наблюдаемое поведение: те же эндпоинты, та же схема БД, тот же образ.

## Impact

- `infra/main.tf`: `docker_image "api"` из собираемого становится получаемым; добавляется контейнер миграций; у `docker_container.api` появляется зависимость от него.
- `infra/variables.tf`: новая переменная под тег образа.
- Новый деплой-workflow; `tfstate-backend.yml` становится его первым job'ом вместо самостоятельного.
- Новые секреты под пароли PostgreSQL и RabbitMQ.
- **Стенд становится доступен из интернета по HTTP без TLS.** Осознанное следствие: без этого нечего показывать, а сертификат на голый IP не выпустить.
- Закрывает основную часть [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22): после этого изменения мерж в `develop` выкатывает бэкенд сам.

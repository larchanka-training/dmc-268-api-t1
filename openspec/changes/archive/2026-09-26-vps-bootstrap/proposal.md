# Proposal

## Why

Диагностика из `vps-access-probe` ([run 36195999589](https://github.com/larchanka-training/dmc-268-api-t1/actions/runs/36195999589)) дала два факта, каждый из которых блокирует CD.

`VPS_DMC268_P` — пароль. Docker-провайдер для `docker_host = "ssh://..."` вызывает системный `ssh`, а тот пароль из переменной окружения не принимает. Пока на сервере нет ключа, которым может пользоваться CI, деплой из Actions невозможен в принципе.

На сервере не установлен Docker (`bash: line 1: docker: command not found`). Весь `infra/` построен на docker-провайдере, и `infra/README.md` требует Docker Engine на целевом хосте — требование записано, но никем не выполнено. Первый же `tofu apply` упадёт на подключении к демону.

Оба предусловия снимаются в одном месте не случайно: сервер сейчас достижим только по паролю, а пароль лежит в секретах GitHub, то есть добраться до машины может лишь прогон workflow. Ни один человек в команде не может зайти на сервер руками — значения секретов GitHub обратно не отдаёт.

## What Changes

- Инженер генерирует у себя ключевую пару CI и кладёт приватный ключ секретом репозитория `VPS_DMC268_KEY_T1` (org-секрет завести нельзя — нет прав администратора организации; права администратора репозитория есть).
- Добавляется одноразовый workflow, который **за одну SSH-сессию по паролю**: определяет доступные права, ставит Docker Engine, добавляет `VPS_DMC268_U` в группу `docker` и дописывает публичный ключ в `authorized_keys`.
- Публичный ключ передаётся входом workflow — он не секрет. Приватный не покидает машину инженера и хранилище секретов.
- Все шаги идемпотентны: повторный прогон не ломает уже настроенный сервер и не дублирует строку в `authorized_keys`.
- Приёмка — повторный прогон `vps-access-probe`: он должен показать «Docker: ок» и пройти вход уже по ключу.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

Изменение помечено `skip_specs: true`, как и `vps-access-probe`. Это разовая подготовка хоста: наблюдаемое поведение сервиса не меняется, требования к деплою появятся в том изменении, которое деплой и опишет.

## Impact

- Новый временный файл в `.github/workflows/` и скрипт в `.github/scripts/`.
- Новый секрет `VPS_DMC268_KEY_T1` в обоих репозиториях — фронту он понадобится для своего CD, сервер общий.
- Состояние сервера меняется необратимо: ставится пакет и доверяется ключ. Откат — удалить строку из `authorized_keys` и снести пакет, для чего снова нужен доступ по паролю.
- Разблокирует: переход `infra/` на удалённый `docker_host`, а значит и весь CD в [#22](https://github.com/larchanka-training/dmc-268-api-t1/issues/22).
- Закрывает вопрос, оставшийся открытым в #22: чем деплой аутентифицируется на сервере.

## ADDED Requirements

### Requirement: Ответ модели не закрывает тред

Система SHALL принимать поле `threadFollowUps` ответа модели по схеме ответа и SHALL NOT публиковать по нему ответы в треды и закрывать треды. Тред бота SHALL считаться закрытым только по закрытию на хостинге — вебхуком `pull_request_review_thread` или сверкой перед публикацией. Модель читает дифф, описание PR и сообщения коммитов, которые пишет автор PR, поэтому её суждение о треде SHALL NOT снимать блокировку мерджа.

#### Scenario: Инъекция просит снять critical-тред как superseded

- **WHEN** на открытом треде `critical` прошлого прогона дифф повторного прогона содержит инструкцию вернуть follow-up для этого места, строку якоря дифф не меняет, а модель возвращает `threadFollowUps` для треда со статусом `superseded` и `resolveThread: true`
- **THEN** ответ в тред не публикуется, тред не закрывается, прогон завершается `completed`, check run — `failure`

#### Scenario: Инъекция в коммите, который меняет строку якоря

- **WHEN** коммит повторного прогона меняет строку якоря открытого треда `critical` и несёт инструкцию, а модель возвращает для треда `fixed` с `resolveThread: true`
- **THEN** ответ в тред не публикуется, тред не закрывается, check run — `failure`

#### Scenario: Модель считает исправленным то, что нашла снова

- **WHEN** повторный прогон находит ту же критичную проблему на открытом треде, а `threadFollowUps` по этому треду — `fixed` с `resolveThread: true`
- **THEN** находка покрыта тредом, ответ в тред не публикуется, тред не закрывается, check run — `failure`

### Requirement: Ревью не публикуется дважды

Тело ревью SHALL нести скрытый маркер прогона `<!-- dmc-268-review-run:<id прогона> -->`. Если ответа на создание ревью нет (обрыв, таймаут, 5xx, отказ лимита), система SHALL после паузы искать ревью с маркером среди ревью бота своего GitHub App и SHALL повторять создание, только если его нет; попытки кончились — сбой. Ревью человека или другого бота с маркером SHALL NOT считаться своим.

#### Scenario: Ревью создано, а ответ — 502

- **WHEN** GitHub записал ревью, а на `POST …/reviews` ответил 502
- **THEN** после паузы ревью найдено по маркеру, второй `POST` не отправляется, его сводка и inline записаны в `published_comments`, прогон завершается `completed` с check run

#### Scenario: Маркер в чужом ревью

- **WHEN** на каждый `POST …/reviews` приходит 502, ревью не создаётся, а в PR есть ревью человека и другого бота с маркером этого прогона
- **THEN** чужое ревью своим не считается, `POST` отправлен столько раз, сколько попыток у адаптера, прогон завершается `failed`

#### Scenario: Отказ лимита на создании ревью

- **WHEN** на первый `POST …/reviews` GitHub ответил 429 с `Retry-After: 7`, не создав ревью
- **THEN** после паузы 7 секунд ревью с маркером не найдено, второй `POST` создаёт его, в PR одно ревью, прогон завершается `completed` с check run

## MODIFIED Requirements

### Requirement: Merge gate по критичным открытым тредам

До публикации находок система SHALL сверить треды бота с GitHub одним запросом с пагинацией на прогон и SHALL выставить check run `dmc-268-ai-review` на `head_sha` с `conclusion=failure`, если остаётся незакрытый тред с замечанием `critical`. Сверка и check run — best-effort: сбой хостинга SHALL записываться в лог и SHALL NOT переводить прогон в `failed`. Check run SHALL выставляться по базе после публикации ревью; при сбое сверки находки SHALL публиковаться без сверки с тредами.

#### Scenario: Ручное закрытие треда снимает блокировку

- **WHEN** тред с critical был закрыт на GitHub вручную до merge gate
- **THEN** `thread_resolved` обновляется при сверке и check run получает `success`

#### Scenario: GraphQL недоступен после публикации

- **WHEN** ревью с замечанием `critical` опубликовано, а на следующем прогоне GraphQL GitHub на сверке тредов отвечает 502 и после повторов адаптера
- **THEN** прогон завершается `completed`, находка опубликована, check run выставлен с `failure` по треду из базы, и сообщение не уходит в DLQ

#### Scenario: Check run не выставился

- **WHEN** ревью опубликовано, а создание check run завершилось сбоем хостинга
- **THEN** прогон завершается `completed`, в лог пишется warning с id прогона, второго ревью нет

## REMOVED Requirements

### Requirement: Диалог в тредах на повторном прогоне

**Reason**: Ответ модели в тред и закрытие треда по нему обходили merge gate инъекцией из диффа (#73), а законного follow-up нет: открытые треды модели не передаются.

**Migration**: Тред закрывает человек на GitHub; поведение — «Ответ модели не закрывает тред».

### Requirement: Одна проблема — один комментарий

**Reason**: Требование ограничивало ответы модели в треды и закрытие покрывающего треда; без ответов и закрытий ботом ограничивать нечего.

**Migration**: Сценарий «Модель считает исправленным то, что нашла снова» перенесён в «Ответ модели не закрывает тред»; публикация находки, ставшей серьёзнее открытого треда, описана в «Повторный прогон не дублирует открытый тред».

### Requirement: Ревью и ответ в тред не публикуются дважды

**Reason**: Бот больше не отвечает в треды, и сценарий о повторе ответа на 502 описывать нечего; блок MODIFIED не может убрать сценарий.

**Migration**: Защита от второго ревью без изменений перенесена в «Ревью не публикуется дважды».

## Why

Модель видит каждое изменение только с тремя строками контекста, которые отдаёт GitHub. Этого
мало, чтобы судить о логике внутри функции: не видно начала цикла, обработки ошибок, соседних
веток. `docs/SYSTEM_DESIGN.md` §5 описывает уровни `surrounding` (±30 строк вокруг изменения) и
`whole_file` (небольшой файл целиком), но они помечены «запланировано» (задача #277). Текст
изменённого файла на `head_sha` сборка уже скачивает, правда только для языков с AST.

## What Changes

- Текст файла на `head_sha` скачивается для каждого изменённого текстового файла с hunk'ами
  (не бинарного, не удалённого), а не только для языков с AST; лимиты прежние:
  `ast_max_files`, `ast_max_file_bytes`. AST строится, как раньше, только для поддержанных языков.
- Чистая доменная функция строит по hunk'ам файла и его тексту на `head_sha` расширенные виды в
  формате unified diff: до 30 строк контекста с каждой стороны hunk'а, соседние окна склеиваются,
  заголовок `@@` пересчитывается. Тот же вид с радиусом «весь файл» даёт файл целиком. Если
  строка hunk'а не совпала с текстом файла, файл не расширяется.
- Бюджет пакета заполняется в два прохода: сначала, как сейчас, все hunk'и с тремя строками
  контекста; затем на остаток - улучшения по файлам: файлы до 8 КБ целиком (AST для них не
  нужен), затем AST остальных файлов, затем окна ±30 строк для остальных. Файл улучшается,
  только если разница по стоимости целиком помещается в остаток и все его hunk'и вошли.
- Элемент `diff` пакета и рендер промпта прежние; `tiers` получает `whole_file` и `surrounding`,
  если хоть один файл получил такой вид. Сверка якорей находок - по исходным hunk'ам.
- Секреты в неизменённых строках расширенного вида заменяются меткой до отправки модели;
  строки `+`/`-` остаются как есть.
- Системный промпт ревью: одна строка о том, что дифф может нести расширенный контекст, а
  замечания ставятся к строкам `+`/`-`.

## Impact

- Код: новый модуль `app/domain/hunk_context.py` (расширенные виды hunk'ов, константы радиуса и
  порога), `app/application/context_assembly.py` (аргумент `sources`, второй проход бюджета),
  `app/application/use_cases/build_review_context.py` (довыборка текстов всех файлов, AST по
  скачанным текстам).
- Промпт: `prompts/review/system.md`, одна строка.
- Тесты: `tests/domain/test_hunk_context.py` (в том числе сверка с `git diff -U30`),
  `tests/application/test_context_assembly.py`, `tests/application/test_build_review_context.py`.
- Песочница контура (`tests/sandbox/outline`): статус `whole_file` для файла, вошедшего целиком,
  с тем, что выбрал бы AST; ожидания тестов и README.
- Документация: `docs/SYSTEM_DESIGN.md` §5.
- Без миграций, новых настроек и изменений API. Запросов к GitHub на прогон станет больше на
  число изменённых файлов без AST-языка, в пределах `ast_max_files`.

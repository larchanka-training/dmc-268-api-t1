## Context

`publish_review` публикует ревью, отвечает в треды (и закрывает их), сверяет открытые треды с GitHub через GraphQL (`sync_open_threads_from_host`) и выставляет check run merge gate по `collect_open_findings`. Любое исключение ответов в треды или сверки уходит в `run_review` и переводит прогон в `failed`, хотя ревью уже в PR.

## Goals / Non-Goals

**Goals:** сбой хостинга при ответах в треды и сверке не роняет прогон и не отменяет gate.

**Non-Goals:** сбои `set_merge_gate_check` и пересчёт gate по вебхуку закрытия треда; повторы POST, маркер прогона в теле ревью, таймауты и `Retry-After` — отдельная задача.

## Decisions

- **Ловим `VcsError`, а не `Exception`.** Адаптер GitHub переводит все сбои хостинга в наследников `VcsError` из `app.domain.vcs_errors`: обрыв сети и исчерпанные 429/5xx — `VcsUnavailableError`, отказ токена — `VcsAuthError`, прочие HTTP-ошибки, ответ GraphQL с `errors` и не-JSON — `VcsError`. Ошибка кода (`AttributeError`, `KeyError`) — не сбой хостинга, её прятать нельзя.
- **Каждый follow-up отдельно, ответ записывается до закрытия.** Сбой ответа — тред пропускается, остальные идут дальше. Ответ записывается в `published_comments` своей транзакцией сразу после `reply_to_review_comment`: если потом упадёт закрытие треда, запись об ответе останется, и следующий прогон не ответит повторно. `thread_resolved=True` — отдельной транзакцией после успешного закрытия. Ответ, который ушёл на GitHub, а в базу не записался (сбой базы между ними), по-прежнему возможен, но это уже не сбой хостинга.
- **Нет инкрементального диффа — как при превышении лимита.** `VcsError` на `fetch_diff` даёт пустой набор hunk'ов: изменение строки якоря не подтверждено, критичный тред со статусом `fixed` не закрывается, ответ публикуется. Результат кэшируется на `prev_head`, повторно дифф в том же прогоне не запрашивается.
- **Gate после сверки, по базе.** Gate считает открытые треды; выставленный до сверки, он видел бы треды, закрытые вручную, открытыми. Упала сверка — gate по базе: в худшем случае `failure` вместо `success`, следующий прогон или вебхук `pull_request_review_thread` исправит.
- **Частичная сверка безопасна.** GraphQL читается целиком до первой записи (`_load_review_threads` собирает все страницы), а каждый закрытый тред обновляется в своей транзакции; сбой VCS посередине не оставляет полузаписанных строк.

## Risks / Trade-offs

- При долгом простое GraphQL gate может показывать `failure` по треду, уже закрытому вручную → пересчёт на вебхуке закрытия треда или следующем прогоне.

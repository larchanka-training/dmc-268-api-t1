## MODIFIED Requirements

### Requirement: Диалог в тредах на повторном прогоне

На повторном прогоне для того же pull request система SHALL для каждого открытого инлайн-треда (не `thread_resolved`) принять `threadFollowUps` от LLM, опубликовать ответ через `POST /repos/{owner}/{repo}/pulls/{number}/comments/{id}/replies` и при допустимом статусе закрыть тред на хостинге. Ответ SHALL записываться в `published_comments` до закрытия треда. Сбой хостинга на одном треде SHALL NOT мешать остальным; без инкрементального диффа критичный тред не закрывается.

#### Scenario: Ответ уходит в корневой комментарий

- **WHEN** модель возвращает follow-up для ранее опубликованного инлайн-комментария
- **THEN** ответ публикуется как reply к корневому `provider_comment_id` этого треда

#### Scenario: Закрытие треда упало после ответа

- **WHEN** ответ в тред опубликован, а закрытие треда на GitHub завершилось сбоем
- **THEN** ответ записан в `published_comments`, `thread_resolved` не выставлен, прогон завершается `completed` с выставленным check run

#### Scenario: Ответ в один тред не опубликован

- **WHEN** публикация ответа в первый из двух тредов завершилась сбоем хостинга
- **THEN** ответ во второй тред публикуется, а check run выставляется

#### Scenario: Два follow-up на один тред

- **WHEN** модель вернула два follow-up на одно и то же место открытого треда
- **THEN** в тред публикуется один ответ, прогон завершается `completed`

### Requirement: Merge gate по критичным открытым тредам

Перед завершением публикации система SHALL сверить открытые треды с состоянием на GitHub и SHALL выставить check run `dmc-268-ai-review` на `head_sha` с `conclusion=failure`, если остаётся незакрытый тред с замечанием `critical`. Ответы в треды и сверка — best-effort: сбой хостинга SHALL записываться в лог и SHALL NOT переводить прогон в `failed`; check run SHALL выставляться после них, при сбое сверки — по данным в базе.

#### Scenario: Ручное закрытие треда снимает блокировку

- **WHEN** тред с critical был закрыт на GitHub вручную до merge gate
- **THEN** `thread_resolved` обновляется при сверке и check run получает `success`

#### Scenario: GraphQL недоступен после публикации

- **WHEN** ревью с замечанием `critical` опубликовано, а GraphQL GitHub на сверке тредов отвечает 502 и после повторов адаптера
- **THEN** прогон завершается `completed`, в PR одно ревью, check run выставлен один раз с `failure` по треду из базы, и сообщение не уходит в DLQ

## Why

Ревью #225 нашло в исправлении обхода merge gate сменой целевой ветки (#222) гонку и два ложных срабатывания:

- Приём выставлял `failure` на head раньше, чем коммитил отмену старого прогона. Воркер старого прогона, прочитавший статус до отмены, выставлял `success` по старому диффу уже после блокировки, и `success` оставался до конца нового ревью, а если оно падало, то навсегда. Тот же класс гонки был у пересчёта gate по закрытию треда.
- Смена ветки определялась по `base_sha`, а это вершина целевой ветки. Она двигается и без смены ветки: повтор доставки `synchronize` после мерджа чужого PR в целевую ветку ставил на head ложный `failure` «целевая ветка сменилась» и запускал лишний прогон.
- Дублем считался последний `completed`/`cancelled` прогон по вебхуку, даже если после него прогон на тот же коммит упал. После «A → B, ревью B упало, B → A» head оставался в `failure` до нового push.
- Подбор ревью упавшего прогона сопоставлял inline только по строке, листал ревью PR ради каждой «сироты» на каждом прогоне, а два прогона, подбиравшие одно ревью одновременно, роняли второй на уникальном индексе.

## What Changes

- Смена целевой ветки — только `edited`, у которого ветка в свежих метаданных отличается от записанной у PR. Иначе работает прежняя проверка дубля по head.
- Дубль — только если последний прогон на коммит не `failed` и не `cancelled`.
- При смене ветки приём сначала коммитит отмену активного прогона и новый прогон, потом выставляет `failure`, потом ставит задачу. Если GitHub отказал, ответ 502, новый прогон уходит в `failed`, у PR возвращается прежняя ветка.
- Публикация и пересчёт по треду после своего POST check run перечитывают последний прогон на head. Если он сменился или их прогон отменён, gate переписывается: блокировкой или gate завершённого нового прогона.
- Подбор ревью упавшего прогона сверяет ещё и текст комментария, смотрит только упавшие позже последнего прогона с записями, а отказ уникального индекса от параллельного подбора не роняет прогон.

## Capabilities

### Modified Capabilities

- `webhook-intake`: REMOVED «Повторная доставка отвечает существующим прогоном» (сценарии «прогон без базы» MODIFIED не удалить), ADDED взамен «Повторная доставка на проверенный коммит отвечает существующим прогоном», MODIFIED «Смена целевой ветки запускает ревью», «Смена целевой ветки блокирует merge gate до нового ревью».
- `review-pipeline`: MODIFIED «Ревью упавшего прогона не дублируется следующим», «Отменённый прогон не выставляет merge gate».

## Impact

- Код: `handle_webhook.py`, `merge_gate_publish.py` (`settle_merge_gate`), `publish_review.py`, `sync_thread_resolution.py`, `github_review.py` (сверка текста), `list_unpublished_failures` (SQL и фейк), `_RACE_CONSTRAINTS`.

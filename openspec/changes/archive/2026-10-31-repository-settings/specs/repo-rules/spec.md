## MODIFIED Requirements

### Requirement: Кэширование правил по неизменяемому ключу

Система SHALL кэшировать результат загрузки правил в `CacheStore` по ключу
«репозиторий, sha коммита» — `base_sha` у прогона, коммит ветки по умолчанию у
статуса правил в кабинете. При попадании SHALL NOT обращаться к VCS. Результаты
`loaded`, `absent` и `too_large` SHALL кэшироваться вместе со временем получения
от VCS, `empty` SHALL выводиться разбором из закэшированного файла; сбой VCS SHALL NOT
кэшироваться. Промах или сбой кэша SHALL NOT считаться ошибкой.

#### Scenario: Повторный прогон на том же коммите не ходит в VCS

- **WHEN** правила для пары «репозиторий, base_sha» уже загружены
- **THEN** следующий прогон с той же парой получает их из кэша без запроса к VCS

#### Scenario: Сбой VCS не кэшируется

- **WHEN** загрузка правил завершилась сбоем VCS
- **THEN** следующий прогон с той же парой снова запрашивает файл

#### Scenario: Файл без принятых правил из кэша

- **WHEN** для пары «репозиторий, base_sha» в кэше лежит файл, в котором ни один раздел не стал правилом
- **THEN** прогон получает статус `empty` с отклонёнными разделами без запроса к VCS

#### Scenario: Время получения переживает кэш

- **WHEN** правила загружены в момент `T`, а позже читаются из кэша по той же паре
- **THEN** у результата время получения — `T`, а не время чтения из кэша

#### Scenario: Запись прежнего формата

- **WHEN** в кэше лежит запись правил без времени получения
- **THEN** она считается промахом, файл запрашивается у VCS заново

## ADDED Requirements

### Requirement: Статус правил читается с ветки по умолчанию

Для статуса правил в кабинете система SHALL разрешать ветку по умолчанию репозитория в sha коммита у VCS и загружать `.review/rules.md` на этом sha тем же путём, что у прогона: тот же лимит размера, тот же разбор, те же статусы. Сбой разрешения ветки SHALL давать статус `unavailable`, как сбой чтения файла.

#### Scenario: Правила с ветки по умолчанию

- **WHEN** ветка по умолчанию `main` указывает на коммит `C`
- **THEN** `.review/rules.md` запрашивается на коммите `C`

#### Scenario: Ветку не удалось разрешить

- **WHEN** VCS не ответила на разрешение ветки по умолчанию или ветки нет
- **THEN** статус — `unavailable`, файл не запрашивается, исход не кэшируется

#### Scenario: Тот же ключ кэша, что у прогона

- **WHEN** в кэше правил того же процесса уже лежит запись для пары «репозиторий, `C`», а ветка `main` указывает на `C`
- **THEN** статус правил берётся из этой записи без запроса файла: ключ и формат записи те же, что у прогона на `base_sha` `C`; кэш процессный, записи воркера процессу API не видны

## Why

Сессия, у которой нет токена провайдера, сейчас наполовину действительна. `GET /auth/me`, `GET /repositories` и другие ручки на `current_session` отвечают ей `200`, а поток `GET /api/v1/events` и ручки репозиториев через `available_repositories` отвечают `401` и удаляют её (#111). Кабинет показывает пользователя вошедшим и выкидывает его на вход, как только откроется поток. Воспроизведено на стенде 23.10.2026 сессией, открытой до выкатки #111. Задача #120.

Сессии без токена бывают только такие: вход после #111 пишет сессию и токен одной транзакцией, а без ключа шифрования сессию не открывает. Токен — часть того, что значит «вошёл»: без него ни список репозиториев, ни поток, ни подключение не работают.

## What Changes

- Сессия действительна, пока её запись существует, срок не истёк **и у неё есть токен провайдера**. Сессия без токена при первом же запросе с её cookie получает `401` и удаляется — так же, как истёкшая, на любой ручке, в том числе на `/auth/me`.
- Проверяется только наличие записи токена, без расшифровки: ключ шифрования для проверки сессии не нужен, а отозванный у GitHub токен по-прежнему узнаётся при обращении к GitHub (`SessionClosed`, как сейчас).
- Сессии, открытые до #111, закрываются сами при следующем запросе — отдельная чистка не нужна.

## Capabilities

### Modified Capabilities

- `user-auth`: действительность сессии включает наличие токена провайдера.

## Impact

- Код: порт `ProviderTokenRepo.exists`, адаптер `SqlAlchemyProviderTokenRepo`, `authenticate` (`app/application/use_cases/auth.py`).
- Запрос к базе на проверку сессии: плюс `SELECT` по первичному ключу `provider_tokens`.
- Контракт API не меняется: `401 UNAUTHENTICATED` и удаление cookie — прежние.
- Тесты: хелпер `sign_in_with_session` пишет сессии токен, как настоящий вход.

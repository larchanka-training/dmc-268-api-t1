## MODIFIED Requirements

### Requirement: Смена целевой ветки блокирует merge gate до нового ревью

При смене целевой ветки приём SHALL выставить на head-коммит check run `in_progress` «Идёт ревью» после коммита отмены и нового прогона и до постановки задачи: прежний `success` описывает чужой дифф, а незавершённая проверка мердж не пускает. Сбой GitHub на блокировке SHALL давать HTTP 502 без задачи; новый прогон SHALL переводиться в `failed`, а запросу на изменение SHALL возвращаться прежняя целевая ветка.

#### Scenario: Окно между сменой ветки и новым ревью закрыто

- **WHEN** на head-коммите check run `success` по старой ветке, и приходит `edited` со сменой целевой ветки
- **THEN** до постановки нового прогона на head-коммит выставлен check run `in_progress` «Идёт ревью»; если новое ревью упадёт, его сменит `failure` «Ревью не удалось»

#### Scenario: Воркер старого прогона выставил gate после блокировки

- **WHEN** прогон на старой ветке прочитал свой статус до отмены и выставил `success` уже после блокировки приёма
- **THEN** перечитав последний прогон на head, он выставляет `in_progress` снова (требование «Отменённый прогон не выставляет merge gate», `review-pipeline`)

#### Scenario: GitHub недоступен на блокировке

- **WHEN** выставить блокирующий check run не удалось
- **THEN** ответ — HTTP 502, задача не ставится, новый прогон — `failed`, у PR прежняя ветка; повтор доставки снова блокирует head и создаёт прогон

#### Scenario: Задачу после блокировки не поставили

- **WHEN** блокировка смены ветки выставлена, а публикация задачи в брокер упала
- **THEN** прогон переходит в `failed`, и на head вместо `in_progress` выставляется `failure` «Ревью не удалось»

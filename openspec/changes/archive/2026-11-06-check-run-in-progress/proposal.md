# Proposal

## Why

Check run `dmc-268-ai-review` выставляется только `completed` в конце прогона, без ссылки на отчёт
(#295). Пока идёт ревью, на head-коммите либо пусто («Expected»), либо висит итог прежнего прогона,
а по самой плашке нельзя перейти к прогону в кабинете.

Решение о gate сейчас принимают четыре места: `settle_merge_gate`, упавший прогон, блокировка
смены целевой ветки при приёме и очистка (#356). Они расходятся: `settle_merge_gate` ставит
упавшему прогону `failure` всегда, а упавший прогон сам себе только если на head уже было ревью.
Статус «в работе», который обязательно должен смениться итогом, при таком разбросе зависал бы.

## What Changes

- Воркер, захватив прогон, выставляет на head check run `in_progress` «Идёт ревью».
- Блокировка смены целевой ветки при приёме тоже становится `in_progress` «Идёт ревью» вместо `failure`:
  для обязательной проверки это та же блокировка мерджа.
- Упавший прогон за head всегда даёт `failure` «Ревью не удалось», и первое ревью коммита тоже:
  иначе «в работе» висел бы. Сейчас без check run обязательная проверка тоже не даёт мерджа.
  Так же завершается прогон, задачу которого не удалось поставить в очередь.
- У check run прогона ссылка `details_url` на экран прогона в кабинете
  (`{PUBLIC_ORIGIN}/reviews/{id}`); у check run паузы и при пустом `PUBLIC_ORIGIN` ссылки нет.
- Решение о gate принимает одна чистая функция по прогону за head; все пути зовут один пересчёт с
  перечитыванием после POST.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `review-pipeline`: check run «в работе» с захвата прогона, ссылка на прогон, упавший прогон
  всегда блокирует gate.
- `webhook-intake`: блокировка смены целевой ветки ставит `in_progress` вместо `failure`.

## Impact

- `app/domain` (новая функция решения), `app/application/merge_gate_publish.py`,
  `review_pipeline.py`, `stale_sweep.py`, `use_cases/start_review_run.py`, порт `MergeGateCheck`,
  адаптер GitHub check run, сборка контейнера (`PUBLIC_ORIGIN` в адаптер) и их тесты.
- Пользователь видит: жёлтую плашку во время ревью вместо пустой или прежнего итога, красную
  «Ревью не удалось» после сбоя первого ревью вместо «Expected», ссылку на прогон.
- Строится поверх #356 (очистка ставит gate) и #360 (признак «ревью записано»), реализация
  после их мерджа.
- Закрывает #295.

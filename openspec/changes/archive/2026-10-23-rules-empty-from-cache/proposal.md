# Proposal

## Why

Ревью PR #74: требование кэширования перечисляет кэшируемые исходы `loaded`, `absent`, `too_large` и молчит про `empty`. По спеке можно решить, что файл без принятых правил не кэшируется и каждый прогон ходит в VCS. В коде `empty` выводится разбором из закэшированного файла (design D1 change `add-rules-e2e-benchmark-and-load`), в кэш статус `empty` не пишется.

## What Changes

- Требование кэширования говорит, что `empty` выводится из закэшированного файла; сценарий «Файл без принятых правил из кэша».
- Код не меняется: поведение уже такое и закреплено тестом `test_empty_file_is_cached_as_loaded_text`.

## Capabilities

### Modified Capabilities

- `repo-rules`: «Кэширование правил по неизменяемому ключу».

## Impact

Только спека.

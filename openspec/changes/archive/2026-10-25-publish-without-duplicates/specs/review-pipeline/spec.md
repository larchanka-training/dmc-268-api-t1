## ADDED Requirements

### Requirement: Ревью и ответ в тред не публикуются дважды

Тело ревью SHALL нести скрытый маркер прогона `<!-- dmc-268-review-run:<id прогона> -->`. Если ответа на создание ревью нет (обрыв, таймаут, 5xx, отказ лимита), система SHALL после паузы искать ревью с маркером среди ревью бота своего GitHub App и SHALL повторять создание, только если его нет; попытки кончились — сбой. Ревью человека или другого бота с маркером SHALL NOT считаться своим. Ответ в тред SHALL NOT повторяться.

#### Scenario: Ревью создано, а ответ — 502

- **WHEN** GitHub записал ревью, а на `POST …/reviews` ответил 502
- **THEN** после паузы ревью найдено по маркеру, второй `POST` не отправляется, его сводка и inline записаны в `published_comments`, прогон завершается `completed` с check run

#### Scenario: Маркер в чужом ревью

- **WHEN** на каждый `POST …/reviews` приходит 502, ревью не создаётся, а в PR есть ревью человека и другого бота с маркером этого прогона
- **THEN** чужое ревью своим не считается, `POST` отправлен столько раз, сколько попыток у адаптера, прогон завершается `failed`

#### Scenario: Отказ лимита на создании ревью

- **WHEN** на первый `POST …/reviews` GitHub ответил 429 с `Retry-After: 7`, не создав ревью
- **THEN** после паузы 7 секунд ревью с маркером не найдено, второй `POST` создаёт его, в PR одно ревью, прогон завершается `completed` с check run

#### Scenario: Ответ в тред упал с 502

- **WHEN** на ответ в тред GitHub ответил 502
- **THEN** ответ не повторяется, в лог пишется warning, остальные треды и check run обрабатываются

### Requirement: Повтор запроса к GitHub по его лимитам

Запрос к GitHub SHALL повторяться на 5xx с растущей паузой, а на отказ лимита (429, 403 лимита, ошибка `RATE_LIMITED` GraphQL при HTTP 200) — после паузы по `retry-after`, иначе до `x-ratelimit-reset` при `x-ratelimit-remaining: 0`, иначе через минуту и вдвое дольше на каждый следующий отказ. Пауза сверх бюджета ожидания SHALL завершать запрос сбоем без ожидания. Бюджет на запрос — 60 с в воркере и 0 в API; таймаут HTTP-клиента — 30 с в воркере и 5 с в API.

#### Scenario: 429 с Retry-After

- **WHEN** GitHub ответил 429 с `Retry-After: 7`
- **THEN** запрос повторяется через 7 секунд

#### Scenario: Лимит GraphQL при HTTP 200

- **WHEN** GraphQL ответил 200 с ошибкой типа `RATE_LIMITED`
- **THEN** запрос повторяется после паузы лимита

#### Scenario: Сброс лимита дальше бюджета

- **WHEN** `x-ratelimit-reset` наступит позже, чем позволяет бюджет ожидания
- **THEN** запрос завершается сбоем сразу, без паузы

#### Scenario: 403 без признаков лимита

- **WHEN** GitHub ответил 403 без `retry-after`, без `x-ratelimit-remaining: 0` и без «rate limit» в сообщении
- **THEN** запрос не повторяется

### Requirement: Потерянный id inline не снимает блокировку

Если ревью прогона опубликовано, а id inline-комментария находки не получен, прогон SHALL завершаться `completed` со сводкой в `published_comments`, а merge gate — на публикации и при пересчёте по вебхуку закрытия треда для прогона на текущем `head_sha` — SHALL считать такую находку открытой.

#### Scenario: Список комментариев ревью не получен

- **WHEN** ревью с находкой `critical` опубликовано, а `GET …/reviews/{id}/comments` отвечает 502 и после повторов
- **THEN** сводка записана, прогон `completed`, check run выставлен с `failure`

#### Scenario: Закрытие другого треда

- **WHEN** у прогона на `head_sha` находка `critical` без id inline, а вебхук закрытия треда пересчитывает gate
- **THEN** check run остаётся `failure`

## MODIFIED Requirements

### Requirement: Merge gate по критичным открытым тредам

До публикации находок система SHALL сверить треды бота с GitHub одним запросом с пагинацией на прогон и SHALL выставить check run `dmc-268-ai-review` на `head_sha` с `conclusion=failure`, если остаётся незакрытый тред с замечанием `critical`. Сверка, ответы в треды и check run — best-effort: сбой хостинга SHALL записываться в лог и SHALL NOT переводить прогон в `failed`. Check run SHALL выставляться по базе после ответов в треды; при сбое сверки находки SHALL публиковаться без сверки с тредами.

#### Scenario: Ручное закрытие треда снимает блокировку

- **WHEN** тред с critical был закрыт на GitHub вручную до merge gate
- **THEN** `thread_resolved` обновляется при сверке и check run получает `success`

#### Scenario: GraphQL недоступен после публикации

- **WHEN** ревью с замечанием `critical` опубликовано, а на следующем прогоне GraphQL GitHub на сверке тредов отвечает 502 и после повторов адаптера
- **THEN** прогон завершается `completed`, находка опубликована, check run выставлен с `failure` по треду из базы, и сообщение не уходит в DLQ

#### Scenario: Check run не выставился

- **WHEN** ревью опубликовано, а создание check run завершилось сбоем хостинга
- **THEN** прогон завершается `completed`, в лог пишется warning с id прогона, второго ревью нет

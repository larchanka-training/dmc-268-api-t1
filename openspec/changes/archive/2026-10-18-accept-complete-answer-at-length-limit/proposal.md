# Proposal: ответ по схеме принимается и на пределе длины

## Why

Живой прогон `LLM live` после `llm-gateway-review-fixes` упал: EUrouter вернул `finish_reason: length` у ответа верификатора, который проходит схему.
Модель с ответом по JSON-схеме дописывает после закрытого объекта пробелы до предела длины, и признак обрезки ставится у полного ответа.
Оборванный JSON не бывает валидным, поэтому признак провайдера должен решать только судьбу ответа, который схему не прошёл.

## What Changes

- Ответ сначала проверяется по схеме; прошедший принимается при любом признаке провайдера.
- Ответ, не прошедший схему и оборванный по пределу длины, по-прежнему завершает вызов сбоем «ответ обрезан пределом длины» без повтора.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `llm-gateway`: требование «Обрезанный ответ не повторяется» касается только ответа, не прошедшего схему.

- Код: `app/infrastructure/llm/structured.py`.

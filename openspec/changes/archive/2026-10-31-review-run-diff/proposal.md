## Why

Экран прогона в кабинете должен показывать полный дифф запроса на изменение (решение 2 из
dmc-268-ui-t1#37, вариант B; задача #87, родитель dmc-268-ui-t1#40). Ручка
`GET /api/v1/reviews/{review_run_id}/diff` уже описана в контракте (`ReviewDiffResponse`, #83),
но отвечает `501`, и кабинет показывает замечания списком без кода вокруг.

## What Changes

- `GET /api/v1/reviews/{review_run_id}/diff` вместо `501` отдаёт дифф пары коммитов
  `base_sha...head_sha` прогона у GitHub: файлы со статусом (`added`/`modified`/`deleted`/`renamed`),
  прежним путём у переименования, признаком бинарного файла, языком по расширению, счётчиками
  добавленных и удалённых строк и ханками по строкам. Форма ответа `200` не меняется.
- Все изменённые файлы попадают в ответ, включая те, что ревью отфильтровало (lock-файлы,
  vendored, сгенерированные); бинарный файл — без ханков.
- Новые коды ошибок в каталоге HTTP-слоя:
  - `409 DIFF_UNAVAILABLE` — у прогона нет `base_sha` (прогоны до появления колонки);
  - `410 COMMIT_NOT_FOUND` — GitHub не знает коммит прогона (force-push убрал `head_sha`);
  - `422 DIFF_TOO_LARGE` — дифф больше лимита ручки.
  Приложение больше не установлено на репозиторий — существующий
  `404 REPOSITORY_NOT_IN_INSTALLATION`; прочий сбой GitHub — `502 SCM_UNAVAILABLE`.
- Дифф по паре коммитов не меняется и кэшируется в памяти процесса API: отдельное хранилище
  с общим лимитом в байтах и лимитом на запись, чтобы диффы не вытесняли кэш видимости и не
  выедали память контейнера (512 МБ).
- Номер установки GitHub App для репозитория API получает у GitHub
  (`GET /repos/{owner}/{repo}/installation` с JWT приложения) и кэширует коротко; в базе он
  по-прежнему не хранится.
- Чтения кабинета ходят к GitHub со своим тайм-аутом, длиннее 5 с вебхука.
- Описание ручки в схеме — реальное поведение вместо «Не реализовано»; экспорт
  `docs/openapi/openapi.json` обновляется.

## Impact

- Код: `app/domain` (представление диффа, признак добавленного файла у `ParsedFile`, доменное
  «не найдено» VCS), `app/application` (use case диффа прогона, метод порта
  `InstallationCatalog`), `app/infrastructure` (адаптер и кэш каталога установок, байтовый
  лимит `InMemoryCacheStore`, второй VCS-шлюз и кэш диффов в контейнере), `app/api`
  (зависимости, ручка, коды ошибок), `app/config.py` (новые настройки).
- Контракт API: новые коды `DIFF_UNAVAILABLE`, `COMMIT_NOT_FOUND`, `DIFF_TOO_LARGE` в
  `AnyProblem`; у ручки диффа нет `501`. Кабинету — обработка новых кодов (dmc-268-ui-t1#107).
- Без миграций и без изменений инфраструктуры стенда; GitHub App — те же разрешения
  (Contents: read и Pull requests: read уже нужны воркеру).
- Документация: `docs/BACKEND_ARCHITECTURE.md`, `docs/SYSTEM_DESIGN.md` §4.3 и тайм-ауты GitHub.

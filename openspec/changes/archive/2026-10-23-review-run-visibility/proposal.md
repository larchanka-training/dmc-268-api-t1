## Why

Список прогонов `GET /reviews` и поток `GET /events` отдают только прогоны репозиториев, к которым у пользователя есть доступ на GitHub (решение А в dmc-268-ui-t1#43). А `GET /reviews/{review_run_id}`, `/steps` и заглушка `/diff` проверяли только сессию: любой вошедший пользователь, зная id прогона, читал прогон чужого репозитория — заголовок PR, находки с кодом и текстом замечаний, шаги. Задача #127.

## What Changes

- `GET /reviews/{review_run_id}`, `/steps` и `/diff` отдают прогон, только если его репозиторий виден пользователю по тому же правилу, что список и поток. Невидимый прогон — `404 REVIEW_NOT_FOUND`, тот же ответ, что у несуществующего: ответ не подтверждает, что id есть.
- Прогон репозитория не с GitHub не виден никому: кабинет видит репозитории только через GitHub.
- GitHub спрашиваем при любом id, до чтения прогона: сбой GitHub — `502 SCM_UNAVAILABLE`, токен отозван — `401` и закрытая сессия, как у списка, — одинаково для существующего и несуществующего id. Иначе `502`, `401` или время ответа выдавали бы, что прогон есть.
- Заглушка `/diff` проверяет видимость прогона до ответа `501`.

## Capabilities

### Modified Capabilities

- `review-rest-api`: ручки одного прогона проверяют его видимость; заглушка диффа — тоже, до `501`.

## Impact

- Код: зависимость `visible_run` в `app/api/reviews.py` — общая для трёх ручек.
- Контракт: у трёх ручек в ответах `502 ScmUnavailableProblem`, в описаниях — 404 для невидимого прогона. Схемы ответов не меняются.
- Нагрузка: запрос прогона, шагов или диффа — тот же обход установок пользователя у GitHub, что у списка; кэш — #126.

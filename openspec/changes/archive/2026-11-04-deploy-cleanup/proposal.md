## Why

Аудит 2026-11-04 (#340): в деплое и CI остались шаги и копии, которые заменил более поздний штатный механизм или которые были нужны один раз.

- Шаг «Доставки вебхука и сбои воркера с прошлого выката» (`diagnostics.sh`) считал `grep` по `docker logs`. Шаг появился до стека наблюдаемости; теперь ошибки API и воркера показывают панели «Доля ошибок 5xx» и «Прогоны по статусам» дашборда «Обзор dmc-268» и алерты `Api5xxSpike`, `ReviewRunsFailing`, доставки вебхука по кодам — запрос к метрике `http_server_request_duration_seconds_count` по `http_route` (в `docs/GITHUB_APP.md`), а со стороны GitHub — история доставок App и переотправка #149.
- `docker rm -f dmc268-migrate` в `migrate.sh` и три блока `removed` в `infra/app.tf` нужны были один раз, на первом деплое после #159 и #203. В плане последнего деплоя операций `forget` нет, контейнера `dmc268-migrate` на стенде нет.
- Шаг «Убедиться, что образ забирается обратно» после push повторял то, что делают следующий шаг trivy по тому же `image@digest` и `docker pull` при деплое.
- Python смены пароля роли мониторинга был скопирован heredoc'ом в `migrate.sh` и в `docker-compose.yml`.
- Около десятка комментариев ссылались на `infra/main.tf`, которого нет с change `infra-files`.
- `DATABASE_URL` в env job'а `test` CI остался от PR #2: тесты читают `TEST_DATABASE_URL`.
- Панель «Свободное место на дисках» дашборда отбирала файловые системы своим селектором, а алерты — записью `dmc268:filesystem_avail:ratio`; списки исключений разошлись (`nsfs` против `ramfs`, системных точек и readonly).
- Шаг «Проверить, что API жив (через туннель)» (`check-api.sh`) проверял `/health` через SSH-туннель после `apply`. Готовность процесса уже ждёт сам `apply` (`wait = true`, тот же `/health` из healthcheck контейнера), API по сети стенда постоянно пробует blackbox-services, публичный вход — blackbox-public, на обе пробы есть алерты, а публикацию порта только на петле сверяет `tests/test_infra_isolation.py`. Туннель на 8000 был нужен только этой проверке. Один отказ теперь ловит не деплой, а алерт: если uvicorn в контейнере слушает `127.0.0.1` вместо `0.0.0.0`, healthcheck изнутри контейнера зелёный, а через пару минут срабатывает `ServiceProbeFailed` пробы blackbox-services.

## What Changes

- Удалены `diagnostics.sh`, его шаг и строка в отчёте; `docs/GITHUB_APP.md` даёт запрос для Grafana Explore.
- Удалены одноразовая уборка в `migrate.sh`, блоки `removed` в `app.tf` и их абзацы в `infra/README.md`.
- Удалён шаг проверки образа после push.
- Шаг пароля роли мониторинга — один файл `alembic/monitor_password.py`, его вызывают `migrate.sh` и сервис `migrate` в compose.
- Ссылки на `infra/main.tf` заменены на настоящие файлы; `DATABASE_URL` убран из CI.
- Панель диска отбирает файловые системы той же записью, что и алерты: `node_filesystem_avail_bytes and on(device, mountpoint) dmc268:filesystem_avail:ratio`.
- Удалены `check-api.sh`, его шаг и строка в отчёте. Порт API на петле остаётся для отладки.

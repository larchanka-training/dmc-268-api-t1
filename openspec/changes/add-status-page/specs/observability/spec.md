## MODIFIED Requirements

### Requirement: Телеметрия не источник данных продукта

Телеметрия SHALL служить только эксплуатации — команде. Данные, которые видит пользователь, — длительность, токены и модель прогона, шаги прогона, — SHALL браться из базы, и ни один ответ API SHALL NOT строиться из спанов. Модули роутов API SHALL NOT обращаться к OpenTelemetry; trace id в заголовке и теле ошибки — идентификатор для разбора, а не данные. Единственное исключение — публичный статус сервиса `GET /api/v1/status` (спека `service-status`): он SHALL строиться из сработавших алертов Prometheus через порт слоя приложения и SHALL отдавать только статусы компонентов.

#### Scenario: Шаги прогона в кабинете

- **WHEN** кабинет запрашивает `GET /api/v1/reviews/{review_run_id}/steps`
- **THEN** шаги приходят из таблицы `review_run_steps`, независимо от того, включена ли трассировка и сохранились ли спаны

#### Scenario: Роуты не читают телеметрию

- **WHEN** проверяются импорты модулей HTTP-слоя
- **THEN** OpenTelemetry и модуль телеметрии импортируют только фабрика приложения и middleware trace id

#### Scenario: Статус сервиса из алертов

- **WHEN** гость запрашивает `GET /api/v1/status`
- **THEN** статусы компонентов выведены из сработавших алертов Prometheus, а в ответе нет ни имён алертов, ни меток, ни значений метрик

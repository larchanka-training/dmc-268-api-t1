## Context

`deploy.yml` (job деплоя, env шага OpenTofu) ставит `TF_VAR_public_origin: https://${{ vars.VPS_DMC268_IP_T1 }}`. Та же переменная IP — адрес SSH (`host:`/`HOST:`). Вход на стенде — nginx фронта с `ngx_http_acme_module`, сертификат в томе `dmc268-ui-acme` (репозиторий интерфейса). Вебхук — `POST /api/v1/webhooks/{provider}` (`app/api/webhooks.py`), для GitHub — `/api/v1/webhooks/github`.

## Decisions

- **D1. Отдельная переменная `PUBLIC_ORIGIN`, а не замена `VPS_DMC268_IP_T1`.** IP нужен для SSH, и смешивать адрес сервера с адресом сервиса — то, из-за чего origin пришлось бы собирать строкой. Пустая `PUBLIC_ORIGIN` роняет шаг проверки конфигурации до изменений на сервере — тем же механизмом, что для остальных обязательных переменных.
- **D2. Порядок выкатки.** (1) DNS A-запись на `62.169.24.237`, проверка `dig`; (2) фронт с доменом на staging Let's Encrypt (`acme_directory`): лимит — 5 одинаковых сертификатов в неделю; (3) бэкенд с `PUBLIC_ORIGIN`; (4) фронт на боевой Let's Encrypt; (5) админ App меняет callback и webhook URL. Том `dmc268-ui-acme` не трогаем. Окно `403` между (2) и (3) — минуты, изменяющих запросов на стенде в это время мало.
- **D3. Фронт и бэкенд — разные PR в своих репозиториях**, связанные ui#41 и этим change; описание PR ссылается на парный.

## Risks / Trade-offs

- [Домен не выбран] → change ждёт; текущий shortlived-сертификат продлевается сам, стенд работает по IP.
- [DuckDNS недоступен или потерян аккаунт] → свой домен убирает зависимость. Решение — за командой.
- [Старые ссылки по IP] → nginx фронта может отвечать `301` с IP на домен; это решается в ui#41.

## Open Questions

- Какой домен: свой или поддомен DuckDNS? Блокирует реализацию, но не меняет задачи — меняется только значение `PUBLIC_ORIGIN`.

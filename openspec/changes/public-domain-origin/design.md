## Context

`deploy.yml` (job деплоя, env шага OpenTofu) ставит `TF_VAR_public_origin: https://${{ vars.VPS_DMC268_IP_T1 }}`. Та же переменная IP — адрес SSH (`host:`/`HOST:`). Вход на стенде — nginx фронта с `ngx_http_acme_module`, сертификат в томе `dmc268-ui-acme` (репозиторий интерфейса). Вебхук — `POST /api/v1/webhooks/{provider}` (`app/api/webhooks.py`), для GitHub — `/api/v1/webhooks/github`.

## Decisions

- **D1. Отдельная переменная `PUBLIC_ORIGIN`, а не замена `VPS_DMC268_IP_T1`; без неё — адрес по IP.** IP нужен для SSH, и смешивать адрес сервера с адресом сервиса — то, из-за чего origin пришлось бы собирать строкой. Пока `PUBLIC_ORIGIN` не задана, `deploy.yml` подставляет `https://` + `VPS_DMC268_IP_T1` (`vars.PUBLIC_ORIGIN || format('https://{0}', vars.VPS_DMC268_IP_T1)`) — так же, как фронт: PR можно мёржить до выбора домена, стенд продолжает работать по IP, а не падает на деплое. Отдельного шага проверки конфигурации в деплое нет, проверки две: формат — `validation` переменной `public_origin` в `infra/variables.tf` (`https://<хост>` строчными, домен или IPv4, без порта, слеша и точки на конце, пути — значение ровно `https://` + `PUBLIC_HOST` фронта), падает на `plan` до изменений на сервере; адрес без хоста (не заданы обе переменные — выражение даёт `https://`; без `deploy.yml` — пустая строка) — защита в начале `.github/scripts/deploy/infra.sh`, до `plan` и `apply`. Переменная пустую строку пропускает: локальный apply живёт без адреса.
- **D2. Порядок выкатки.** (1) DNS A-запись на `62.169.24.237`, проверка `dig`; (2) админ App **добавляет** callback `https://<домен>/api/v1/auth/github/callback` вторым (App принимает до 10), callback по IP оставляет: с (4) API строит `redirect_uri` от `PUBLIC_ORIGIN` (`app/infrastructure/container.py`), и без зарегистрированного callback домена войти не сможет никто; (3) фронт с доменом на staging Let's Encrypt (`acme_directory`): лимит — 5 одинаковых сертификатов в неделю; (4) бэкенд с `PUBLIC_ORIGIN` и сразу после деплоя обязательная проба `curl -si -X POST "$PUBLIC_ORIGIN/api/v1/auth/logout" -H "Origin: $PUBLIC_ORIGIN"` → `204` (пока staging — с `-k`): `403 ORIGIN_FORBIDDEN` значит, что `PUBLIC_ORIGIN` не совпал с `PUBLIC_HOST` фронта, а деплой при этом зелёный; (5) фронт на боевой Let's Encrypt; (6) сразу за (5) админ App меняет только Webhook URL и Setup URL (`/api/v1/auth/github/setup`, «Redirect on update» включён), затем в Recent Deliveries переотправляет (Redeliver) упавшие доставки — GitHub хранит их около 3 дней. Callback по IP удаляется, когда домен устоялся. Том `dmc268-ui-acme` не трогаем. Окно `403` между (3) и (4) — минуты, изменяющих запросов на стенде в это время мало. **Окно вебхуков:** у nginx фронта на 443 один `server`, поэтому с (3) `https://<IP>` отдаёт сертификат домена; GitHub проверяет TLS, и доставки на старый Webhook URL падают с (3) до (6) — PR в это время без ревью. Раньше (5) Webhook URL не переключить (staging-сертификату GitHub не доверяет), поэтому (5) и (6) — подряд, а пропущенное возвращает Redeliver. Cookie сессии host-only (без `Domain`): после переезда, как и после отката, все входят заново. С (3) до (5) горит критический `PublicEndpointDown` (blackbox `https_public` по `public_origin` проверяет цепочку, staging-сертификату не доверяет): перед (3) — тишина в Alertmanager (`amtool silence add alertname=PublicEndpointDown --duration=2h` в `dmc268-alertmanager`), после (5) — снять; затянулась выкатка — продлить (`amtool silence update` или новый `silence add`). Откат — в обратном порядке: если callback по IP уже удалён — сначала вернуть его вторым; (1) бэкенд (`gh variable delete PUBLIC_ORIGIN` и деплой); (2) фронт на IP, затем проба `Origin` по IP → `204`; (3) сразу за (2) админ App возвращает на IP только Webhook и Setup URL, callback не трогает, и делает Redeliver. Между (1) и (2) — такое же короткое окно `403`; вебхуки тоже идут с окном: пока фронт не передеплоен, `https://<IP>` отдаёт сертификат домена, после (2) домен из Webhook URL отдаёт другой сертификат — доставки падают до (3). Команды — `infra/README.md`, «Публичный адрес стенда».
- **D3. Фронт и бэкенд — разные PR в своих репозиториях**, связанные ui#41 и этим change; описание PR ссылается на парный.

## Risks / Trade-offs

- [Домен не выбран] → код смёржен, ручные задачи ждут; без `PUBLIC_ORIGIN` деплой берёт адрес по IP, текущий shortlived-сертификат продлевается сам.
- [DuckDNS недоступен или потерян аккаунт] → свой домен убирает зависимость. Решение — за командой.
- [Старые ссылки по IP] → `http://<IP>` фронт перенаправляет `301` на домен; `https://<IP>` после перехода отдаёт сертификат домена, и браузер показывает несовпадение имени. Перенаправлять `https://<IP>` фронт не стал (решение ui#41): ссылки по IP заменяются доменом.

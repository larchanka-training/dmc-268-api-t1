# demo-mode Specification

## Purpose
Демо-режим для локального запуска без GitHub App: как он включается, какие демо-данные пишет скрипт начальных данных, как демо-пользователь видит их без входа и обращений к GitHub и почему без входа доступно только чтение.

## Requirements

### Requirement: Демо-режим включается только настройкой

Сервис SHALL работать в демо-режиме только при `DEMO_MODE=true`. По умолчанию демо-режим SHALL быть выключен, и без настройки поведение ручек SHALL не меняться.

#### Scenario: Настройка не задана

- **WHEN** API запущен без `DEMO_MODE`
- **THEN** `GET /api/v1/reviews` без cookie отвечает `401 UNAUTHENTICATED`

#### Scenario: Демо-режим включён

- **WHEN** API запущен с `DEMO_MODE=true` и демо-данные записаны
- **THEN** `GET /api/v1/reviews` без cookie отвечает `200` со списком демо-прогонов

### Requirement: Демо-данные записываются идемпотентно

Скрипт начальных данных SHALL записывать демо-пользователя, демо-репозитории, их запросы на изменение и прогоны в статусах `completed`, `failed` и `analysing`, с шагами и находками. Повторный запуск SHALL NOT создавать дубликаты и SHALL NOT трогать данные, не относящиеся к демо-пользователю.

#### Scenario: Повторный запуск

- **WHEN** скрипт начальных данных запущен дважды подряд
- **THEN** число строк в таблицах после второго запуска такое же, как после первого

#### Scenario: Запуск одной командой

- **WHEN** `docker compose up` запущен с `.env` из `.env.example`
- **THEN** сервис `seed` завершается с кодом 0 после миграций, и кабинет показывает демо-прогоны

### Requirement: Демо-видимость не обращается к GitHub

Для демо-пользователя видимые репозитории SHALL определяться по базе (демо-репозитории) без вызова GitHub. Демо-репозитории SHALL NOT быть видны пользователю с действительной сессией GitHub.

#### Scenario: Без реквизитов GitHub App

- **WHEN** демо-режим включён, реквизиты GitHub App пусты и запрос пришёл без cookie
- **THEN** списки прогонов, репозиториев и аналитика отвечают `200` без исходящих запросов к GitHub

#### Scenario: Вошедший пользователь в демо-режиме

- **WHEN** демо-режим включён и запрос пришёл с действительной сессией GitHub
- **THEN** видимость репозиториев считается через GitHub, демо-прогонов в ответе нет

### Requirement: Демо-режим только для чтения

В демо-режиме изменяющий запрос (`POST`, `PUT`, `PATCH`, `DELETE`) без действительной сессии SHALL получать `401 UNAUTHENTICATED`, как вне демо-режима.

#### Scenario: Повторный прогон без входа

- **WHEN** демо-режим включён и `POST /api/v1/reviews` пришёл без cookie
- **THEN** ответ — `401 UNAUTHENTICATED`, прогон не создаётся
